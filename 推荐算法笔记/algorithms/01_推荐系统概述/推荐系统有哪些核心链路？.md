# 面试题：推荐系统有哪些核心链路？

![](images/0d56cd6846e7e66ce3893c1e358e7a6e6dfa1465cd5ea3c564daa7fd571bb679.jpg)

推荐系统的核心环节可分为以下六个主要阶段，涵盖从数据采集到最终展示的全链路流程，各环节相互协作以实现精准推荐：

# 数据收集与预处理

 通过日志系统、埋点技术收集用户行为数据（如点击、浏览、购买等）;  
 数据预处理包括清洗（去重、异常值处理）、归一化、标签化等操作，为后续建模提供高质量数据输入。

# 二、特征工程与用户画像构建

1. 特征提取：将原始数据转化为算法可理解的向量（Embedding），例如通过文本挖掘提取关键词，或利用图像识别技术生成商品视觉特征。  
2. 用户画像：基于用户行为聚类生成兴趣标签，或通过表示学习（Word2Vec、GNN）构建用户向量。  
3. 物品画像：结合多模态数据（文本、图像、视频）生成物品标签，例如使用 BERT 处理商品描述、CV 算法分析图像内容。

# 三、候选集召回

目标：从海量物品中快速筛选出潜在兴趣候选集（通常从百万级降至千级）。常用方法包括：

 Embedding 召回：通过矩阵分解（SVD、ALS）或深度学习（YouTube DNN）生成用户/物品向量，利用近似最近邻（ANN）算法检索。  
 规则召回：结合业务策略（如热门商品、新上架商品）补充多样性。   
 协同过滤：基于用户相似度（UserCF）或物品相似度（ItemCF）推荐。

# 四、排序（粗精排与重排）

 粗排：使用轻量模型初步过滤候选集，减少后续计算压力。  
 精排：采用复杂模型（如DeepFM、DIN）预测用户偏好分数，融合多维度特征（用户画像、场景上下文、实时行为）进行精准排序。

 重排：根据业务规则优化排序结果，例如去重（避免重复推荐）、多样性控制（平衡兴趣分布）、广告插入等。

![](images/5b7d887f7aab3f691e72f1cc50a69565cc7d1e21ed2609bf5c98081a4f5729ad.jpg)

# 五、结果展示与反馈

 个性化展示：根据设备类型（移动端/PC 端）调整布局，分页加载提升用户体验。  
 实时反馈机制：记录用户对推荐结果的点击、停留时长等行为，用于在线模型更新（如 Flink 实时流处理）。

# 六、评估与迭代优化

 离线评估：通过 AUC、Recall@K、NDCG 等指标衡量模型效果。  
 在线 AB 测试：对比新旧策略的 CTR、GMV 等业务指标，验证优化效果。  
 冷启动优化：利用迁移学习（如跨域推荐）或基于人口统计信息的推荐解决新用户/物品冷启动问题。

推荐系统的核心链路是 "数据 $\longrightarrow$ 特征 $\longrightarrow$ 召回 $\longrightarrow$ 排序 $\longrightarrow$ 展示 $\longrightarrow$ 反馈" 的闭环流程，各环节需结合算法与工程优化（如实时计算、多模态融合）以应对大规模数据和高并发场景。实际应用中，不同业务场景（如电商、短视频）会针对链路中的特定环节进行定制化设计。

# 七、核心数学公式推导

## 7.1 召回率公式

召回阶段衡量从全量物品中检索出相关物品的能力。设相关物品集合为 $\mathcal{R}$，召回结果集合为 $\mathcal{C}$，则：

$$\text{Recall}@K = \frac{|\mathcal{R} \cap \mathcal{C}_K|}{|\mathcal{R}|}$$

其中 $\mathcal{C}_K$ 为召回的前 $K$ 个物品。

**命中率（Hit Rate）**：

$$\text{HR}@K = \frac{1}{N} \sum_{u=1}^{N} \mathbb{1}[\text{target}_u \in \mathcal{C}_K(u)]$$

## 7.2 精确率与 NDCG

$$\text{Precision}@K = \frac{|\mathcal{R} \cap \mathcal{C}_K|}{K}$$

**NDCG（Normalized Discounted Cumulative Gain）**：

$$\text{DCG}@K = \sum_{i=1}^{K} \frac{2^{rel_i} - 1}{\log_2(i + 1)}$$

$$\text{NDCG}@K = \frac{\text{DCG}@K}{\text{IDCG}@K}$$

其中 $rel_i$ 为位置 $i$ 物品的相关性，IDCG 为理想排序下的 DCG。

## 7.3 CTR/CVR 预估公式

**点击率（CTR）预估**：精排模型预估用户 $u$ 点击物品 $i$ 的概率：

$$P(\text{click} \mid u, i) = \sigma\left(f_\theta(x_u, x_i, x_c)\right)$$

其中 $\sigma(\cdot)$ 为 sigmoid 函数，$x_u, x_i, x_c$ 分别为用户特征、物品特征和上下文特征。

**转化率（CVR）预估**：

$$P(\text{convert} \mid u, i) = \sigma\left(g_\phi(x_u, x_i, x_c)\right)$$

**CTCVR（点击且转化）**：需遵循 CTCVR 假设：

$$P(\text{click} \wedge \text{convert}) = P(\text{click}) \times P(\text{convert} \mid \text{click})$$

**ESMM 损失函数**：

$$\mathcal{L} = \sum_{(u,i) \in \mathcal{D}} \left[-y_{\text{ctr}} \log p_{\text{ctr}} - (1-y_{\text{ctr}})\log(1-p_{\text{ctr}}) - y_{\text{ctcvr}} \log(p_{\text{ctr}} \cdot p_{\text{cvr}})\right]$$

## 7.4 多目标优化公式

推荐系统通常同时优化多个目标（点击、转化、停留时长等），多目标优化的总体损失函数为：

$$\mathcal{L}_{\text{total}} = \sum_{t=1}^{T} w_t \cdot \mathcal{L}_t(\theta_t, \theta_{\text{shared}})$$

其中 $w_t$ 为第 $t$ 个目标的权重，$\theta_t$ 为任务特定参数，$\theta_{\text{shared}}$ 为共享参数。

**帕累托最优多目标优化**：

$$\min_{\theta} \left[\mathcal{L}_1(\theta), \mathcal{L}_2(\theta), \ldots, \mathcal{L}_T(\theta)\right]$$

**MGDA（Multiple Gradient Descent Algorithm）**：通过求解以下优化问题找到帕累托最优下降方向：

$$\min_{\alpha} \left\| \sum_{t=1}^{T} \alpha_t \nabla_\theta \mathcal{L}_t \right\|^2, \quad \text{s.t.} \quad \sum_{t=1}^{T} \alpha_t = 1, \; \alpha_t \geq 0$$

## 7.5 漏斗转化率公式

推荐系统漏斗各阶段的转化率：

$$\text{曝光} \xrightarrow{\text{CTR}} \text{点击} \xrightarrow{\text{CVR}} \text{转化} \xrightarrow{\text{复购率}} \text{留存}$$

整体转化率为各阶段连乘：

$$P(\text{最终转化}) = \prod_{s=1}^{S} P(\text{阶段}_s \mid \text{阶段}_{s-1})$$

**GMV 最大化**（电商场景）：

$$\text{GMV} \approx \sum_{i \in \text{曝光}} P(\text{click} \mid i) \times P(\text{convert} \mid \text{click}, i) \times \text{price}_i$$

## 7.6 A/B 测试的统计显著性

$$Z = \frac{\hat{p}_A - \hat{p}_B}{\sqrt{\hat{p}(1-\hat{p})\left(\frac{1}{n_A} + \frac{1}{n_B}\right)}}$$

其中 $\hat{p} = (n_A \hat{p}_A + n_B \hat{p}_B) / (n_A + n_B)$ 为合并比例。当 $|Z| > Z_{\alpha/2}$ 时拒绝原假设。

# 八、推荐系统架构总览

典型工业级推荐系统的整体架构如下：

```
用户请求 → API网关 → [特征服务] → [多路召回] → [粗排] → [精排] → [重排] → 展示
                ↓           ↓          ↓        ↓       ↓       ↓
            实时特征层   向量检索层  轻量模型  深度模型  策略引擎
                ↑           ↑          ↑        ↑       ↑
            特征存储     向量索引    模型服务  GPU推理   规则配置
```

数据流向：
- 离线层：日志收集 → 特征计算 → 模型训练 → 模型部署
- 近线层：实时日志流 → 增量特征更新 → 在线学习
- 在线层：请求 → 特征拉取 → 召回 → 排序 → 展示

# 八、各阶段延迟预算分解

典型推荐请求总延迟预算约 100-200ms，各环节的分配如下：

| 瘫痪 | 耗时预算 | 占比 | 关键优化手段 |
|------|---------|------|------------|
| 特征拉取 | 10-20ms | 10% | 特征预计算、本地缓存 |
| 多路召回 | 15-30ms | 15% | ANN 索引、并发召回 |
| 粗排 | 5-10ms | 5% | 轻量模型、模型蒸馏 |
| 精排 | 30-80ms | 40% | GPU 推理、模型量化 |
| 重排 | 5-15ms | 5% | 规则引擎优化 |
| 网络传输 | 10-20ms | 10% | CDN、边缘部署 |
| 业务逻辑 | 10-20ms | 10% | 并发处理 |

# 九、实时处理与批处理对比

| 维度 | 离线批处理 | 近线实时流处理 | 在线实时处理 |
|------|----------|-------------|------------|
| 数据来源 | 数据仓库（Hive） | 消息队列（Kafka） | 请求上下文 |
| 处理延迟 | 小时~天级 | 秒~分钟级 | 毫秒级 |
| 典型任务 | 模型训练、特征统计 | 实时特征更新、在线学习 | 特征拉取、模型推理 |
| 技术栈 | Spark, Hive | Flink, Storm | Redis, gRPC |
| 数据一致性 | 最终一致 | 准实时 | 强一致 |
| 成本 | 低（批量计算） | 中 | 高（低延迟要求） |

```python
import numpy as np
from collections import defaultdict
from typing import List, Dict, Tuple

class FeatureService:
    def __init__(self):
        self.user_features = {}
        self.item_features = {}

    def get_user_features(self, user_id: int) -> Dict:
        return self.user_features.get(user_id, {"age": 25, "gender": "unknown"})

    def get_item_features(self, item_ids: List[int]) -> List[Dict]:
        return [self.item_features.get(iid, {"category": "unknown"}) for iid in item_ids]

    def update_realtime(self, user_id: int, action: str, item_id: int):
        if user_id not in self.user_features:
            self.user_features[user_id] = {"click_count": 0, "recent_items": []}
        self.user_features[user_id]["click_count"] += 1
        self.user_features[user_id]["recent_items"].append(item_id)
        if len(self.user_features[user_id]["recent_items"]) > 50:
            self.user_features[user_id]["recent_items"] = \
                self.user_features[user_id]["recent_items"][-50:]

class RecallModule:
    def __init__(self, embedding_dim=64):
        self.user_emb = {}
        self.item_emb = {}
        self.embedding_dim = embedding_dim

    def add_embeddings(self, user_id, user_vec, item_id, item_vec):
        self.user_emb[user_id] = user_vec
        self.item_emb[item_id] = item_vec

    def recall(self, user_id: int, top_k: int = 500) -> List[Tuple[int, float]]:
        if user_id not in self.user_emb:
            return []
        user_vec = self.user_emb[user_id]
        scores = []
        for iid, ivec in self.item_emb.items():
            score = np.dot(user_vec, ivec) / (np.linalg.norm(user_vec) * np.linalg.norm(ivec) + 1e-8)
            scores.append((iid, score))
        scores.sort(key=lambda x: x[1], reverse=True)
        return scores[:top_k]

class RankingModule:
    def __init__(self):
        self.weights = None

    def predict(self, user_features: Dict, item_features_list: List[Dict]) -> List[float]:
        scores = []
        for item_feat in item_features_list:
            score = hash(str(user_features) + str(item_feat)) % 100 / 100.0
            scores.append(score)
        return scores

class RerankModule:
    def __init__(self, diversity_weight=0.3):
        self.diversity_weight = diversity_weight

    def rerank(self, items_with_scores: List[Tuple[int, float]],
               item_features: List[Dict]) -> List[Tuple[int, float]]:
        result = []
        used_categories = set()
        for item_id, score in items_with_scores:
            cat = item_features[items_with_scores.index((item_id, score))].get("category", "unknown")
            diversity_bonus = 0.0 if cat in used_categories else self.diversity_weight
            result.append((item_id, score + diversity_bonus))
            used_categories.add(cat)
        result.sort(key=lambda x: x[1], reverse=True)
        return result

class RecommendationPipeline:
    def __init__(self):
        self.feature_service = FeatureService()
        self.recall = RecallModule()
        self.ranking = RankingModule()
        self.rerank = RerankModule()

    def recommend(self, user_id: int, num_results: int = 10) -> List[Dict]:
        user_feat = self.feature_service.get_user_features(user_id)
        recall_results = self.recall.recall(user_id, top_k=500)
        if not recall_results:
            return []
        item_ids = [iid for iid, _ in recall_results]
        item_feats = self.feature_service.get_item_features(item_ids)
        rank_scores = self.ranking.predict(user_feat, item_feats)
        items_with_scores = list(zip(item_ids, rank_scores))
        items_with_scores.sort(key=lambda x: x[1], reverse=True)
        top_items = items_with_scores[:50]
        top_feats = self.feature_service.get_item_features([iid for iid, _ in top_items])
        reranked = self.rerank.rerank(top_items, top_feats)
        return [{"item_id": iid, "score": score} for iid, score in reranked[:num_results]]

    def record_feedback(self, user_id: int, item_id: int, action: str):
        self.feature_service.update_realtime(user_id, action, item_id)
```

# 十一、常见问题与易错点

1. **漏斗衰减率**：从召回到精排，候选集逐级缩减，需关注每一级的"命中率"，避免好的候选在早期被误删。
2. **特征一致性**：离线训练和在线推理的特征必须完全一致，否则产生训练-推理偏差（Training-Serving Skew）。
3. **实时性权衡**：实时特征更新越频繁，效果越好但系统复杂度越高，需根据业务需求平衡。
4. **冷启动路径**：新用户和新物品应有专门的召回通道，不能完全依赖个性化召回。
5. **A/B 测试的流量划分**：需确保用户维度的流量正交，避免多实验相互干扰。
