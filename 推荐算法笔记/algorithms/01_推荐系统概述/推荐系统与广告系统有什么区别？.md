# 面试题：推荐系统与广告系统有什么区别？

推荐系统和广告系统是互联网领域两大核心信息过滤技术，虽然底层技术相似，但它们在根本目标、核心逻辑和系统设计上存在显著差异。下面这个表格对它们进行了对比：

<table><tr><td>维度</td><td>推荐系统(Recommender System)</td><td>广告系统(Advertising System)</td></tr><tr><td>根本目标</td><td>提升用户体验和参与度(如停留时长、互动率)</td><td>实现平台商业收入最大化</td></tr><tr><td>核心逻辑</td><td>"人找信息"与"信息找人"相结合,优化内容与用户的匹配</td><td>纯粹的"信息找人",本质是竞价交易,平衡用户、广告主、平台三方利益</td></tr><tr><td>排序机制</td><td>综合CTR、用户兴趣、内容多样性、新颖性等多种因素</td><td>RankScore = 出价(Bid) × pCTR × pCVR</td></tr><tr><td>关键指标</td><td>点击率(CTR)、用户停留时长、转化率(CVR)等</td><td>预估CTR/CVR的准确性、千次展示收入(RPM)、广告主投资回报率(ROI)</td></tr><tr><td>系统复杂性</td><td>模型设计复杂,需考虑用户长期兴趣、探索与利用等问题</td><td>商业逻辑复杂,集成竞价、预算控制、实时计价等多个强耦合模块</td></tr></table>

# 一、核心目标与利益相关方不同

# 1. 广告系统：

直接目标是增加平台收入。通过精准匹配广告主与用户，最大化广告主的出价收益。例如，广告排序需综合预估点击率（CTR）、转化率（CVR）和广告主出价（如 eCPM=bid×CTR×CVR×1000）。

以广告收入为核心指标，兼顾 CTR、CVR、ROI 等。

# 2. 推荐系统：

直接目标是提升用户参与度 （如点击率、停留时长等），间接为平台创造长期价值。例如，电商推荐通过分析用户历史行为推荐商品，以提高用户留存和复购。

关注用户活跃度 （如点击率、停留时长）和转化率（如 GMV）。

# 二、利益相关方不同

1. 广告系统：需平衡用户、平台、广告主三方利益 。例如，广告主需要 ROI（投资回报率）保障，用户希望减少干扰，平台需权衡收入与体验。  
2. 推荐系统：仅需考虑用户与平台的双向需求，如用户兴趣匹配和平台流量分配效率。

# 三、排序机制差异

# 1. 广告系统：

a. 竞价机制：广告排序需结合用户兴趣（CTR/CVR预估）和广告主出价。例如，同一广告位可能因不同广告主的出价高低而展示不同内容。  
b. 扣费模式：采用 GSP（广义二价）或 VCG（博弈论）等竞价扣费规则。

# 2. 推荐系统：

a. 纯兴趣驱动：排序仅依赖用户兴趣模型（如深度学习），无需考虑第三方出价。  
b. 多样性约束：需平衡推荐列表的多样性和新颖性，避免重复内容。

# 四、数据与物料库限制

# 1. 广告系统：

 物料池受限：仅能召回广告主投放的素材，且需符合广告法要求（如特定商品禁止推广）。  
 定向策略：广告主可设置人群定向（如性别、地域），进一步缩小候选集。

# 2. 推荐系统：

 全量候选集：可调用平台所有商品或内容（如电商全量商品库、视频平台全量影片库）。  
 无外部限制：不受第三方定向策略约束，仅需符合平台内容规范。

# 五、技术侧重点差异

# 1. 广告系统：

 精准数值预估：需严格校准 CTR/CVR 的绝对值，确保出价计算的准确性。  
 相关模块复杂：包含预算控制（Budget Control）、流量分配（Pacing）等模块。

# 2. 推荐系统：

 长期兴趣建模：注重用户兴趣的连续性（如使用序列模型捕捉行为时序）。  
 探索与利用：需通过强化学习等策略挖掘用户潜在兴趣，避免陷入信息茧房。

# 系统架构对比

## 推荐系统典型架构

```
用户请求 → 召回层（多路召回：协同过滤/向量召回/热门召回）
         → 粗排层（轻量模型快速过滤）
         → 精排层（复杂深度模型精准排序）
         → 重排层（多样性/新鲜度/业务规则调整）
         → 最终推荐列表
```

推荐系统的核心链路是漏斗式的，从海量候选（百万级）逐步缩减到最终列表（数十个），每一层使用不同复杂度的模型。

## 广告系统典型架构

```
广告请求 → 流量分配（Budget Pacing/频次控制）
         → 召回层（定向匹配/语义召回）
         → 粗排层（eCPM 估算）
         → 精排层（CTR/CVR 精准预估）
         → 竞价排序（eCPM = bid × pCTR × pCVR × 1000）
         → 价格计算（GSP/VCG 扣费）
         → 最终广告展示
```

广告系统在推荐漏斗基础上增加了竞价排序和价格计算环节，并且需要实时管理广告主预算和投放节奏。

## 架构差异总结

| 架构维度 | 推荐系统 | 广告系统 |
|---------|---------|---------|
| 召回候选集 | 全量物品库（百万~亿级） | 广告主投放物料（万~十万级） |
| 排序依据 | 兴趣匹配分 | eCPM（bid × pCTR × pCVR） |
| 后处理 | 多样性打散、去重 | 频次控制、预算检查、竞价 |
| 实时性要求 | 秒级更新用户画像 | 毫秒级竞价响应 |
| 离线评估 | AUC/GAUC/NDCG | RPM/ROI/广告主满意度 |

## 评估指标对比

### 推荐系统核心指标

| 指标 | 公式 | 含义 |
|------|------|------|
| CTR | 点击数 / 曝光数 | 用户对推荐内容的点击意愿 |
| CVR | 转化数 / 点击数 | 用户从点击到转化的比例 |
| GMV | $\sum$(订单金额) | 商品交易总额 |
| 留存率 | 次日/7日/30日回访比例 | 用户长期粘性 |
| NDCG | $\frac{DCG}{IDCG}$ | 排序质量，考虑位置权重 |
| 多样性 | $1 - \frac{2}{n(n-1)}\sum sim(i,j)$ | 推荐列表的多样性 |
| 覆盖率 | 被推荐物品数 / 总物品数 | 物品被推荐的公平性 |

### 广告系统核心指标

| 指标 | 公式 | 含义 |
|------|------|------|
| eCPM | bid × pCTR × pCVR × 1000 | 千次展示期望收入 |
| RPM | 总收入 / 展示次数 × 1000 | 实际千次展示收入 |
| ROI | 转化价值 / 广告花费 | 广告主投资回报率 |
| CPA | 广告花费 / 转化数 | 每次转化成本 |
| CPM | 广告花费 / 展示次数 × 1000 | 千次展示成本 |
| 预算消耗率 | 实际消耗 / 计划预算 | 广告投放节奏 |

## CTR 预估校准差异

推荐系统中，CTR 预估只需要排序准确（AUC 高即可），不要求绝对值准确。广告系统中，CTR 预估的绝对值直接影响 eCPM 计算和扣费金额，因此需要严格的校准（Calibration）：

$$\text{Calibration Ratio} = \frac{\text{预估 CTR 均值}}{\text{实际 CTR 均值}}$$

理想情况下该比率接近 1.0。常用的校准方法包括 Platt Scaling 和 Isotonic Regression。

## 业务模型差异

### 推荐系统的商业逻辑

推荐系统通过提升用户体验间接创造商业价值：

```
好的推荐 → 用户满意度↑ → 停留时长↑ → DAU↑ → 广告库存↑/交易额↑ → 平台收入↑
```

推荐系统是一个"延迟回报"系统，单次推荐的好坏难以直接量化其对平台的长期价值。

### 广告系统的商业逻辑

广告系统通过精准匹配直接创造收入：

```
精准的 CTR/CVR 预估 → 高 eCPM 排序 → 广告主获客 → 广告主加预算 → 平台收入↑
```

广告系统是一个"即时回报"系统，每次广告展示都可以直接计算对应的收入。

## 代码实现：推荐 vs 广告排序

### 推荐系统排序逻辑

```python
import numpy as np


class RecommenderRanker:
    def __init__(self, n_items, diversity_weight=0.1, freshness_weight=0.05):
        self.n_items = n_items
        self.diversity_weight = diversity_weight
        self.freshness_weight = freshness_weight

    def rank(self, user_features, item_features, user_history):
        scores = np.dot(user_features, item_features.T)
        diversity_penalty = np.zeros(self.n_items)
        for i in range(self.n_items):
            sim_to_history = np.mean([
                np.dot(item_features[i], item_features[h]) 
                for h in user_history if h < self.n_items
            ]) if len(user_history) > 0 else 0
            diversity_penalty[i] = sim_to_history
        freshness_bonus = np.random.uniform(0, 1, self.n_items)
        final_scores = (
            scores 
            - self.diversity_weight * diversity_penalty 
            + self.freshness_weight * freshness_bonus
        )
        ranked_indices = np.argsort(-final_scores)
        return ranked_indices, final_scores[ranked_indices]


ranker = RecommenderRanker(n_items=100)
user_feat = np.random.randn(64)
item_feats = np.random.randn(100, 64)
history = [1, 5, 10, 23]
indices, scores = ranker.rank(user_feat, item_feats, history)
print(f"推荐排序 Top-5: {indices[:5]}, 分数: {scores[:5]}")
```

### 广告系统排序逻辑

```python
class AdRanker:
    def __init__(self, bid_scale=1000):
        self.bid_scale = bid_scale

    def predict_pctr(self, user_features, ad_features):
        logits = np.dot(user_features, ad_features.T)
        return 1.0 / (1.0 + np.exp(-logits))

    def predict_pcvr(self, user_features, ad_features):
        logits = np.dot(user_features, ad_features.T) * 0.8
        return 1.0 / (1.0 + np.exp(-logits))

    def compute_ecpm(self, bids, pctr, pcvr):
        return bids * pctr * pcvr * self.bid_scale

    def gsp_pricing(self, sorted_ecpms, sorted_pctr, sorted_pcvr):
        prices = np.zeros(len(sorted_ecpms))
        for i in range(len(sorted_ecpms) - 1):
            next_ecpm = sorted_ecpms[i + 1]
            prices[i] = next_ecpm / (sorted_pctr[i] * sorted_pcvr[i] * self.bid_scale + 1e-8)
        return prices

    def rank(self, user_features, ad_features, bids, budget_remaining):
        pctr = self.predict_pctr(user_features, ad_features)
        pcvr = self.predict_pcvr(user_features, ad_features)
        ecpm = self.compute_ecpm(bids, pctr, pcvr)
        budget_mask = budget_remaining > 0
        ecpm = ecpm * budget_mask
        sorted_indices = np.argsort(-ecpm)
        sorted_ecpms = ecpm[sorted_indices]
        sorted_pctr = pctr[sorted_indices]
        sorted_pcvr = pcvr[sorted_indices]
        sorted_bids = bids[sorted_indices]
        prices = self.gsp_pricing(sorted_ecpms, sorted_pctr, sorted_pcvr)
        return sorted_indices, sorted_ecpms, prices


ad_ranker = AdRanker()
user_feat = np.random.randn(64)
ad_feats = np.random.randn(50, 64)
bids = np.random.uniform(1, 10, 50)
budget = np.ones(50) * 100
indices, ecpms, prices = ad_ranker.rank(user_feat, ad_feats, bids, budget)
print(f"广告排序 Top-5: {indices[:5]}")
print(f"eCPM: {ecpms[:5]}")
print(f"GSP扣费: {prices[:5]}")
```

## 信息流广告：推荐与广告的融合

在实际产品中，推荐和广告经常混合展示（信息流广告）。这带来了额外的技术挑战：

1. **广告插入位置**：每隔多少条自然内容插入一条广告？需要平衡用户体验和收入
2. **广告与内容的竞争**：当广告的预估效果不如自然内容时，是否仍然展示广告？
3. **用户体验建模**：过多的广告会导致用户流失，需要建模广告密度与留存率的关系
4. **冷启动差异**：推荐系统可以用协同过滤处理新物品，广告系统的冷启动更依赖广告主提供的素材信息

## 演进趋势

| 趋势 | 推荐系统 | 广告系统 |
|------|---------|---------|
| 模型架构 | 深度学习→序列建模→生成式推荐 | 深度学习→多任务学习→自动出价 |
| 特征工程 | 手动交叉→自动交叉→端到端 | 手动交叉→自动交叉→强化学习出价 |
| 优化目标 | CTR→多目标→长期价值 | eCPM→ROI→广告主生命周期价值 |
| 技术前沿 | 生成式推荐、大模型推荐 | 自动出价、保效合约、隐私计算 |

## 常见问题

1. **Q: 推荐系统和广告系统可以共享模型吗？**
   A: 部分可以共享。底层的 embedding 层和特征处理逻辑通常可以共享，但排序层和优化目标不同。实践中常采用多任务学习框架，共享底层特征表征。

2. **Q: 为什么广告系统需要 CTR 校准而推荐系统不需要？**
   A: 因为广告排序依赖 eCPM = bid × pCTR × pCVR，pCTR 的绝对值直接影响排序和扣费。如果 pCTR 系统性偏高或偏低，会导致广告主被多收费或少展示。推荐系统只关心相对排序，AUC 高即可。

3. **Q: 推荐系统和广告系统哪个更难做？**
   A: 各有难点。推荐系统的难点在于长期兴趣建模、多样性保障和海量候选的高效召回；广告系统的难点在于多方利益博弈、实时竞价和精准的 CTR/CVR 校准。

# 小结：

 广告系统是商业化导向的流量变现工具，需在多方利益博弈中实现收益最大化；  
 推荐系统是用户体验导向的内容分发工具，侧重长期用户价值。  
 尽管两者均依赖机器学习模型，但广告系统因竞价机制和商业属性，复杂度更高。实际应用中，部分平台会将广告嵌入推荐系统（如信息流广告），形成混合模式。
