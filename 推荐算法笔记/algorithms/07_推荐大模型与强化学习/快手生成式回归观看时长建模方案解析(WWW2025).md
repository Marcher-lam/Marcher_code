以下为快手团队提出的生成式回归观看时长建模方案（Generative Regression, GR）的技术解析，论文发表于

WWW2025Generative Regression Based Watch Time Prediction for Short-Video Recommendation

# 一、技术原理

# 1. 问题背景

 长尾分布：观看时长分布跨度大（0.1s~600s），直接回归易受极端值干扰  
 序关系敏感：预估误差相同时，高估比低估对推荐质量影响更大（如预测 3.5s vs 真实 3s优于预测2.5s）  
离散化偏差：传统序数回归（Ordinal Regression, OR）依赖固定分桶（如 CREAD/TPM），导致：

 桶边界人工设定敏感（e.g., 5s/10s 分界处预测跳变）  
 桶间条件依赖未被建模（e.g., 看完 10s 必然包含看完 5s）

# 2. GR 模型原理

核心思想：将连续值预测重构为条件依赖的序列生成任务，通过动态词汇表实现无损重建。

# 数学形式化表达：

连续值分解：观看时长 y 分解为时间槽序列 $\mathbf { s } = \{ s _ { 1 } , s _ { 2 } , \ldots , s _ { k } \}$ ，满足：

$$
y = \sum_ {i = 1} ^ {k} s _ {i}, \quad s _ {i} \in \mathcal {V}
$$

，其中 为动态构建的词汇表（每个 token 表示固定时长，如 5s、10s）

词汇表构建算法（动态百分位衰减）：

创新点：通过残差迭代和百分位衰减，平衡词汇表完整性 （覆盖长尾）与平衡性 （token 频率均匀）

```txt
输入：观看时长数据集Y，初始百分位q_start，衰减率α  
while reconstruction_error > ε:  
    z = percentile(Y, q) # 计算当前分位数值  
    if z == 0: break  
    V.append(z) # 添加新 token至词汇表  
    Y = [y - z if y > z else y for y in Y] # 更新残差  
    q = max(q * α, q_end) # 衰减百分位 
```

#  标签编码与解码：

 编码原则：

 正确性： $\left| y - \sum s _ { i } \right| < \delta$ （ 为重建误差阈值）  
k =arg min |sl 最短序列： k

 单调性： $s _ { i } \geq s _ { i + 1 }$ （降序排列减少搜索空间）

 贪心编码：从最大 token 开始匹配，逐步逼近目标值

 Encoder：FFN 提取用户/视频特征 $\mathbf { h } = \mathrm { F F N } ( \mathbf { x } _ { \mathrm { u s e r } } , \mathbf { x } _ { \mathrm { i t e m } } )$

 Decoder：Transformer 自回归生成 token 序列：

$$
\mathbf {c} _ {t} = \operatorname {T r a n s f o r m e r} ([ \mathbf {s} _ {t - 1}; \mathbf {h} ], \mathbf {c} _ {t - 1})
$$

$$
P \left(s _ {t} \mid \mathbf {s} _ {<   t}\right) = \operatorname {S o f t m a x} \left(\mathbf {Wc} _ {t} + \mathbf {b}\right)
$$

# 创新点：引入课程学习与嵌入混合（CLME）

gt 动态采样率：训练初期用真实标签 作为输入，后期逐步切换为模型预测 $\hat { \bf s } _ { t - 1 }$

 嵌入混合： $\mathbf { e } _ { t } = \beta \cdot \mathbf { e } ( \mathbf { s } _ { t - 1 } ^ { \mathrm { g t } } ) + ( 1 - \beta ) \cdot \mathbf { e } ( \hat { \mathbf { s } } _ { t - 1 } )$

（ $\beta$ 随训练轮次衰减，缓解 Teacher Forcing 导致的曝光偏差）

#  损失函数：多任务联合优化 Loss

$$
\mathcal {L} = \underbrace {\sum_ {t = 1} ^ {k} \mathrm { C E} (s _ {t} , \hat {s} _ {t})} _ {\text {序 列 分 类 损 失}} + \lambda \underbrace {\mathrm {H u b e r} (y , \sum \hat {s} _ {t})} _ {\text {连 续 值 回 归 损 失}}
$$

（Huber 损失增强对异常值的鲁棒性）

# 四、代码实现：动态词汇表构建与 GR 模型

```python
import numpy as np
import torch
import torch.nn as nn
import torch.nn.functional as F
def build_dynamic_vocab(watch_times, q_start=0.95, alpha=0.95, q_end=0.1, epsilon=0.5):
    vocab = []
    residuals = np.array(watch_times, dtype=float)
    q = q_start
    while True:
        z = np.percentile(residuals, q * 100)
        if z <= epsilon:
            break
        vocab.append(round(z, 2))
        residuals = np.array([r - z if r > z else r for r in residuals])
        q = max(q * alpha, q_end)
    vocab.sort(reverse=True)
    return vocab
def greedy_encode(target, vocab, delta=1.0):
    remaining = target
    tokens = []
    for v in vocab:
        while remaining >= v - delta:
            tokens.append(v)
            remaining -= v
            if remaining <= delta:
                return tokens
    if remaining > delta and vocab:
        tokens.append(vocab[-1])
    return tokens
def greedy_decode(tokens):
    return sum(tokens)
watch_times = np.random.exponential(scale=30, size=10000)
watch_times = np.clip(watch_times, 0.5, 600)
vocab = build_dynamic_vocab(watch_times)
print(f"动态词汇表: {vocab[:10]}... (共{len(vocab)}个token)")
test_target = 87.5
tokens = greedy_encode(test_target, vocab)
decoded = greedy_decode(tokens)
print(f"原始值: {test_target}, 编码: {tokens}, 解码: {decoded}, 误差: {abs(decoded - test_target):.2f}")
class GREncoder(nn.Module):
    def __init__(self, user_dim, item_dim, hidden_dim=128):
        super().__init__()
        self.user_proj = nn.Sequential(nn.Linear(user_dim, hidden_dim), nn.ReLU())
        self.item_proj = nn.Sequential(nn.Linear(item_dim, hidden_dim), nn.ReLU())

    def forward(self, user_feat, item_feat):
        return torch.cat([self.user_proj(user_feat), self.item_proj(item_feat)], dim=-1)
class GRDecoder(nn.Module):
    def __init__(self, encoder_dim, vocab_size, d_model=128, nhead=4, num_layers=2):
        super().__init__()
        self.token_embed = nn.Embedding(vocab_size, d_model)
        self.encoder_proj = nn.Linear(encoder_dim, d_model)
        decoder_layer = nn.TransformerDecoderLayer(d_model, nhead, d_model * 4, batch_first=True)
        self.decoder = nn.TransformerDecoder(decoder_layer, num_layers)
        self.output_head = nn.Linear(d_model, vocab_size)

    def forward(self, encoder_out, target_tokens=None, max_steps=10):
        batch_size = encoder_out.size(0)
        memory = self.encoder_proj(encoder_out).unsqueeze(1)
        if target_tokens is not None:
            embeds = self.token_embed(target_tokens)
            seq_len = embeds.size(1)
            causal_mask = nn.Transformer.generate_square_subsequent_mask(seq_len, device=embeds.device)
            combined = torch.cat([memory.expand(-1, seq_len, -1), embeds], dim=1)
            output = self.decoder(combined[:, :-1, :], memory, tgt_mask=causal_mask[:seq_len-1, :seq_len-1])
            logits = self.output_head(output)
            return logits
        else:
            generated = []
            current_input = memory
            for step in range(max_steps):
                output = self.decoder(current_input, memory)
                logits = self.output_head(output[:, -1:, :])
                next_token = logits.argmax(dim=-1)
                generated.append(next_token)
                next_embed = self.token_embed(next_token)
                current_input = torch.cat([current_input, next_embed], dim=1)
            return torch.cat(generated, dim=1)
user_dim, item_dim = 64, 128
encoder = GREncoder(user_dim, item_dim, hidden_dim=64)
decoder = GRDecoder(128, vocab_size=50, d_model=64, nhead=4, num_layers=2)
user_feat = torch.randn(4, user_dim)
item_feat = torch.randn(4, item_dim)
encoder_out = encoder(user_feat, item_feat)
target_tokens = torch.randint(0, 50, (4, 6))
logits = decoder(encoder_out, target_tokens=target_tokens)
print(f"\nEncoder输出: {encoder_out.shape}")
print(f"Decoder logits: {logits.shape}")
```

# 五、课程学习与嵌入混合（CLEM）策略详解

CLEM 解决的核心问题是 Teacher Forcing 导致的训练-推理不一致：

| 阶段 | 训练方式 | β 值 | 说明 |
|------|---------|------|------|
| 训练初期 | 主要使用真实标签 | 0.9 | 稳定训练，避免错误累积 |
| 训练中期 | 混合使用 | 0.5 | 逐步过渡 |
| 训练后期 | 主要使用模型预测 | 0.1 | 接近推理时的实际输入 |
| 推理时 | 纯模型预测 | 0.0 | 完全依赖自回归生成 |

嵌入混合公式：$e_t = \beta \cdot e(s_{t-1}^{gt}) + (1-\beta) \cdot e(\hat{s}_{t-1})$

# 六、常见问题与易错点

| 问题 | 说明 | 建议 |
|------|------|------|
| 词汇表覆盖不足 | 长尾时长无法精确重建 | 增加衰减轮次，降低 epsilon 阈值 |
| 自回归误差累积 | 后续 token 预测错误会累积 | 使用 CLEM 策略缓解训练推理不一致 |
| 编码非唯一 | 同一时长可能有多种 token 组合 | 使用贪心编码确保最短序列和单调性 |
| Huber 损失 δ 选择 | δ 过大趋近 MSE，过小趋近 MAE | 推荐 δ=1.0，根据时长分布调整 |
| 序列长度差异大 | 不同样本生成 token 数差异大 | 使用 padding + mask 处理变长序列 |

# 七、学习总结

1. GR 将连续值回归重构为条件依赖的序列生成任务，是观看时长预测的范式创新
2. 动态词汇表通过百分位衰减构建，平衡了覆盖性和频率均匀性
3. CLEM 策略通过渐进式混合真实标签和模型预测，有效缓解 Teacher Forcing 的曝光偏差
4. 联合损失函数（CE + Huber）同时优化分类精度和回归准确性
5. 离线 XAUC 提升 14.98%，在线 APP 使用时长 +0.112%，验证了工业级价值
