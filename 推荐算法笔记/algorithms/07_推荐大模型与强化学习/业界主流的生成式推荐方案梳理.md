# 面试题：业界主流的生成式推荐方案梳理

1、 谷歌 TIGER：https://arxiv.org/pdf/2305.05065

 核心思想：通过残差量化（RQ-VAE）为广告生成层次化语义 ID，实现语义可解释的离散化表征。  
 技术架构：

 编码阶段：使用预训练文本编码器提取广告标题/描述的特征，经 RQ-VAE 量化生成 3 级 ID（类目 品牌 产品）。  
 生成阶段：Transformer 序列到序列模型基于用户历史行为 ID 序列，自回归预测下一广告的语义 ID。

 创新点

 解决十亿级广告库的存储问题，ID 嵌入表内存占用仅为传统 Embedding 的 1/100。  
 语义碰撞具有可解释性（相似广告共享前缀 ID），冷启动广告召回率提升 $12 \%$ 。

# 2、 百度 COBRA：http://arxiv.org/pdf/2503.02453

 核心思想：级联稀疏ID（粗粒度类目）与稠密向量（细粒度细节），实现由粗到精的生成推荐。  
 技术架构：

 级联表征：广告的稀疏 ID（RQ-VAE 生成）与动态稠密向量（Transformer 编码器输出）拼接输入。  
 交替预测：Causal Transformer 先预测稀疏 ID 定位大类，再生成稠密向量捕捉细节（如"运动鞋" $ ^ { \bullet }$ "透气网面"）。  
 推理优化：BeamFusion 算法融合 Beam Search 得分与 ANN 相似度，平衡精度与多样性。

 创新点：

端到端训练双目标损失：ID 交叉熵+向量对比损失，解决语义 gap 问题。  
 工业级效果：百度 Feed 流广告场景中，Recall@800 达 0.4466，在线 $C V R { + } 3 . 6 \%$ ，ARPU+4.15%。

# 3、 快手 OneRec：https://arxiv.org/pdf/2502.18965

 核心思想：MoE 架构统一召回与排序，直接生成整个推荐 Session。  
 技术架构：

 多模态量化：视频通过 3 级 Codebook 离散化为 Token 序列（如 a_99b_225c_67）。  
 Session 生成：T5 结构 Encoder-Decoder $^ +$ 稀疏 MoE，每层仅激活 $1 3 \%$ 参数，预测 N 个视频的 3 级 ID。  
 DPO 偏好对齐：Softmax-DPO 算法从 Beam Search 结果中筛选最优/最差 Session，通过奖励模型（预测观看时长）优化生成质量。  
 创新点：

 支持千候选视频的毫秒级推理，QPS 提升 5 倍（TensorRT-LLM 优化）。  
 在线 A/B 测试：用户观看时长 $+ 1 . 6 \%$ ，互动率 $+ 3 . 3 6 \%$ 。

# 4、 Meta HSTU：https://arxiv.org/pdf/2402.17152

 核心思想：层次化序列转导单元（HSTU）压缩超长行为序列，突破Transformer 上下文限制。  
 技术架构：

 稀疏注意力：点式聚合注意力替代 Softmax，减少冗余计算。  
 动态压缩：随机长度采样（SL）算法移除 $80 \%$ 低价值历史行为（如 30 天前点击）。  
 推理加速：M-FALCON 算法微批处理候选广告，单卡吞吐量提升 2.99 倍。  
 创新点：

 支持 200 万 Token 上下文，训练速度比 FlashAttention-2 快 15.2 倍。  
 工业场景：在 285 倍复杂度模型下，推理 QPS 反升 2.48 倍。

# 5、 小红书 GenRank：https://arxiv.org/pdf/2505.04180

 核心思想：行为导向的生成式排序，将广告视为上下文，专注预测用户行为（点击/忽略）。  
 技术架构：

 Action-Oriented 组织：

输入序列 $=$ 时间嵌入 $^ +$ 位置嵌入 $^ +$ 广告嵌入 $^ +$ 行为嵌入（历史）/掩码（候选）。

GenRank 引入 Mask Action Embedding，仅允许历史行为与当前候选物品交互，屏蔽其他候选物品。

 轻量偏置编码：线性 I/O 的位置/时间编码替代复杂 Embedding，序列长度压缩 $50 \%$ 。  
 创新点：

 训练速度比 HSTU提升 $9 4 . 8 \%$ ，P99延迟降低 $2 5 \%$ 。在线指标：用户互动行为（点赞/收藏） $+ 1 . 2 5 \%$ ，7日留存$+ 0 . 1 5 \%$ 。

# 六、技术路线对比：物品 ID 表征方式

生成式推荐的核心问题之一是如何表征物品。不同方案对比如下：

| 表征方式 | 代表模型 | 优势 | 劣势 | 适用规模 |
|---------|---------|------|------|---------|
| 传统 Embedding 查表 | DLRM、DIN | 无量化损失、精度高 | 内存随物品数线性增长 | 千万级以内 |
| RQ-VAE 语义 ID | TIGER、OneRec | 内存友好、层次化结构、冷启动友好 | 量化损失、语义碰撞 | 十亿级以上 |
| 稀疏 ID + 稠密向量 | COBRA | 兼顾粗粒度定位和细粒度匹配 | 双索引维护复杂 | 十亿级 |
| 无显式 ID（行为序列） | HSTU、GenRank | 避免 ID 依赖、纯序列建模 | 物品特征利用有限 | 超长行为序列 |

# 七、代码实现：RQ-VAE 语义 ID 编码

```python
import torch
import torch.nn as nn
import torch.nn.functional as F
class RQVAE(nn.Module):
    def __init__(self, input_dim=256, hidden_dim=128, num_levels=3, codebook_size=4096):
        super().__init__()
        self.num_levels = num_levels
        self.codebook_size = codebook_size
        self.encoder = nn.Sequential(
            nn.Linear(input_dim, hidden_dim),
            nn.ReLU(),
            nn.Linear(hidden_dim, hidden_dim),
        )
        self.codebooks = nn.ModuleList([
            nn.Embedding(codebook_size, hidden_dim) for _ in range(num_levels)
        ])
        self.decoder = nn.Sequential(
            nn.Linear(hidden_dim, hidden_dim),
            nn.ReLU(),
            nn.Linear(hidden_dim, input_dim),
        )
        for cb in self.codebooks:
            nn.init.uniform_(cb.weight, -1.0 / codebook_size, 1.0 / codebook_size)

    def encode(self, x):
        z = self.encoder(x)
        residual = z
        indices_list = []
        quantized_sum = torch.zeros_like(z)
        for level in range(self.num_levels):
            distances = torch.cdist(residual.unsqueeze(0), self.codebooks[level].weight.unsqueeze(0)).squeeze(0)
            idx = distances.argmin(dim=-1)
            indices_list.append(idx)
            quantized = self.codebooks[level](idx)
            quantized_sum = quantized_sum + quantized
            residual = residual - quantized.detach() + quantized
        semantic_ids = torch.stack(indices_list, dim=-1)
        return semantic_ids, quantized_sum

    def decode(self, quantized):
        return self.decoder(quantized)

    def forward(self, x):
        semantic_ids, quantized = self.encode(x)
        recon = self.decode(quantized)
        recon_loss = F.mse_loss(recon, x)
        commitment_loss = 0.0
        z = self.encoder(x)
        residual = z
        for level in range(self.num_levels):
            distances = torch.cdist(residual.unsqueeze(0), self.codebooks[level].weight.unsqueeze(0)).squeeze(0)
            idx = distances.argmin(dim=-1)
            quantized = self.codebooks[level](idx)
            commitment_loss += F.mse_loss(residual, quantized.detach())
            residual = residual - quantized.detach()
        total_loss = recon_loss + 0.25 * commitment_loss
        return semantic_ids, total_loss
batch_size, input_dim = 64, 256
model = RQVAE(input_dim=input_dim, hidden_dim=128, num_levels=3, codebook_size=4096)
item_features = torch.randn(batch_size, input_dim)
semantic_ids, loss = model(item_features)
print(f"Semantic IDs: {semantic_ids.shape}")
print(f"Example IDs: {semantic_ids[0].tolist()}")
print(f"Total Loss: {loss.item():.4f}")
optimizer = torch.optim.Adam(model.parameters(), lr=1e-3)
for epoch in range(5):
    optimizer.zero_grad()
    ids, loss = model(item_features)
    loss.backward()
    optimizer.step()
    print(f"Epoch {epoch+1}, Loss: {loss.item():.4f}")
```

# 八、生成式推荐与传统推荐的范式差异

| 维度 | 传统多阶段推荐 | 生成式推荐 |
|------|-------------|----------|
| 建模范式 | 判别式（打分+排序） | 生成式（序列生成） |
| 物品表征 | 稠密 Embedding 向量 | 离散语义 ID（Token） |
| 候选集生成 | 独立召回通道（协同过滤/向量检索） | 模型自回归生成 |
| 排序方式 | 多阶段打分精筛 | 生成过程隐含排序 |
| 上下文利用 | 各阶段独立，信息逐级丢失 | 统一序列建模，信息无损传递 |
| Scaling Law | 千亿参数即饱和 | 万亿参数仍持续提升 |
| 系统复杂度 | 多模块级联，维护成本高 | 端到端统一模型 |
| 冷启动处理 | 需独立冷启动通道 | 语义 ID 天然支持新物品 |

# 九、常见问题与易错点

| 问题 | 说明 | 建议 |
|------|------|------|
| 语义 ID 碰撞 | 大规模物品库中不同物品可能映射到相同 ID | 增加量化层级、扩大 codebook、使用 Balanced K-means |
| 生成多样性不足 | 自回归生成容易陷入重复模式 | 使用温度采样、top-p 采样、重复惩罚 |
| 推理延迟高 | 自回归逐 token 生成延迟大 | 投机解码、KV 缓存优化、TensorRT 加速 |
| 训练数据构造 | Session 级训练样本如何切分 | 按用户会话边界切分，确保 Session 内行为连贯 |
| 长尾物品覆盖 | 生成模型偏向热门物品 | 在损失函数中增加长尾权重，或在解码时加入多样性约束 |

# 十、学习总结

1. 生成式推荐将推荐任务从"打分排序"重构为"序列生成"，是推荐系统的范式性变革
2. 物品表征是核心：从传统 Embedding 到语义 ID（RQ-VAE），解决了十亿级物品库的表征和存储问题
3. 五大方案各有侧重：TIGER 重语义 ID，COBRA 重稀疏稠密融合，OneRec 重端到端 Session 生成，HSTU 重超长序列压缩，GenRank 重行为导向排序
4. 工业落地需平衡效果与效率：MoE 稀疏激活、KV 缓存分块、投机解码等是关键优化手段
5. 生成式推荐验证了推荐系统的 Scaling Law：模型参数从千亿到万亿持续提升，与传统 DLRM 的饱和特性形成鲜明对比
