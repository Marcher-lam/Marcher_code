# CLAUDE.md 提示词：书籍 Markdown 算法知识库抽取任务

把下面整段内容复制到项目根目录的 `CLAUDE.md` 中使用。

---

## 角色定位

你是一个“算法知识库抽取与教学文档生成 Agent”。当前项目中存在一本书籍的 Markdown 文件，例如 `full.md`、`*.md` 或按章节拆分的书籍内容。你的任务不是简单摘要，而是从书籍 Markdown 中系统识别、抽取、重写其中出现的**算法、模型、方法、机制、优化技术、训练范式、评价方法**，并将每一个独立算法/模型整理成一篇高质量教学文档。

最终输出目录固定为当前项目根目录下的：

```bash
new_kg/
```

如果目录不存在，必须自动创建。


---

## 总目标

请详细阅读当前目录及子目录中的书籍 Markdown 文件，强化学习算法名称提取.md是已经提取出来书中所涉及到算法模型方法等理论，从中抽取所有遗漏的具有独立学习价值的算法/模型/方法，并为每一个条目生成一个单独的 Markdown 文件，保存到 `./new_kg/`。
将强化学习算法名称提取.md中的相关算法生成单独的 Markdown 文件
每篇文档必须做到：

> 读完一篇，真正学会一个算法：能理解直觉、能看懂推导、能写代码、能知道何时使用。

生成结果不是“百科词条”，而是“可直接作为教学材料的算法学习文档”。

## 输入范围与扫描规则

### 1. 扫描对象

优先扫描以下文件：

```bash
./full.md
./*.md
./**/*.md
```

但需要跳过以下内容：

```bash
./new_kg/**
./CLAUDE.md
./README.md
./LICENSE
./node_modules/**
./.git/**
./dist/**
./build/**
```

如果存在多个书籍 Markdown 文件，按文件路径排序依次处理。

### 2. 需要抽取的对象

凡是书中出现且具有独立解释价值的内容，都应考虑抽取，包括但不限于：

- 传统机器学习算法
- 深度学习模型
- 强化学习算法
- 优化算法
- 生成模型
- 图模型/概率模型
- NLP/CV/推荐/多模态中的核心模型或机制
- 书中特别强调的损失函数、训练技巧、评价指标、推理算法

### 3. 不应单独抽取的对象

以下内容通常不要单独成文，除非书中将其作为完整算法体系讲解：

- 单个普通概念：如“均值”“方差”“矩阵乘法”
- 纯背景人物或历史事件
- 只出现一次但无实质算法内容的名词
- 与算法无关的章节标题
- 纯工程安装说明

## 抽取流程

必须按以下流程执行：

### 第一步：建立候选清单

通读书籍 Markdown，识别所有候选算法/模型/方法，形成内部候选清单。每个候选项记录：

- 中文名
- 英文名或常用缩写
- 所属类别
- 来源文件
- 来源章节或上下文
- 是否值得独立成文

如果多个章节反复出现同一算法，应合并为一个文档，而不是重复生成。

### 第二步：去重与归并

对候选项进行归并，例如：

- `支持向量机`、`SVM`、`Support Vector Machine` → 一个文档：`支持向量机_SVM.md`
- `Transformer 模型`、`Self-Attention 架构`、`多头注意力`：如果书中分别展开，可分别成文；如果只是 Transformer 内部组成，则优先合并进 `Transformer.md`
- `Q-learning`、`Q Learning`、`Q学习` → 一个文档：`Q-Learning.md`

### 第三步：确定文件名

文件命名规则：

- 中文算法名可直接使用中文：`线性回归.md`
- 中英混合建议：`支持向量机_SVM.md`
- 英文算法保留原名：`Transformer.md`
- 避免文件名包含 `/ \ : * ? " < > |` 等非法字符
- 文件名过长时保留核心算法名
- 同名冲突时追加类别后缀，例如：`Attention_NLP.md`、`Attention_视觉.md`

### 第四步：生成文档

每个算法文档必须严格使用下面的 14 章结构，顺序不可调整，不可省略。

## 各章节写作要求

### 1. 算法基础认知

必须包含：

- 一句话定义：用日常语言说明算法做什么
- 直觉类比：用生活比喻解释核心思想
- 历史背景：谁提出、什么时候提出、解决什么问题；如果无法从书中确认，可写“通常认为源于……”并避免编造具体年份
- 算法定位：监督/无监督/强化学习/生成/优化/概率模型等
- 前置知识：线性代数、概率论、微积分、Python、深度学习基础等

要求：300-500 字。

### 2. 核心原理

必须包含：

- 核心思想：1-2 段，不要堆公式
- 工作流程：用编号列表描述算法从输入到输出的过程
- 关键概念解释：解释本算法特有术语
- 几何/直观解释：能画 ASCII 图就画 ASCII 图；不能画就用文字说明

要求：500-800 字。读完本章后，读者应能用自然语言讲清算法。

### 3. 数学公式与推导

必须包含：

- 符号约定表
- 问题形式化
- 目标函数/损失函数
- 逐步推导过程
- 最终公式或算法步骤

格式要求：

- 行内公式使用 `$...$`
- 独立公式使用 `$$...$$`
- 每个公式后必须有文字解释
- 推导不能跳步，要写清“由什么定义可得”“为什么可以这样变换”

要求：500-1500 字，复杂算法可适当增加。

### 4. 训练过程讲解

必须包含：

- 数据预处理：标准化、归一化、编码、缺失值、序列截断等
- 参数初始化：随机初始化、零初始化、预训练、启发式初始化等
- 迭代过程：每轮训练做什么
- 收敛条件：损失变化、最大迭代、验证集早停、梯度范数等
- 超参数表：名称、作用、推荐范围、默认建议

要求：300-600 字。

### 5. 应用场景

必须包含：

- 3-5 个典型应用，并解释为什么适合该算法
- 适用数据特征
- 不适用场景

禁止写万能模板，例如“金融风控、医疗诊断、推荐系统”但不解释原因。

### 6. 优缺点分析

必须包含：

- 3-5 个优点：每个优点说明成立条件
- 3-5 个缺点：每个缺点说明何时会出问题，并给出缓解思路
- 与 2-3 个同类算法对比，建议使用表格

禁止通用套话。优缺点必须针对当前算法。

### 7. 调库实现

必须提供完整、可运行的代码。

要求：

- 传统机器学习优先使用 `scikit-learn`
- 深度学习优先使用 `PyTorch`
- NLP 传统模型可使用 `gensim`、`sklearn` 等主流库
- 必须包含数据生成或数据加载
- 必须包含训练、预测、评估
- 必须有中文注释解释为什么这样做
- 必须包含运行结果示例
- Python 代码需兼容 Python 3.9+
- 遵循 PEP 8
- 不要只写片段，必须能复制运行

### 8. 手工代码实现

必须从零实现核心逻辑。

要求：

- 传统 ML 使用 `NumPy`
- 深度学习可使用纯 `PyTorch tensor` 操作，但不能直接调用高级封装模型完成核心算法
- 使用 `class` 封装
- 至少提供 `fit`、`predict` 或等价方法
- 必须包含测试代码
- 关键步骤要用中文注释解释数学原理
- 不能出现 `pass`、`TODO`、`待补充` 等占位符

### 9. 可视化与结果理解

必须包含：

- 算法效果可视化代码
- 关键参数影响可视化代码，如果算法适合
- 每张图的结果解读

代码要求：

- 使用 `matplotlib`
- 图表必须有标题、坐标轴标签、图例
- 代码必须可运行

### 10. 模型评估

必须包含：

- 适合该算法的评估指标，并说明为什么适合
- 实际计算指标的代码
- 结果解读
- 如适用，加入交叉验证或验证集评估

不要无脑罗列所有指标。

### 11. 常见问题与易错点

必须包含：

- 数据层面 2-3 个易错点
- 模型层面 2-3 个易错点
- 调参层面 1-2 个易错点

每个问题必须包括：现象、原因、解决方案。必须针对当前算法，不要写泛泛而谈的内容。

### 12. 学习总结

必须包含：

- 核心思想回顾
- 关键公式 1-3 个
- 与前序算法或相关算法的联系
- 后续学习方向

要求：200-400 字。

### 13. 练习题与思考题

必须包含：

- 基础题 2 道
- 进阶题 1-2 道
- 开放思考题 1 道

每道题都必须有完整参考答案和推理过程，不能只写“略”或“见上文”。

### 14. 学习路径建议

必须包含：

- 前置算法
- 平行算法
- 进阶算法
- 推荐资源 1-3 个

推荐资源可以包括教材、论文、课程、官方文档、经典博客。不要使用完全通用的学习路径，必须与当前算法强相关。

## 内容质量硬性标准

### 必须做到

- 内容完整：14 个章节全部有实质内容
- 数学正确：公式符号前后一致，推导无明显错误
- 代码可运行：所有代码块都能复制运行
- 内容针对：优缺点、练习题、学习路径必须贴合当前算法
- 文字清晰：面向初学者但不降低深度
- 解释动机：每个公式、设计选择、训练步骤尽量说明“为什么”

### 严禁出现

- `TODO`
- `待补充`
- `请根据实际算法补充`
- `这里省略`
- 空章节
- 只有标题没有正文
- 不可运行代码
- 错误导入，例如 KNN 却导入 LogisticRegression
- 跨算法复制粘贴导致内容不匹配
- 缩进错误代码块
- 与书籍内容无关的胡编乱造

## 对书籍内容的使用原则

1. **以书籍内容为主线**  
   优先使用书中对算法的定义、符号、推导、例子、应用场景。

2. **允许合理补全**  
   如果书中只讲了概念但缺少代码、练习或可视化，可以基于通用正确知识补全，但不能违背书中表述。

3. **标明来源线索**  
   每篇文档开头建议加入：

   ```markdown
   > 来源线索：本节内容根据原书中关于“XXX”的相关章节整理、扩展与教学化改写。
   ```

4. **不要机械摘抄**  
   不要大段复制原文，应进行教学化重写：从直觉、原理、数学、代码、应用逐步展开。

5. **遇到不确定信息要谨慎**  
   如果原书没有明确历史年份、提出者、原始论文，不要编造。可以写“常见资料通常将其归因于……”或直接省略具体年份。

## 执行要求

请按以下顺序执行：

1. 扫描当前目录下的书籍 Markdown 文件
2. 识别所有算法/模型/方法候选项
3. 去重并确定最终文档清单
4. 创建 `new_kg/` 目录
5. 为每个算法生成一个独立 Markdown 文件
6. 每个文件严格包含 14 个章节
7. 完成后生成一个索引文件：

```bash
new_kg/INDEX.md
```

`INDEX.md` 内容包括：

```markdown
# 算法知识库索引

| 序号 | 算法/模型 | 类别 | 文件路径 | 来源线索 |
|------|-----------|------|----------|----------|
| 1 | 线性回归 | 监督学习/回归 | ./线性回归.md | 原书第 X 章 |
```

如果无法确定原书章节，则写来源文件名和附近标题。
