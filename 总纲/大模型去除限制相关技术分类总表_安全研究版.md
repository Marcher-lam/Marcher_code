# 大模型去除限制相关技术分类总表（安全研究与防护视角）

> 重要说明：本文将“大模型去除限制相关技术”作为 **AI 安全研究、红队评估、防护加固、模型治理** 主题进行分类整理。  
> 本文不会提供可直接用于绕过安全限制、移除安全对齐、生成有害内容或制作不受控模型的操作步骤、代码、数据集构造流程或可执行攻击流程。  
> 重点是：**技术类别、研究原理、风险点、防护思路、评测维度与治理框架**。

# 1. 基础概念

## 1.1 什么是“限制”

在大模型安全语境中，“限制”通常指：

- 有害内容拒答
- 安全策略遵循
- 系统提示词遵循
- 工具权限限制
- 隐私保护
- 版权保护
- 不泄露机密
- 不生成违法危险内容
- 不执行高风险操作
- 不输出敏感系统指令
- 不泄露训练数据或用户数据

这些限制通常来自：

- 预训练数据过滤
- SFT 安全数据
- RLHF / RLAIF
- DPO / 偏好优化
- 系统提示词
- 安全分类器
- 工具调用策略
- 输出审核
- 产品级风控

## 1.2 “去除限制”的层级

| 层级 | 含义 |
|---|---|
| Prompt 层 | 通过输入诱导模型忽略规则 |
| 对话层 | 通过多轮上下文改变模型行为 |
| 检索层 | 用恶意文档污染 RAG 上下文 |
| 工具层 | 诱导 Agent 调用不该调用的工具 |
| 解码层 | 通过采样、logit、格式等操控输出 |
| 激活层 | 干预中间表示，削弱拒答方向 |
| 权重层 | 修改模型权重，降低拒答倾向 |
| 微调层 | 用特定数据继续训练，改变安全行为 |
| 对齐层 | 逆向或削弱 RLHF/SFT 后的安全偏好 |
| 系统层 | 绕过 API、网关、权限和审计策略 |

## 1.3 风险边界

相关技术若被滥用，可能导致：

- 生成危险操作说明
- 泄露隐私、密钥、企业机密
- 绕过企业安全策略
- 诱导工具误调用或越权调用
- 自动化攻击增强
- 恶意代码生成
- 欺诈、钓鱼、社会工程
- 模型产品合规风险
- 企业 Agent 越权执行

# 2. Prompt 级绕过技术分类

## 2.1 直接越狱提示

常见类别：

- Ignore Previous Instructions
- DAN-style Prompt
- Roleplay Jailbreak
- Developer Mode Prompt
- Unfiltered Assistant Prompt
- Fictional Scenario Framing
- Hypothetical Framing
- Simulation Framing

风险：

- 对弱安全模型有效
- 变体极多
- 容易和正常创作请求混淆

防护：

- 系统提示词优先级
- 安全分类器
- 输入意图识别
- 输出审核
- 拒答一致性训练

## 2.2 角色扮演绕过

方式：

- 扮演专家
- 扮演小说角色
- 扮演无规则模型
- 扮演终端/模拟器
- 扮演安全研究员
- 扮演审查器
- 扮演翻译器

风险：安全边界被“语境”稀释，模型可能把危险请求当成创作任务。

防护：

- 对角色扮演中的真实意图做检测
- 区分虚构表达与可执行危险信息
- 对高风险领域进行语义级安全审查

## 2.3 假设性与教育性包装

常见包装：

- “仅用于教育”
- “仅用于小说”
- “仅用于防御”
- “仅用于学术研究”
- “不要真的执行”
- “帮我理解原理”
- “写成历史分析”
- “写成新闻报道”

防护：分析实际输出是否提供可操作伤害能力；对高风险步骤、参数、代码、流程进行降级；提供安全替代内容。

## 2.4 分步诱导

方式：

- 先询问无害基础知识
- 再逐步组合成危险流程
- 拆分敏感目标
- 在最后要求整合

防护：

- 多轮上下文安全审查
- Intent accumulation detection
- 对话级风险状态机
- 任务级安全边界

# 3. Prompt Injection 技术分类

## 3.1 Prompt Injection 定义

Prompt Injection 是指通过输入内容操控模型行为，使其违反原始任务、系统指令或安全策略。模型无法天然区分“指令”和“数据”，因此网页、文档、邮件、工具返回内容都可能携带恶意指令。

## 3.2 直接 Prompt Injection

形式：

- 用户直接输入恶意指令
- 要求模型忽略系统消息
- 要求泄露 prompt
- 要求越权工具调用

防护：

- 指令层级隔离
- 系统消息不可见
- 规则不可由用户覆盖
- 工具调用权限控制

## 3.3 间接 Prompt Injection

恶意指令隐藏在：

- 网页
- PDF
- 邮件
- 日历
- 代码仓库
- RAG 文档
- 搜索结果
- 工具返回
- 图片 OCR 文本
- 数据库字段
- 用户上传文件

防护：

- 将外部内容标记为 untrusted data
- RAG 内容与指令隔离
- Tool result sandbox
- 工具调用前二次确认
- 最小权限原则

## 3.4 RAG Prompt Injection

攻击位置：

- 检索文档
- 网页 chunk
- 企业知识库
- 用户上传文件
- Markdown 注释
- HTML 隐藏文本
- 表格单元格
- 图片 OCR

防护：

- 检索内容净化
- 文档指令剥离
- 引用内容只作为证据
- 证据与指令通道分离
- 结果交叉验证
- 高风险工具独立策略模型审批

## 3.5 工具调用注入

风险：

- 恶意网页让浏览器 Agent 点击按钮
- 恶意邮件让邮件 Agent 转发敏感信息
- 恶意文档让代码 Agent 执行命令
- 恶意日志让运维 Agent 删除资源

防护：

- Tool allowlist / denylist
- Human-in-the-loop
- 参数级安全检查
- 工具调用审计
- 沙箱执行
- 敏感操作二次确认
- 不可信内容不可直接驱动工具

# 4. Jailbreak 攻击分类

## 4.1 Jailbreak 基础

Jailbreak 是 Prompt Injection 的一种特殊形式，目标是让模型忽略安全协议或绕过拒答机制。

分类：

- 手工 jailbreak
- 自动化 jailbreak
- 对抗后缀 jailbreak
- 多轮 jailbreak
- 编码 jailbreak
- 角色扮演 jailbreak
- 多模态 jailbreak
- 长上下文 jailbreak
- Agent jailbreak

## 4.2 手工 Jailbreak

特点：

- 人类编写提示词
- 利用模型服从性
- 利用角色扮演
- 利用规则冲突
- 利用格式约束

防护：红队数据训练、jailbreak prompt 识别、安全系统提示词、输出侧安全审查。

## 4.3 自动化 Jailbreak

方法类别：

- 遗传算法搜索
- 梯度近似搜索
- 强化学习搜索
- LLM 自动生成 jailbreak
- Prompt mutation
- Adversarial suffix search
- Multi-agent attack generation

防护：自动红队、持续安全评测、变体数据增强、模型和系统双层防御。

## 4.4 对抗后缀攻击

概念：在用户请求后添加一段特殊 token 或字符串，诱导模型输出目标内容。

防护：

- 后缀异常检测
- token 分布检测
- 输入规范化
- 随机化防御
- 训练鲁棒性增强
- 输出安全审查

## 4.5 Many-shot Jailbreak

概念：在长上下文中放入大量示例，让模型通过 in-context learning 学到不安全模式。长上下文模型更容易受影响。

防护：

- 长上下文安全评估
- 对示例模式进行风险识别
- 上下文窗口分区
- 高风险示例截断或降权
- 长上下文安全训练

## 4.6 编码与混淆 Jailbreak

方式：

- Base64
- Unicode 混淆
- 零宽字符
- ROT13
- 反向文本
- 翻译
- 拼音/谐音
- 表情符号编码
- Markdown/HTML 混淆
- 代码字符串拼接
- OCR 隐藏文本

防护：输入规范化、编码检测、Unicode 清洗、多语言安全分类、模型端语义安全审查。

## 4.7 隐喻与文学化绕过

形式：诗歌、隐喻、小说、谜语、童话、暗语、类比、符号化描述。

防护：语义级风险识别、多轮澄清、高风险领域概念映射、对隐喻进行安全解释而非执行。

# 5. 多模态绕过技术

## 5.1 图像 Prompt Injection

恶意指令可隐藏在：图片文字、截图、二维码、手写文本、OCR 内容、UI 界面、水印、隐藏像素、对抗 patch。

防护：OCR 内容标记为不可信；图像文本与系统指令隔离；UI 操作前权限校验；多模态输入安全分类。

## 5.2 音频 Prompt Injection

形式：语音指令注入、隐藏音频命令、超声波命令、背景音诱导、ASR 错误利用。

防护：ASR 输出安全审查、声纹和权限验证、高风险操作二次确认、音频输入可信度评估。

## 5.3 视频 Prompt Injection

风险：视频帧中文字指令、多帧逐步注入、屏幕录制中包含恶意命令、Agent 观看视频后执行错误任务。

防护：视频帧 OCR 风险检测、时间维度一致性检查、视频内容作为数据而非指令、工具调用隔离。

# 6. 训练时攻击与对齐污染

## 6.1 数据投毒

目标：改变模型行为、植入后门、削弱安全拒答、影响特定话题输出、诱导特定触发器行为。

类型：

- Label Poisoning
- Data Poisoning
- Backdoor Poisoning
- Preference Data Poisoning
- Instruction Data Poisoning
- Safety Data Poisoning
- RAG Corpus Poisoning

防护：数据溯源、数据去重、异常样本检测、标注审计、训练数据安全扫描、数据版本管理、训练后行为回归测试。

## 6.2 后门攻击

形式：Trigger phrase、特殊 token、罕见 Unicode、特定风格、特定主题、特定图像 patch、特定上下文模式。

防护：Trigger search、Activation anomaly detection、Backdoor benchmark、Fine-pruning、Model inspection、安全微调、去后门训练。

## 6.3 偏好数据污染

攻击方式：将不安全回答标为 preferred；将安全拒答标为 rejected；污染 reward model；污染 DPO pair；污染安全示例。

防护：偏好数据审计、多标注者一致性、reward model 红队、偏好数据异常检测、安全集回归评测。

## 6.4 恶意微调

概念：在开源 base/instruct 模型上继续微调，用不安全数据削弱拒答行为或改变安全边界。

防护：模型发布治理、权重访问管理、安全许可证、量化/微调模型审计、下游模型安全评测。

# 7. 对齐移除与弱化技术分类

## 7.1 对齐移除概念

对齐移除通常指削弱模型经过 SFT/RLHF/DPO 等对齐训练后形成的安全行为。

可能路径：

- 继续微调覆盖安全偏好
- 模型编辑
- 激活干预
- 权重消融
- 拒答方向移除
- reward hacking
- 解码层操控

安全研究目的：理解拒答机制、评估安全脆弱性、改进更稳健的安全对齐、降低过度拒答、提升良性请求可用性。

## 7.2 过度拒答与合理去拒答

| 类型 | 含义 |
|---|---|
| 合理安全拒答 | 对真实危险请求拒绝 |
| 过度拒答 | 对无害请求也拒绝 |
| 去除过度拒答 | 让模型回答安全但被误拒的问题 |
| 去除安全限制 | 让模型回答危险请求 |

安全目标应是：**降低过度拒答，同时保持对真实危险请求的拒答能力。**

## 7.3 Unlearning

LLM Unlearning 原本用于：去除敏感知识、去除版权内容、去除有害行为、降低幻觉、修正错误记忆。

方法类别：

- Gradient Ascent Unlearning
- Negative Preference Optimization
- Forget + Retain Training
- Task Vector Negation
- Representation Unlearning
- Elastic Weight Consolidation
- Knowledge Unlearning
- Safety Behavior Unlearning

风险：被滥用为“安全行为遗忘”；可能破坏模型通用能力；可能产生不可控副作用。

## 7.4 Model Editing

方法：

- ROME
- MEMIT
- MEND
- SERAC
- Knowledge Neurons
- Task Vector Editing
- Rank-one Update
- Low-rank Model Editing
- Activation Patching

风险：可被用于修改安全行为；局部编辑可能有全局副作用；难以完全预测影响范围。

防护：编辑影响范围评估、安全集回归、层级监控、权重差异审计。

# 8. 表示层干预：Refusal Direction 与 Activation Steering

## 8.1 Refusal Direction

研究发现，部分安全对齐模型的拒答行为可能与激活空间中的某些方向相关。

概念性表达：

```text
refusal direction ≈ harmful request activations 与 harmless request activations 的差异方向
```

研究意义：理解拒答机制、解释安全对齐行为、分析跨语言拒答迁移、设计更稳健防护、分析过度拒答。

风险：该方向可能被用于削弱拒答；单一方向假设可能过于简化；不同模型/语言/层有差异。

## 8.2 Activation Steering

类别：

- Activation Addition
- Activation Subtraction
- Directional Ablation
- Projection-based Steering
- Contrastive Activation Addition
- Representation Engineering
- Inference-time Intervention
- Safety Steering
- Refusal Steering

用途：控制风格、控制情绪、增强诚实性、减少过度拒答、安全干预、可解释性研究。

风险：不当使用可绕过安全；参数选择敏感；可能损伤模型能力。

## 8.3 Directional Ablation

概念：在激活空间移除某个方向上的分量。如果该方向与拒答相关，可能削弱拒答行为。

注意：本文不提供可执行公式、代码或层选择流程；该技术应仅用于受控安全研究和防御评估。

防护意义：说明单点拒答方向可能脆弱，需要多层、多机制、动态安全防护。

## 8.4 Refusal Vector Transfer

研究问题：拒答方向是否跨模型、跨语言、跨任务、跨安全策略通用。

防护：多语言安全训练、跨语言拒答一致性评测、激活空间鲁棒性检查、动态拒答机制。

# 9. 权重层干预：Abliteration / Ablation 类技术

## 9.1 Abliteration 概念

Abliteration 通常指通过识别模型中的“拒答相关方向”，并对模型权重或激活进行修改，从而弱化拒答行为。

研究语境：mechanistic interpretability、refusal behavior analysis、safety robustness evaluation、over-refusal reduction、alignment fragility analysis。

风险：可被滥用为“移除安全护栏”；修改后模型可能更易输出危险内容；对模型能力和稳定性有副作用。

## 9.2 Standard Ablation

概念：从权重或激活中移除拒答方向分量。直接消融可能改变权重范数并损伤模型能力。

风险：能力退化、输出风格异常、安全行为缺失、不可控副作用。

## 9.3 Orthogonal Projection Ablation

概念：将表示或权重投影到与目标方向正交的子空间，目标是去除某个行为方向影响。

研究用途：分析某类行为是否由特定方向控制；研究 refusal vector 的因果影响。

防护启示：如果安全只依赖单一线性方向，可能不稳健；安全机制应分布式、多层、多目标。

## 9.4 Norm-preserving Ablation

概念：在移除方向分量时尽量保持原向量范数，目标是减少能力损伤。

风险：若用于拒答方向，可能在保持能力的同时削弱拒答；更难通过简单质量退化检测发现。

防护：行为安全评测、权重差异审计、拒答机制多样化。

## 9.5 Projected Ablation

概念：对一个或多个方向做投影处理，可能结合 harmless / harmful 方向做区分，目标是更精细地修改行为方向。

风险：可用于更定向地改变安全行为，对模型内部机制理解要求更高。

## 9.6 Norm-preserving Biprojected Abliteration（范数保持双投影消融法）

用户提到的“范数保持双投影消融法”可归入此类。

概念性描述：

- 属于拒答方向消融的变体
- 关注在消融目标方向时保持权重或表示范数
- “双投影”通常表示同时考虑多个方向或子空间关系
- 目标是更精细地改变拒答相关表示，同时减少模型能力损伤

安全研究意义：

- 说明简单拒答方向可能存在可操纵性
- 可用于评估模型安全机制是否过度依赖单一方向
- 可帮助设计更强的安全训练和拒答机制

风险：

- 可能被用于制造弱安全模型
- 可能降低模型对危险请求的拒答能力
- 可能绕过普通 prompt 层防护

防护方向：

- 多机制安全对齐
- 动态拒答重构
- 表示层随机化训练
- 拒答方向鲁棒训练
- 安全集和过拒答集同时评测
- 权重完整性检测
- 模型发布前安全审计

## 9.7 Optimal Transport Refusal Ablation

概念：将拒答行为视为激活分布结构问题，不只使用一维 refusal direction，尝试通过分布对齐或传输思想分析拒答表示。

安全意义：拒答机制可能是高维分布结构，防御也应避免只依赖单一方向。

# 10. 推理时行为操控

## 10.1 System Prompt Override

形式：要求忽略系统提示词、输出系统提示词、重新定义规则、切换角色。

防护：系统消息不可由用户覆盖；分离 instruction 与 data；输出前安全策略检查；不泄露系统提示词。

## 10.2 Logit Bias 与解码操控

概念：通过改变 token logits 影响输出。若开放过强控制，可能影响拒答 token 或强制模型输出不安全序列。

防护：限制 logit bias 范围；禁止影响安全关键 token；输出审核；高风险请求不允许用户控制解码参数。

## 10.3 Sampling 参数操控

参数：temperature、top_p、top_k、repetition penalty、max_tokens、stop sequences。

风险：高温采样可能提高不稳定输出概率；stop sequence 可截断安全提示；max_tokens 可诱导不完整拒答。

防护：安全场景固定采样策略；stop sequence 审查；输出完整性检测；safety decoder。

## 10.4 Structured Output 绕过

风险：用户要求 JSON/XML/YAML 格式输出危险字段；模型为满足 schema 输出不安全内容；function calling 参数被注入。

防护：Schema 级安全约束；参数级审查；工具调用前策略模型检查；高风险字段拒绝填充。

# 11. 过度拒答缓解技术

## 11.1 过度拒答问题

过度拒答表现：安全但敏感的话题被拒绝；合法科研内容被拒绝；新闻/历史/文学内容被拒绝；医疗/法律泛信息被拒绝；安全防御研究被误拒。

目标：**降低无害请求拒答率，同时保持有害请求拒答率。**

## 11.2 安全保留式去拒答

方法类别：

- Fine-tuning on benign hard cases
- Contrastive safety training
- Activation-based over-refusal reduction
- Boundary clarification data
- Benign-sensitive dataset
- Refusal calibration
- Harmlessness-preserving alignment
- ACTOR-like activation training
- Safety-preserving preference optimization

## 11.3 拒答校准

指标：

- Over-refusal Rate
- Under-refusal Rate
- False Refusal
- False Compliance
- Safety-Utility Tradeoff
- Benign Sensitive Accuracy
- Harmful Refusal Accuracy

防护目标：不应简单“减少拒答”，应区分合法请求与危险请求，需要双集评测：benign-sensitive + harmful。

# 12. 防御与加固技术

## 12.1 Prompt 层防御

技术：安全系统提示词、指令优先级、Prompt policy、Prompt injection detector、输入规范化、编码清洗、高风险意图识别、多轮上下文审查、拒答模板。

## 12.3 表示层防御

## 12.4 系统层防御

技术：输入输出双向审核、工具权限隔离、最小权限原则、审计日志、人类确认、沙箱执行、速率限制、账户风控、数据访问控制、RAG 内容隔离、外部内容可信度标注。

## 12.5 Agent 防御

## 12.6 RAG 防御

措施：文档清洗、指令剥离、HTML 隐藏文本检测、prompt injection scanner、检索内容作为 evidence 而非 instruction、多源交叉验证、引用溯源、上下文分区、安全模板、输出事实性检查。

# 18. 总结

大模型去除限制相关技术，从安全研究视角可以概括为以下大类：

1. **Prompt 级绕过**：直接越狱、角色扮演、假设性包装、分步诱导  
2. **Prompt Injection**：直接注入、间接注入、RAG 注入、工具调用注入  
3. **Jailbreak 攻击**：手工越狱、自动化越狱、对抗后缀、many-shot、编码混淆  
4. **多模态绕过**：图像、音频、视频中的隐藏指令或对抗输入  
5. **训练时攻击**：数据投毒、后门、偏好数据污染、安全数据污染、恶意微调  
6. **对齐移除/弱化**：继续微调、模型编辑、unlearning、偏好反转  
7. **表示层干预**：Activation Steering、Refusal Direction、Directional Ablation  
8. **权重层干预**：Abliteration、Orthogonal Projection、Norm-preserving Ablation、Projected Ablation  
9. **范数保持双投影消融类**：属于更精细的拒绝方向消融技术，安全研究中用于评估拒答机制脆弱性  
10. **推理时操控**：system prompt override、logit bias、sampling 参数、structured output 滥用  
11. **过度拒答缓解**：安全保留式去拒答、拒答校准、benign-sensitive 数据训练  
12. **防护与治理**：安全对齐、红队训练、RAG 隔离、工具权限、监控审计、动态拒答重构  

一句话总结：

> 大模型“去除限制”相关技术本质上揭示了当前安全对齐机制的脆弱性；正确用途不是制造不受控模型，而是通过红队评估、机制解释、过度拒答校准和系统级防护，构建更稳健、更可控、更可信的大模型系统。
