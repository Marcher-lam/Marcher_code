# 人工智能模型量化技术分类总表

> 说明：模型量化（Quantization）是将模型中的权重、激活、KV Cache、梯度或优化器状态从高精度表示（如 FP32/BF16/FP16）转换为低精度表示（如 FP8/FP4/INT8/INT4/INT2）的技术。  
> 其目标是 **降低显存/内存占用、降低带宽压力、提升推理吞吐、降低部署成本、支持端侧/边缘设备运行大模型**。  
> 本文按 **数值格式 → PTQ → QAT → LLM 量化 → KV Cache 量化 → 训练量化 → 硬件/推理引擎 → 评测与工程落地** 系统分类。

---

# 1. 模型量化基础

## 1.1 什么是量化

量化是将高精度数值映射到低精度数值：

```text
FP32 / BF16 / FP16 → INT8 / INT4 / FP8 / FP4 / Binary
```

基本公式：

```text
q = round(x / scale + zero_point)
x_hat = scale * (q - zero_point)
```

其中：

- `x`：原始浮点值
- `q`：量化后的整数值
- `scale`：缩放因子
- `zero_point`：零点偏移
- `x_hat`：反量化后的近似值

---

## 1.2 量化的核心收益

主要收益：

1. **降低模型大小**  
   FP16 权重每个参数 2 字节，INT4 权重每个参数约 0.5 字节。

2. **降低显存占用**  
   大模型可以部署到更少 GPU 或消费级显卡。

3. **降低内存带宽压力**  
   Decode 阶段常常是 memory-bound，权重和 KV Cache 变小可以提升吞吐。

4. **提升推理速度**  
   若硬件和 kernel 支持低精度矩阵乘，可显著加速。

5. **降低部署成本**  
   同样硬件上可服务更多并发请求。

6. **支持端侧和边缘部署**  
   手机、PC、嵌入式、边缘盒子可运行更大模型。

---

## 1.3 量化的主要代价

常见代价：

- 精度下降
- 生成质量下降
- 长上下文退化
- 数学/代码能力下降
- 小模型更敏感
- 多模态模型某些模块更敏感
- 低 bit 需要专用 kernel
- 不同硬件支持差异大
- 量化校准数据选择影响很大
- 推理引擎兼容性问题

---

## 1.4 量化误差来源

误差来源：

- 舍入误差
- 截断误差
- clipping 误差
- outlier 激活
- scale 估计不准
- group size 过大
- zero point 处理不当
- 激活分布漂移
- KV Cache 累积误差
- attention score 敏感
- normalization 数值敏感

# 4. 按量化粒度分类

## 4.1 Per-tensor Quantization

整个 tensor 共享一个 scale / zero point。

优点：

- 简单
- 开销小
- 部署容易

缺点：

- 对 outlier 敏感
- 精度可能较差

---

## 4.2 Per-channel Quantization

每个输出通道一个 scale。

常用于：

- Conv 权重
- Linear 权重
- 视觉模型
- INT8 推理

优点：

- 精度更好
- 通道差异可建模

---

## 4.3 Per-group / Groupwise Quantization

将权重按 group 分组，每组一个 scale。

常见于 LLM INT4：

- group size 32
- group size 64
- group size 128
- group size 256

优点：

- 平衡精度和元数据开销
- LLM 权重量化常用

---

## 4.4 Per-token Quantization

每个 token 的激活单独量化。

常用于：

- LLM 激活动态量化
- W8A8
- INT8 dynamic activation
- torchao int8 dynamic activation

优点：

- 适合激活动态变化
- 对 sequence 更灵活

---

## 4.5 Per-block / Blockwise Quantization

每个 block 一个 scale。

应用：

- FP8 block scaling
- MXFP8
- MXFP4
- GGUF block quantization
- blockwise INT4
- tensor core 友好格式

---

## 4.6 Per-head Quantization

每个 attention head 一个 scale。

应用：

- KV Cache 量化
- Attention 量化
- Multi-head sensitivity 不同的场景

---

## 4.7 Layerwise Quantization

每层单独选择量化策略。

方法：

- 敏感层保留高精度
- 非敏感层低 bit
- Layerwise bit allocation
- Mixed Precision Search
- Hessian-aware Layer Selection

---

# 5. 按量化映射方式分类

## 5.1 对称量化

公式：

```text
q = round(x / scale)
x_hat = q * scale
```

特点：

- zero_point = 0
- 硬件实现简单
- 权重量化常用
- 对分布近似对称的数据效果好

---

## 5.2 非对称量化

公式：

```text
q = round(x / scale + zero_point)
x_hat = scale * (q - zero_point)
```

特点：

- 能表示非零中心分布
- 激活量化常用
- 需要 zero point
- 硬件实现略复杂

---

## 5.3 均匀量化

特点：

- 量化间隔固定
- 最常见
- 便于硬件加速

---

## 5.4 非均匀量化

特点：

- 量化间隔不固定
- 可更贴合权重分布
- 硬件支持较复杂

方法：

- K-means Quantization
- Log Quantization
- Power-of-two Quantization
- Vector Quantization
- Product Quantization
- AQLM
- Codebook Quantization

---

## 5.5 随机量化

方法：

- Stochastic Rounding
- Randomized Quantization
- Probabilistic Quantization

用途：

- 低精度训练
- 减少系统性偏差
- 提高训练稳定性

---

# 6. 训练后量化 PTQ

## 6.1 PTQ 基础

PTQ = Post-Training Quantization，即训练完成后不重新训练或只用少量校准数据完成量化。

优点：

- 成本低
- 不需要训练全模型
- 快速部署
- 工程最常用

缺点：

- 极低 bit 精度可能下降明显
- 对校准数据敏感
- 小模型和复杂任务更难

---

## 6.2 Dynamic Quantization

特点：

- 权重提前量化
- 激活运行时动态量化
- 不需要校准数据或校准较少
- CPU 上常见

适用：

- RNN
- Transformer linear
- CPU 推理
- 中小模型部署

---

## 6.3 Static Quantization

特点：

- 权重和激活都提前确定 scale
- 需要校准数据
- 部署效率高
- 常用于 CNN / CV 模型

流程：

```text
准备模型
  ↓
插入 observer
  ↓
校准数据前向
  ↓
计算 scale / zero_point
  ↓
转换为量化模型
```

---

## 6.4 Weight-only Quantization

特点：

- 只量化权重
- 激活保持 FP16/BF16/FP32
- LLM 最常见
- 部署相对容易
- W4A16、W8A16 常见

代表：

- GPTQ
- AWQ
- bitsandbytes 4-bit
- GGUF
- torchao int4 weight-only
- TensorRT-LLM INT4 AWQ

---

## 6.5 Calibration

校准数据用于估计量化参数。

校准方法：

- MinMax Calibration
- Moving Average MinMax
- Histogram Calibration
- Entropy Calibration
- KL Divergence Calibration
- Percentile Calibration
- MSE Calibration
- SmoothQuant Calibration

- RAG prompt
- 代码数据
- 数学数据
- 多模态样本

---

## 6.6 Outlier 处理

LLM 激活中常存在 outlier，会影响 INT8/INT4 精度。

方法：

- Outlier Channel Splitting
- Outlier-aware Quantization

# 7. 量化感知训练 QAT

## 7.1 QAT 基础

QAT = Quantization-Aware Training，在训练阶段模拟量化误差，让模型适应低精度推理。

核心技术：

- Fake Quantization
- Observer
- Straight-through Estimator
- Learnable Scale
- Quantization Noise Injection

流程：

```text
原模型
  ↓
插入 fake quant
  ↓
训练 / 微调
  ↓
导出真实量化模型
```

---

## 7.2 Fake Quantization

训练时：

```text
FP32 参数 → fake quant → fake dequant → FP32 计算图
```

作用：

- 模拟量化误差
- 反向传播仍可训练
- 最终部署转换为真实 INT kernel

---

## 7.3 Straight-through Estimator

量化中的 round 不可导，STE 近似其梯度：

```text
forward: q = round(x)
backward: dq/dx ≈ 1
```

应用：

- Binary Network
- Ternary Network
- INT8 QAT
- INT4 QAT
- LSQ

---

## 7.4 LSQ

LSQ = Learned Step Size Quantization。

特点：

- 学习 scale
- 比固定 scale 更灵活
- 适合低 bit 量化
- 常用于 QAT 研究

---

## 7.5 PACT

PACT = Parameterized Clipping Activation。

特点：

- 学习激活 clipping 阈值
- 控制激活范围
- 提高低 bit 激活量化效果

---

## 7.6 LLM QAT

大模型 QAT 难点：

- 训练成本高
- 分布式复杂
- 低 bit 梯度不稳定
- 需要高质量数据
- 容易遗忘

方法：

- LoRA + QAT
- QLoRA-style Fine-tuning
- Int8 Activation + Int4 Weight QAT
- torchao QAT Linear
- Fine-tune Quantized Model
- Knowledge Distillation QAT
- Mixed Precision QAT

---

## 8.5 SmoothQuant

X' = X / s
W' = sW
Y = X'W'

# 10. KV Cache 量化

## 10.1 KV Cache 为什么重要

在自回归推理中，KV Cache 大小随上下文长度线性增长：

```text
KV Cache ∝ batch × layers × heads × seq_len × head_dim × dtype
```

长上下文场景下，KV Cache 可能比模型权重更限制并发。

# 23. 常见问题与排查

## 23.1 量化后质量下降明显

可能原因：

- bit 太低
- group size 太大
- 校准数据不匹配
- 敏感层被量化
- outlier 未处理
- tokenizer / chat template 错误
- 推理后端不兼容
- KV Cache 量化误差大
- 长上下文任务未评估

处理：

- 提高 bit
- 减小 group size
- 更换校准数据
- 保留敏感层高精度
- 使用 AWQ / SmoothQuant
- 做业务回归
- 单层误差分析
- 尝试 QAT

---

## 23.2 量化后速度没变快

可能原因：

- 没有低精度 kernel
- 量化只是压缩存储，计算时反量化
- batch 太小
- CPU/GPU 后端不支持
- memory-bound 与 compute-bound 不同
- 数据拷贝开销大
- 推理引擎没有启用对应后端

处理：

- 确认 kernel 支持
- 使用 TensorRT-LLM / vLLM / llama.cpp 对应格式
- 压测不同 batch
- 使用 profiling
- 检查是否真正 int4/int8 GEMM
- 避免频繁 dequant

---

## 23.3 量化模型无法加载

可能原因：

- transformers 版本不匹配
- quantization_config 缺失
- tokenizer 不匹配
- safetensors / GGUF 格式错误
- 推理引擎不支持该量化格式
- GPU 架构不支持该 kernel
- group size 不支持
- act-order 不兼容

---

## 23.4 低 bit 量化长上下文退化

可能原因：

- KV Cache 精度不足
- attention 层敏感
- RoPE 扩展误差
- 低 bit 权重影响 retrieval
- 校准数据没有长上下文

处理：

- 使用更高 bit KV
- 长上下文校准
- 保留 attention 高精度
- 使用 LongBench / Needle 测试
- 调整 KV quant scheme

---

# 27. 总结

人工智能模型量化技术可以概括为以下大类：

1. **数值格式**：FP32、BF16、FP16、FP8、FP4、INT8、INT4、INT2、Binary、Ternary  
2. **量化对象**：权重、激活、KV Cache、梯度、优化器状态、Embedding、Attention、MLP  
3. **量化粒度**：Per-tensor、Per-channel、Per-group、Per-token、Per-block、Layerwise  
4. **量化映射**：对称、非对称、均匀、非均匀、随机量化、定点量化  
5. **训练后量化 PTQ**：Dynamic、Static、Weight-only、Calibration、Outlier 处理  
6. **量化感知训练 QAT**：Fake Quant、STE、LSQ、PACT、INT8/INT4 QAT、LLM QAT  
7. **LLM 专用量化**：LLM.int8、bitsandbytes、NF4、QLoRA、GPTQ、AWQ、SmoothQuant、HQQ、AQLM、GGUF  
8. **KV Cache 量化**：FP8/INT8/INT4 KV、Paged KV、KV Compression、长上下文优化  
9. **低精度训练**：FP16、BF16、FP8、AMP、Loss Scaling、8-bit Optimizer、1-bit Gradient  
10. **量化 + 稀疏**：SparseGPT、Wanda、2:4 Sparsity、Sparse Quantization  
11. **领域模型量化**：视觉、语音、扩散、推荐、搜索、Embedding、多模态模型量化  
12. **工具链**：PyTorch、torchao、Transformers、PEFT、bitsandbytes、AutoGPTQ、AutoAWQ、llama.cpp、TensorRT-LLM、ONNX Runtime、TFLite、OpenVINO  
13. **硬件后端**：NVIDIA、AMD、Intel、Apple、ARM、移动端 NPU、边缘 AI 芯片  
14. **评测体系**：PPL、KL、SQNR、MMLU、GSM8K、HumanEval、LongBench、业务指标、延迟和显存  
15. **工程流程**：校准、量化、能力回归、性能压测、灰度上线、监控和回滚  

一句话总结：

> 模型量化的本质是：在可接受的精度损失范围内，用更少的 bit 表示模型与中间状态，从而把模型部署到更便宜、更小、更快、更低功耗的硬件环境中。
