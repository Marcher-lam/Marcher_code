# 大模型强化学习算法分类总表

> 说明：这里的“大模型强化学习算法”主要指用于大语言模型（LLM）、多模态大模型（MLLM/VLM）、推理模型、Agent 模型在预训练之后进行行为优化、偏好对齐、推理增强、工具使用训练、长程任务训练的一类算法与训练范式。  
> 它并不只包括传统 RL 中的 PPO、Actor-Critic，也包括当前大模型后训练中常见的偏好优化、奖励模型、可验证奖励、Agentic RL、RLHF/RLAIF 等方法。

---

## 0. 总体分类框架

大模型强化学习算法可以从 8 个维度理解：

1. **反馈来源**
   - 人类反馈：RLHF
   - AI 反馈：RLAIF
   - 宪法/规则反馈：Constitutional AI
   - 工具/环境反馈：Tool / Environment Feedback
   - 可验证反馈：RLVR
   - 自动评测器反馈：Judge / Reward Model / Critic

2. **是否显式训练奖励模型**
   - 显式奖励模型类：Reward Model + PPO / GRPO / REINFORCE
   - 无显式奖励模型类：DPO / IPO / KTO / ORPO / SimPO 等
   - 混合类：Reward Model + Preference Optimization

3. **训练数据形式**
   - 偏好对：chosen / rejected
   - 排序列表：ranked responses
   - 标量奖励：reward score
   - 过程奖励：step-level reward
   - 结果奖励：outcome reward
   - 环境轨迹：trajectory / rollout
   - 工具调用轨迹：tool-use traces
   - 多模态轨迹：image / video / audio + action + text

4. **优化对象**
   - 回答偏好对齐
   - 安全对齐
   - 推理能力增强
   - 数学/代码能力增强
   - 工具调用能力增强
   - Agent 长程任务能力增强
   - 多模态理解与生成能力增强
   - 检索、搜索、网页操作能力增强

5. **RL 更新方式**
   - On-policy RL
   - Off-policy RL
   - Offline preference optimization
   - Online preference optimization
   - Rejection sampling / Best-of-N
   - Expert iteration / Self-play / Self-improvement
   - Curriculum RL
   - Multi-agent RL

6. **是否需要 Critic**
   - Actor-Critic 类：PPO、A2C/A3C、TRPO 等
   - Critic-free 类：REINFORCE、REINFORCE++、RLOO、GRPO 等
   - Preference-only 类：DPO、IPO、ORPO、KTO、SimPO 等

7. **奖励粒度**
   - Token-level
   - Sentence-level
   - Step-level
   - Turn-level
   - Trajectory-level
   - Episode-level
   - Task-level
   - Multi-objective reward

8. **模型形态**
   - LLM
   - VLM / MLLM
   - Diffusion Model
   - Speech LLM
   - Embodied Agent
   - Web Agent
   - Code Agent
   - Multi-agent System

# 1. 经典 RLHF 类算法

## 1.1 RLHF：Reinforcement Learning from Human Feedback

**中文名**：基于人类反馈的强化学习  
**核心思想**：先用人类偏好数据训练奖励模型，再用强化学习优化大模型，使模型输出更符合人类偏好。

典型流程：

1. 预训练模型
2. 指令微调 SFT
3. 收集人类偏好数据
4. 训练奖励模型 Reward Model
5. 使用 RL 算法优化策略模型
6. 加入 KL 惩罚，避免模型偏离参考模型过远

常见组成：

- SFT Model
- Reward Model
- Policy Model
- Reference Model
- KL Penalty
- PPO / GRPO / REINFORCE / RLOO

适用场景：

- ChatGPT 类对话模型
- 安全对齐
- 有帮助性、有害性、真实性优化
- 复杂主观偏好优化

---

## 1.2 PPO-RLHF

**中文名**：基于近端策略优化的 RLHF  
**英文名**：Proximal Policy Optimization for RLHF

**核心思想**：使用 PPO 的 clipped objective 限制策略更新幅度，避免大模型后训练不稳定。

关键组成：

- Policy loss
- Value loss
- Entropy bonus
- KL penalty
- Reward normalization
- Advantage estimation
- Generalized Advantage Estimation（GAE）

优点：

- 稳定性较好
- 是早期 RLHF 的主流方案
- 适合奖励模型输出连续标量奖励的场景

缺点：

- 训练复杂
- 需要 Actor + Critic
- 显存和工程成本高
- 对超参数敏感
- 容易 reward hacking

---

## 1.3 PPO-ptx

**中文名**：带预训练混合损失的 PPO  
**核心思想**：在 PPO 强化学习时混入预训练语言建模损失，降低灾难性遗忘。

适用场景：

- 对话模型对齐
- 保持语言能力
- 降低模型胡言乱语和格式退化

---

## 1.4 TRPO-RLHF

**英文名**：Trust Region Policy Optimization  
**中文名**：信赖域策略优化

特点：

- 通过 KL 约束限制策略更新范围
- 理论稳定性强
- 工程实现复杂

在大模型中使用较少，但 PPO 可以看作 TRPO 的简化工程版本。

---

## 1.5 A2C / A3C / Actor-Critic RLHF

**中文名**：行动器-评论器方法  
**核心思想**：Actor 产生文本策略，Critic 估计价值函数。

适用场景：

- 理论研究
- 小规模语言环境
- 交互式任务

在大模型后训练中，通常被 PPO、GRPO、RLOO 等替代。

---

# 2. Critic-Free 强化学习算法

## 2.1 REINFORCE

**中文名**：蒙特卡洛策略梯度  
**核心思想**：直接使用整段输出的奖励估计策略梯度，不训练价值函数。

优点：

- 简单
- 不需要 Critic
- 容易实现

缺点：

- 方差大
- 样本效率低
- 对奖励归一化敏感

适用场景：

- 小规模任务
- 可验证奖励任务
- 数学、代码、选择题等有明确最终奖励的任务

---

## 2.2 REINFORCE with Baseline

**中文名**：带基线的 REINFORCE  
**核心思想**：引入 baseline 降低梯度估计方差。

常见 baseline：

- 平均奖励
- 批内平均奖励
- Moving average reward
- Value function baseline
- Group baseline

---

## 2.3 RLOO

**英文名**：Reinforcement Learning with Leave-One-Out Baseline  
**中文名**：留一基线强化学习

**核心思想**：对同一 prompt 采样多个回答，用其他回答的平均奖励作为当前回答的 baseline。

特点：

- 不需要 Critic
- 适合 LLM 多样本采样
- 比普通 REINFORCE 方差更低

适用场景：

- 数学推理
- 代码生成
- 可验证奖励任务
- 轻量级 RLHF

---

## 2.4 REINFORCE++

**中文名**：增强版 REINFORCE  
**核心思想**：在 REINFORCE 基础上加入奖励归一化、KL 控制、长度归一化、批内 baseline、clip 等技巧。

常见改进：

- Advantage normalization
- Reward whitening
- KL penalty
- Token-level loss masking
- Length normalization
- Ratio clipping
- Group baseline

适用场景：

- 无 Critic 大模型 RL
- 数学推理模型训练
- 代码模型训练

---

## 2.5 GRPO

**英文名**：Group Relative Policy Optimization  
**中文名**：组相对策略优化

**核心思想**：对同一问题采样一组回答，用组内奖励均值或相对奖励构造 advantage，不需要单独训练 Critic。

典型流程：

1. 对同一 prompt 采样多个输出
2. 用奖励模型或验证器打分
3. 计算组内相对优势
4. 使用类似 PPO 的 clipped policy objective 更新模型
5. 加入 KL 正则约束参考模型

优点：

- 不需要 Critic
- 显存压力低于 PPO
- 适合推理模型训练
- 适合数学、代码等可验证任务

缺点：

- 需要多样本采样
- 对 reward 设计敏感
- 如果组内样本质量都很差，信号可能弱

适用场景：

- 数学推理
- 代码推理
- 长链路 CoT 推理
- RLVR
- DeepSeek-R1 类训练范式

---

## 2.6 Dr. GRPO / DAPO / GSPO / GPG / GPRS 等 GRPO 变体

这些属于 GRPO 或 group-based policy optimization 的扩展方向。

常见改进方向：

- 更稳定的 group advantage
- 更好的长度归一化
- 更合理的 KL 控制
- 去除或弱化 reference model
- 对长 CoT 推理进行稳定优化
- 对稀疏奖励进行方差控制
- 对多轮 Agent 轨迹进行组相对优化

适用场景：

- 长推理模型
- 多轮工具调用
- Web Agent
- Code Agent
- 复杂环境交互任务

---

# 3. 直接偏好优化类算法

这一类方法通常不显式训练奖励模型，也不跑传统在线 RL，而是把偏好数据直接转化为监督式目标。严格说它们常被称为“偏好优化”或“RLHF 替代算法”，但本质上来源于 RLHF 目标的重写，因此通常归入大模型强化学习/对齐算法体系。

---

## 3.1 DPO

**英文名**：Direct Preference Optimization  
**中文名**：直接偏好优化

**核心思想**：不训练奖励模型，不使用 PPO，而是直接用偏好对优化策略，使 chosen 输出概率高于 rejected 输出。

优点：

- 简单稳定
- 工程成本低
- 不需要奖励模型
- 不需要在线采样
- 常作为 RLHF 替代方案

缺点：

- 依赖偏好数据质量
- 对分布外任务提升有限
- 不像在线 RL 那样能探索新策略

适用场景：

- 对话模型偏好对齐
- 安全对齐
- 代码偏好优化
- 总结、翻译、问答风格优化

---

## 3.2 IPO

**英文名**：Identity Preference Optimization  
**中文名**：身份偏好优化 / 恒等偏好优化

**核心思想**：针对 DPO 中偏好过强、过拟合等问题进行目标函数修正，使优化更稳定。

适用场景：

- 偏好数据噪声较大
- DPO 训练不稳定
- 需要更平滑偏好目标

---

## 3.3 KTO

**英文名**：Kahneman-Tversky Optimization  
**中文名**：卡尼曼-特沃斯基优化

**核心思想**：不要求成对偏好数据，可以使用“好/坏”单样本反馈，借鉴前景理论对人类偏好进行建模。

优点：

- 数据要求低于 DPO
- 可使用二元标签
- 适合偏好数据稀缺场景

适用场景：

- 安全数据
- 内容质量过滤
- 单样本好坏标注
- 人工审核数据复用

---

## 3.4 ORPO

**英文名**：Odds Ratio Preference Optimization  
**中文名**：赔率比偏好优化

**核心思想**：将 SFT 和偏好优化合并到一个目标中，通过 odds ratio 增强 chosen 与 rejected 的区分。

优点：

- 不需要参考模型
- 训练流程简单
- 可将监督学习与偏好学习结合

适用场景：

- 轻量对齐
- 中小模型后训练
- 指令模型偏好增强

---

## 3.5 CPO

**英文名**：Contrastive Preference Optimization  
**中文名**：对比偏好优化

**核心思想**：通过对比 chosen 与 rejected 输出优化模型偏好。

适用场景：

- 对比式偏好数据
- 多候选回答排序
- 简化版偏好对齐

---

## 3.6 SimPO

**英文名**：Simple Preference Optimization  
**中文名**：简单偏好优化

**核心思想**：使用参考模型无关的 reward margin 目标，简化 DPO 类训练。

优点：

- 不需要 reference model
- 工程简单
- 成本较低

适用场景：

- 资源受限训练
- 快速偏好对齐
- 中小模型调优

---

## 3.7 RRHF

**英文名**：Rank Responses to Align Human Feedback  
**中文名**：排序响应对齐

**核心思想**：使用多个候选回答的排序信息训练模型，而不仅仅是二元 chosen/rejected。

适用场景：

- 多候选排序数据
- 人工排序数据
- Reward model 蒸馏

---

## 3.8 SLiC-HF

**英文名**：Sequence Likelihood Calibration with Human Feedback  
**中文名**：基于人类反馈的序列似然校准

**核心思想**：通过偏好对约束模型输出似然，使高质量回答概率更高。

---

## 3.9 PRO

**英文名**：Preference Ranking Optimization  
**中文名**：偏好排序优化

**核心思想**：使用排序学习思想进行偏好对齐。

---

## 3.10 BCO

**英文名**：Binary Classifier Optimization  
**中文名**：二分类器优化

**核心思想**：将偏好对齐转化为二分类器或判别目标。

---

## 3.11 NCA / AOT / APO / SPPO 等偏好优化变体

常见方向：

- 更稳定的 preference loss
- 更好的排序建模
- Reference-free 优化
- 多负样本偏好优化
- Distributional preference optimization
- Pairwise / Listwise preference optimization
- 多目标偏好优化

# 4. AI 反馈与宪法反馈类算法

## 4.1 RLAIF

**英文名**：Reinforcement Learning from AI Feedback  
**中文名**：基于 AI 反馈的强化学习

**核心思想**：用 AI 模型代替人类标注者，对回答进行评分、比较或生成偏好标签，再进行 RL 或偏好优化。

优点：

- 成本低
- 可扩展
- 反馈速度快
- 适合大规模数据生成

缺点：

- 可能继承 AI 评审模型偏见
- 评审模型错误会放大
- 容易形成自我强化偏差

适用场景：

- 安全对齐
- 大规模偏好数据构造
- 多轮对话评估
- 自动红队
- 自动数据筛选

---

## 4.2 Constitutional AI

**中文名**：宪法式 AI / 基于原则的 AI 对齐

**核心思想**：用一组自然语言规则、原则或宪法指导模型自我批判、自我修正，并结合 AI 反馈进行偏好训练。

典型流程：

1. 模型生成回答
2. 根据宪法原则进行自我批判
3. 生成修订回答
4. AI 偏好模型比较原始回答和修订回答
5. 用 RLAIF 或偏好优化训练模型

适用场景：

- 安全对齐
- 价值观约束
- 减少有害输出
- 政策合规
- 企业定制规范

---

## 4.3 Self-Rewarding Language Models

**中文名**：自奖励语言模型

**核心思想**：模型同时扮演生成器和评审器，通过自我打分或自我比较构造奖励信号。

适用场景：

- 数据稀缺场景
- 自我改进
- 自动偏好数据生成

风险：

- 奖励偏差
- 模型自嗨
- 评审能力不足导致错误强化

---

## 4.4 LLM-as-a-Judge RL

**中文名**：大模型评审器强化学习

**核心思想**：使用强模型作为 Judge，对候选回答进行评分或排序，再用 RL 或偏好优化训练目标模型。

适用场景：

- 开放式问答
- 写作
- 摘要
- 对话质量
- 多轮 Agent 任务

常见问题：

- Judge bias
- 位置偏差
- 长度偏差
- 风格偏差
- Reward hacking

---

# 5. 可验证奖励强化学习 RLVR

## 5.1 RLVR

**英文名**：Reinforcement Learning with Verifiable Rewards  
**中文名**：基于可验证奖励的强化学习

**核心思想**：不用主观奖励模型，而是使用可自动验证的客观信号作为奖励，例如数学答案是否正确、代码测试是否通过、格式是否满足约束。

典型奖励来源：

- 数学最终答案匹配
- 代码单元测试通过率
- 形式化证明验证
- 选择题正确率
- SQL 执行结果正确性
- JSON Schema 校验
- 编译是否成功
- 工具执行结果是否正确
- 检索答案是否命中证据

适用场景：

- 数学推理
- 代码生成
- 数据分析
- 形式化证明
- 工具调用
- Web 自动化
- 科学计算

---

## 5.2 Outcome Reward RL

**中文名**：结果奖励强化学习

**核心思想**：只根据最终答案是否正确给奖励。

优点：

- 简单客观
- 不需要过程标注
- 易扩展

缺点：

- 奖励稀疏
- 不知道中间推理哪里错
- 训练难度较高

适用场景：

- 数学最终答案
- 代码测试
- 游戏胜负
- 任务完成状态

---

## 5.3 Process Reward RL

**中文名**：过程奖励强化学习

**核心思想**：对中间推理步骤进行打分或验证，而不仅仅看最终答案。

相关模型：

- Process Reward Model（PRM）
- Step-wise Verifier
- Critic Model
- Reasoning Judge

优点：

- 奖励更密集
- 有助于长链推理
- 能指导模型修正中间步骤

缺点：

- 标注成本高
- 过程正确性难定义
- 可能惩罚不同但有效的推理路径

适用场景：

- 数学证明
- 复杂推理
- 多步代码生成
- 科学问题求解

---

## 5.4 Outcome Reward Model（ORM）

**中文名**：结果奖励模型  
**核心思想**：只判断最终输出好坏或最终答案正确性。

---

## 5.5 Process Reward Model（PRM）

**中文名**：过程奖励模型  
**核心思想**：对每一步推理过程进行评价。

---

## 5.6 Verifier-Guided RL

**中文名**：验证器引导强化学习

**核心思想**：使用外部验证器、测试器、解释器、编译器、数学检查器、形式化证明器作为奖励源。

典型验证器：

- Python interpreter
- Unit tests
- Compiler
- Theorem prover
- Calculator
- SQL engine
- Browser environment
- Game simulator
- Robotics simulator

---

# 6. 推理模型强化学习算法

## 6.1 Chain-of-Thought RL

**中文名**：思维链强化学习

**核心思想**：对模型的长推理过程进行强化学习，使其学会搜索、反思、分解和验证。

适用场景：

- 数学
- 逻辑推理
- 代码
- 复杂问答
- 多步规划

---

## 6.2 Long-CoT RL

**中文名**：长思维链强化学习

**核心思想**：鼓励模型生成更长、更结构化、更可验证的推理轨迹。

常见奖励：

- 答案正确性
- 推理格式
- 步骤一致性
- 自我检查
- 工具验证结果
- 过短惩罚或长度控制

风险：

- 过度冗长
- 伪推理
- 奖励黑客
- 训练成本高

---

## 6.3 Self-Consistency RL

**中文名**：自一致性强化学习

**核心思想**：对同一问题生成多个推理路径，奖励与多数一致且正确的回答。

---

## 6.4 Self-Reflection RL

**中文名**：自反思强化学习

**核心思想**：模型先生成答案，再进行反思、纠错、修订，并根据修订结果或验证结果进行强化学习。

---

## 6.5 Tree-of-Thought RL

**中文名**：思维树强化学习

# 9. 奖励模型与评估模型训练算法

## 9.1 Reward Modeling

**中文名**：奖励模型训练

**核心思想**：用人类或 AI 偏好数据训练一个模型，对输出质量给分。

常见输入：

- prompt + chosen + rejected
- multi-turn conversation
- image + text answer
- tool trajectory
- reasoning steps

输出形式：

- scalar reward
- pairwise preference
- listwise ranking
- token-level reward
- step-level reward

**中文名**：成对奖励模型

训练数据：

- chosen response
- rejected response

损失函数：

- Bradley-Terry loss
- Pairwise ranking loss
- Logistic preference loss

## 9.3 Listwise Reward Model

**中文名**：列表排序奖励模型

- 对多个候选回答进行整体排序

## 9.4 Scalar Reward Model

## 9.5 Generative Reward Model

**中文名**：生成式奖励模型

核心思想：

- 不只输出分数，而是生成评价、理由、批注、比较结论

- LLM-as-judge
- 自动偏好标注
- 过程反馈
- 复杂任务评估

## 9.6 Critic Model

**中文名**：评论器模型 / 价值模型

- 估计当前状态或轨迹的未来价值
- Actor-Critic、PPO 中常见

---

## 9.7 Verifier Model

**中文名**：验证器模型

类型：

- Outcome verifier

- Step verifier

## 9.8 Debate / Critique Reward Model

**中文名**：辩论式 / 批判式奖励模型

# 10. 在线偏好优化与主动反馈算法

## 10.1 Online DPO

**中文名**：在线直接偏好优化

**核心思想**：训练过程中实时采样模型输出，并用人类、AI Judge 或奖励模型生成偏好，再进行 DPO 更新。

优点：

- 比离线 DPO 更贴近当前模型分布
- 可以持续改进
- 避免偏好数据过时

---

## 10.2 Online RLHF

**中文名**：在线 RLHF

**核心思想**：模型训练过程中持续收集偏好反馈或奖励反馈。

适用场景：

- 产品在线对齐
- 用户反馈学习
- 动态偏好更新
- 个性化助手

---

## 10.3 Active Preference Learning

**中文名**：主动偏好学习

**核心思想**：模型主动选择最有价值的样本请求人类或 AI 标注。

常见策略：

- 不确定性采样
- 分歧采样
- 代表性采样
- 难例挖掘
- 多样性采样

---

## 10.4 Rejection Sampling Fine-tuning

**中文名**：拒绝采样微调

**核心思想**：从模型采样多个候选，保留奖励高的样本进行 SFT。

优点：

- 简单
- 稳定
- 可与 RL 结合

适用场景：

- 数学
- 代码
- 对话
- 数据合成

---

## 10.5 Best-of-N / BoN Training

**中文名**：多候选择优训练

**核心思想**：每个 prompt 生成 N 个候选，用奖励模型或验证器选最优样本。

---

## 10.6 Iterative Preference Optimization

**中文名**：迭代偏好优化

流程：

1. 当前模型采样
2. 奖励模型/Judge 评分
3. 构造偏好数据
4. DPO/ORPO/KTO/SFT 更新
5. 重复迭代

---

# 20. 一句话总览

大模型强化学习算法可以粗略分为：

1. **经典 RLHF 类**：Reward Model + PPO/GRPO/REINFORCE  
2. **偏好优化类**：DPO、IPO、KTO、ORPO、SimPO  
3. **AI 反馈类**：RLAIF、Constitutional AI、LLM-as-Judge  
4. **可验证奖励类**：RLVR、ORM、PRM、Verifier-guided RL  
5. **推理增强类**：Long-CoT RL、MCTS、Self-consistency、Expert Iteration  
6. **Agentic RL 类**：工具调用、网页操作、代码 Agent、GUI Agent、具身智能体  
7. **多模态 RL 类**：VLM-RLHF、Visual RLVR、Diffusion RLHF、Vision-Language-Action RL  
8. **安全与多目标类**：Safe RLHF、Constrained RLHF、Multi-objective RLHF  
9. **工程稳定化类**：KL 正则、奖励归一化、优势归一化、长度控制、分布式 RLHF

# 22. 使用建议

- 如果只是做企业私有模型对齐，优先考虑：**SFT + DPO/ORPO/KTO/SimPO**。
- 如果做数学、代码、推理模型，优先考虑：**RLVR + GRPO/RLOO/REINFORCE++**。
- 如果有高质量人类偏好数据和工程资源，可以考虑：**Reward Model + PPO/GRPO**。
- 如果做工具调用或 Agent，重点关注：**Agentic RL + Tool-use RL + Verifier-guided RL**。
- 如果做多模态模型，重点关注：**VLM-RLHF、Visual RLVR、Diffusion RLHF**。
- 如果做安全对齐，重点关注：**Constitutional AI、RLAIF、Safe RLHF、Multi-objective RLHF**。
