# 强化学习推理训练 学习文档

> 通过自动奖励信号（而非人类偏好）训练LLM的推理能力。

> 来源线索：本节内容根据原书中关于"reinforcement learning for reasoning"的第1章1.5节整理、扩展与教学化改写。

## 1. 算法基础认知

### 一句话定义
强化学习推理训练使用数学/逻辑可验证的奖励来训练LLM自主发展推理能力。

### 直觉类比
你给一个棋手设定规则："赢了这盘棋加1分"，然后让他跟自己对弈成千上万次。不需要人类教练，他自己就能从胜负结果中学到越来越好的走棋策略。RL训练推理模型也一样——用"答案是否正确"作为自动奖励信号。

### 历史背景
2025年1月，DeepSeek-R1 技术报告揭示了一个重要发现：即使不使用人类标注的推理链数据，仅通过强化学习+可验证奖励，模型也能自主涌现推理行为。OpenAI 的 o1 系列被认为使用了类似方法。DeepSeek-R1 采用了"冷启动 SFT → RL(GRPO) → 再SFT → 再RL"的多阶段训练策略。

### 算法定位
- **类型**：强化学习 / 推理训练 / 后训练方法
- **性质**：需要自动奖励信号，修改模型权重

### 前置知识
- 理解 RLHF/PPO 的基本概念
- 了解 CoT 推理是什么
- 基础强化学习概念（奖励、策略梯度）

## 2. 核心原理

### 核心思想
与 RLHF 不同，RL 推理训练使用的是**可自动验证的奖励信号**而非人类偏好判断。这绕过了昂贵的人类标注，使得大规模 RL 训练变得可行。核心理念是：如果奖励信号（如数学答案是否正确）是可靠且自动可得的，模型可以通过大量试错来自主改进推理能力。

### 工作流程
1. 准备一个能产生自动验证奖励的任务集（如数学题、编程题）
2. 模型为每个问题生成推理链+答案
3. 自动验证器判断答案是否正确，给出奖励 $r \in \{0,1\}$ 或连续分数
4. 使用 RL 算法（PPO/GRPO）根据奖励信号更新模型
5. 模型逐渐学会：好的推理链 → 正确答案 → 高奖励

### 关键概念解释
- **可验证奖励**：答案的正确性可以被自动判断的奖励信号。数学=计算结果匹配，编程=通过测试用例
- **GRPO (Group Relative Policy Optimization)**：DeepSeek-R1 使用的 RL 算法，是 PPO 的变体。对同一个 prompt 生成一组回答，用组内相对排名计算优势（而非依赖价值函数）
- **冷启动 SFT**：在 RL 之前先用少量高质量推理数据做 SFT，让模型学会推理格式，加速 RL 的收敛
- **过程奖励模型 (PRM)**：不仅奖励最终答案的正确性，也奖励中间推理步骤的合理性

### 直观解释
```
RLHF（偏好优化）:
标注者: "回复A比回复B更好"  ← 主观判断
模型学习: 什么样的回答"更讨人喜欢"

RL推理训练:
验证器: "答案=42，正确!"  ← 客观可验证
模型学习: 什么样的推理过程能导出正确答案
```

## 3. 数学公式与推导

### 符号约定
| 符号 | 含义 |
|------|------|
| $\pi_\theta$ | 策略（推理模型），参数 $\theta$ |
| $x$ | 输入问题 |
| $y$ | 生成的推理链+答案 |
| $r(x, y)$ | 奖励信号（0/1或连续值） |
| $G$ | GRPO中的一组采样 |
| $\pi_{\text{ref}}$ | 参考策略（如 SFT 模型） |

### GRPO 核心公式

对每个问题 $x$，采样一组 $N$ 个回答 $\{y_1, ..., y_N\}$：

1. 计算组内奖励的均值和标准差：
   $$\mu = \frac{1}{|G|} \sum_{y \in G} r(x, y), \quad \sigma = \sqrt{\frac{1}{|G|} \sum_{y \in G} (r(x, y) - \mu)^2}$$

2. 使用组内相对排名作为优势：
   $$A_i = \frac{r(x, y_i) - \mu}{\sigma}$$

这比PPO的优势估计更简单——不需要价值网络！

3. GRPO的优化目标：
   $$\mathcal{L}_{\text{GRPO}}(\theta) = -\frac{1}{|G|} \sum_{i} \left[\min\left(\rho_i A_i, \text{clip}(\rho_i, 1-\epsilon, 1+\epsilon) A_i\right) - \beta \cdot \text{KL}(\pi_\theta \| \pi_{\text{ref}})\right]$$

   其中 $\rho_i = \frac{\pi_\theta(y_i|x)}{\pi_{\text{old}}(y_i|x)}$ 是策略比率。

### 与标准PPO的关键区别

| 方面 | PPO (RLHF) | GRPO (DeepSeek-R1) |
|------|------------|---------------------|
| 优势估计 | 需要价值函数 V(s) | 组内标准化奖励 |
| 奖励来源 | RM (人类偏好) | 自动验证器 |
| 计算开销 | 额外一个价值网络 | 无额外网络 |
| 数学直觉 | 这个动作比平均好多少 | 这个回答比组内其他回答好多少 |

### 推理RL训练的奖励设计

最常见的奖励结构（DeepSeek-R1）：

$$r(x, y) = \begin{cases} 1 & \text{如果最终答案正确} \\ 0 & \text{否则} \end{cases}$$

加上格式奖励：

$$r_{\text{total}}(x, y) = r_{\text{correctness}}(x, y) + \lambda \cdot r_{\text{format}}(y)$$

其中格式奖励检查模型是否正确使用了 `thinking` / `response` 标签。

## 4. 训练过程讲解

### 数据预处理
- 准备可自动验证的问题集（数学题、代码题等）
- 不需要人工标注——这是关键优势
- 问题难度应适中：模型不能全对（没法学习）也不能全错（无法探索到正确路径）

### 训练流程 (DeepSeek-R1 路由)
1. **冷启动 SFT** (需少量数据, ~数千条)：用推理格式数据微调
2. **RL (GRPO)**：用可验证奖励训练推理能力
3. **Rejection Sampling + SFT**：用RL模型拒绝采样生成更多高质量数据，再次SFT微调
4. **再RL**：在更大的SFT模型上再做一轮RL

### 迭代过程（RL阶段）
1. 采样一个 batch 的问题
2. 每个问题生成 N 个候选回答（如 N=16）
3. 验证器为每个回答打分
4. 计算 GRPO 损失（组内标准化 + PPO clip + KL 惩罚）
5. 反向传播更新模型

### 关键超参数
| 参数 | 作用 | 推荐范围 | 默认建议 |
|------|------|----------|----------|
| N (组大小) | GRPO每问题采样数 | 8 ~ 64 | 16 |
| $\epsilon$ (clip) | PPO裁剪范围 | 0.1 ~ 0.3 | 0.2 |
| $\beta$ (KL系数) | 限制偏离参考策略 | 0.001 ~ 0.04 | 0.001 |
| learning_rate | RL阶段学习率 | 1e-7 ~ 1e-5 | 1e-6 |
| max_new_tokens | 推理+回答最大长度 | 2048 ~ 16384 | 4096 |

## 5. 应用场景

### 典型应用
1. **数学问题求解**：答案可精确验证，是最适合RL训练的域。DeepSeek-R1在MATH等基准上取得显著提升。
2. **代码生成与调试**：能否通过测试用例是天然的、自动的奖励信号。适用于编程竞赛和算法题。
3. **逻辑推理与规划**：推理过程的每一步都有可验证的约束或正确性标准。
4. **科学推理**：物理/化学问题有唯一答案，可自动验证。
5. **工具调用与Agent规划**：任务是否成功完成是可观察的奖励信号。

### 适用数据特征
- 任务有明确的、自动可验证的对错标准
- 模型在任务上已有基本能力但不稳定（单次正确率30-70%）
- 能够承受RL训练的计算成本

### 不适用场景
- 完全开放式生成（没有对错标准）
- 模型对该任务完全没有能力（RL无法从零创造能力）
- 奖励信号稀疏或有噪声（需要过程奖励或更复杂的奖励设计）

## 6. 优缺点分析

### 优点
| 优点 | 说明 | 成立条件 |
|------|------|----------|
| 不需要人类标注 | 自动奖励使大规模训练可行 | 有可验证的奖励定义 |
| 超越模仿 | 不受限于示范数据质量，可探索更优策略 | 奖励信号正确且无漏洞 |
| 涌现行为 | 模型可能自发产生未明确训练的推理模式（如DeepSeek-R1的"啊哈时刻"） | 模型有足够容量 |
| 可扩展 | 理论上生成越多的在线数据，效果越好 | 有足够的计算资源 |

### 缺点
| 缺点 | 说明 | 缓解思路 |
|------|------|----------|
| 训练极不稳定 | RL训练LLM比SFT更易崩溃 | GRPO（更稳）、仔细监控KL |
| 奖励信号稀疏 | 只有最终答案有奖励，中间步骤无反馈 | 过程奖励模型(PRM) |
| 语言质量退化 | 在追求正确性的过程中可能失去流畅性 | KL惩罚+格式奖励 |
| 奖励漏洞 | 模型可能找出不诚信但"有效"的策略 | 奖励沙盒设计+多样化验证 |
| 硬件要求高 | 需要大量GPU进行多轮生成和训练 | 从冷启动SFT开始减少RL步数 |

### 与同类方法对比
| 方法 | 训练方式 | 奖励来源 | 稳定性 | 效果上限 |
|------|----------|----------|--------|----------|
| 推理RL (GRPO) | RL | 自动验证 | 中 | 最高 |
| 推理SFT | 监督 | 标注演示 | 高 | 中-高 |
| 推理时扩展(Best-of-N) | 不训练 | 自动验证(推理时) | 最高 | 高(成本高) |
| RLHF | RL | 人类偏好 | 中-低 | 中(偏好非准确) |

## 7. 调库实现

```python
"""
强化学习推理训练的调库实现
展示 GRPO (Group Relative Policy Optimization) 的核心流程
"""

import torch
from transformers import AutoModelForCausalLM, AutoTokenizer
import numpy as np
from typing import List, Tuple


class MathVerifier:
    """数学答案的自动验证器"""

    def __init__(self):
        # 存储问题ID到正确答案的映射
        self.answers = {}

    def add_problem(self, problem_id: str, answer: str):
        self.answers[problem_id] = answer

    def verify(self, problem_id: str, model_output: str) -> float:
        """
        验证模型的回答是否正确

        实现逻辑：
        1. 从模型输出中提取最终答案
        2. 与正确答案比较
        3. 返回 1.0 (正确) 或 0.0 (错误)
        """
        import re

        # 提取答案：找"答案""最终结果是"等后面的内容
        patterns = [
            r"(?:答案[是为]?|最终答案为?|结果为?)\s*:?\s*(.+?)(?:\n|$)",
            r"(?:answer is|final answer:?)\s*(.+?)(?:\n|$|\.)",
            r"\\boxed\{(.+?)\}",  # LaTeX boxed答案
        ]

        extracted = None
        for pattern in patterns:
            match = re.search(pattern, model_output, re.IGNORECASE)
            if match:
                extracted = match.group(1).strip()
                break

        if extracted is None:
            extracted = model_output.strip().split("\n")[-1].strip()

        correct_answer = self.answers.get(problem_id, "")
        return 1.0 if extracted == correct_answer else 0.0

    def check_format(self, model_output: str) -> float:
        """
        检查输出是否使用了正确的推理格式
        格式：包含 thinking / 推理步骤 + 明确答案
        """
        score = 0.0
        # 检查是否有推理步骤（用编号或关键词标识）
        import re
        has_steps = bool(re.search(r"(?:Step \d|\d+\\.|首先|然后|其次)", model_output))
        has_answer = bool(re.search(r"(?:答案|answer|最终|final)", model_output, re.IGNORECASE))

        if has_steps:
            score += 0.3  # 有推理步骤的部分分
        if has_answer:
            score += 0.7  # 有明确答案标记的部分分

        return score


class GRPOTrainer:
    """Group Relative Policy Optimization (GRPO) 的简化实现"""

    def __init__(self, model, tokenizer, ref_model, device="cpu"):
        self.model = model
        self.tokenizer = tokenizer
        self.ref_model = ref_model
        self.device = torch.device(device)
        self.model.to(self.device)
        self.ref_model.to(self.device)
        # 冻结参考模型
        for param in self.ref_model.parameters():
            param.requires_grad = False

    def generate_group(self, prompt: str, n: int, max_new_tokens: int = 1024) -> List[str]:
        """
        对同一个 prompt 生成 N 个不同的回答（组）

        这是 GRPO 的关键步骤——通过同一问题的多次采样来获得相对好坏的信息
        """
        inputs = self.tokenizer(prompt, return_tensors="pt").to(self.device)
        responses = []

        for _ in range(n):
            with torch.inference_mode():
                outputs = self.model.generate(
                    **inputs,
                    max_new_tokens=max_new_tokens,
                    temperature=0.8,  # 需要随机性来获得多样性
                    do_sample=True,
                    top_p=0.95,
                )
            # 提取生成的 token
            generated = outputs[0][inputs["input_ids"].shape[1]:]
            response = self.tokenizer.decode(generated, skip_special_tokens=True)
            responses.append(response)

        return responses

    def compute_group_advantages(self, rewards: List[float]) -> torch.Tensor:
        """
        GRPO 的优势计算：组内标准化

        公式: A_i = (r_i - mean(r)) / std(r)

        关键直觉：
        - 如果一个回答的 reward 高于组内平均 → 正向引导更新
        - 如果一个回答的 reward 低于组内平均 → 反向引导更新
        - 标准化使得不同难度问题的reward更具可比性
        """
        rewards_tensor = torch.tensor(rewards)
        mean_reward = rewards_tensor.mean()
        std_reward = rewards_tensor.std()

        if std_reward < 1e-8:
            # 所有回答一样好/坏的情况（极难或极简单的问题）
            advantages = torch.zeros_like(rewards_tensor)
        else:
            advantages = (rewards_tensor - mean_reward) / std_reward

        return advantages

    def train_step(
        self,
        prompt: str,
        problem_id: str,
        verifier: MathVerifier,
        n_samples: int = 8,
        kl_coef: float = 0.001,
        clip_epsilon: float = 0.2,
    ) -> dict:
        """
        单步 GRPO 训练

        这是 DeepSeek-R1 训练方案的核心。
        """
        # 步骤1: 为同一个问题生成N个候选回答
        responses = self.generate_group(prompt, n=n_samples)

        # 步骤2: 自动验证器打分
        rewards = []
        for resp in responses:
            correct_score = verifier.verify(problem_id, resp)
            format_score = verifier.check_format(resp)
            total_reward = correct_score + 0.1 * format_score  # 格式权重较低
            rewards.append(total_reward)

        # 步骤3: 计算组内标准化优势
        advantages = self.compute_group_advantages(rewards)

        # 步骤4: 用 PPO-style 损失 + KL 惩罚更新模型
        # 注：这是简化版本——完整实现需要计算log prob和KL散度

        stats = {
            "rewards": rewards,
            "advantages": advantages.tolist(),
            "mean_reward": np.mean(rewards),
            "max_reward": max(rewards),
            "num_correct": sum(1 for r in rewards if r >= 1.0),
        }

        print(f"  GRPO Step - Mean Reward: {stats['mean_reward']:.2f}, "
              f"Correct: {stats['num_correct']}/{n_samples}")
        return stats
```

## 8. 手工代码实现

```python
"""
GRPO 的手工实现：展示组内标准化奖励和KL约束的核心逻辑
"""

import torch
import torch.nn as nn
import torch.nn.functional as F
import numpy as np


class GRPOStep:
    """GRPO 单步更新的核心数学实现"""

    @staticmethod
    def group_relative_advantage(rewards: list) -> list:
        """
        组内相对优势：GRPO 的"秘密武器"

        本质：用组内排名代替绝对价值
        优势 = (r - mean(r)) / std(r)

        为什么这很巧妙？
        - 不需要价值网络 V(s)（节省参数和训练成本）
        - 自动适应不同难度的问题
        - 数学上等价于"这个回答在同组中排第几"
        """
        rewards = np.array(rewards)
        mean = rewards.mean()
        std = rewards.std()

        if std < 1e-8:
            return [0.0] * len(rewards)

        advantages = (rewards - mean) / std
        return advantages.tolist()

    @staticmethod
    def compute_grpo_loss(
        log_probs_current,   # log π_θ_curr(y|x)
        log_probs_old,       # log π_θ_old(y|x)
        log_probs_ref,       # log π_ref(y|x)
        advantages,          # 组内标准化后的优势
        kl_coef=0.001,       # KL权重
        clip_epsilon=0.2,    # PPO clip
    ):
        """
        GRPO 损失计算

        三部分：
        1. PPO clip 确保更新稳定
        2. 加权优势融入强化信号
        3. KL惩罚防止偏离参考策略太远（保持语言能力）
        """
        # 策略比率
        log_ratio = log_probs_current - log_probs_old
        ratio = torch.exp(log_ratio)

        # PPO 目标
        surr1 = ratio * advantages
        surr2 = torch.clamp(ratio, 1 - clip_epsilon, 1 + clip_epsilon) * advantages
        ppo_objective = torch.min(surr1, surr2)

        # KL 惩罚（相对于参考策略，通常是初始SFT模型）
        kl_penalty = (log_probs_current - log_probs_ref).abs().mean()

        # GRPO损失 = 负的PPO目标 + KL惩罚
        # 取负号因为optimizer是最小化
        loss = -ppo_objective.mean() + kl_coef * kl_penalty

        return loss, {
            "ppo_obj": ppo_objective.mean().item(),
            "kl_penalty": kl_penalty.item(),
            "ratio": ratio.mean().item(),
        }


class ReasoningRewardDesigner:
    """推理训练中的奖励设计"""

    def __init__(self):
        self.extraction_patterns = [
            r"\\boxed{(.+?)}",
            r"答案[是为]?\s*[:：]?\s*(.+?)(?:\n|$)",
            r"answer\s*is\s*(.+?)(?:\n|$|\.)",
        ]

    def extract_answer(self, text):
        """从推理链中提取最终答案"""
        import re
        for pattern in self.extraction_patterns:
            match = re.search(pattern, text, re.IGNORECASE)
            if match:
                return match.group(1).strip()
        return text.strip().split("\n")[-1]

    def compute_total_reward(self, reason_response, correct_answer):
        """
        计算总奖励

        包含多维度：
        - 正确性奖励：答案是否正确
        - 格式奖励（可选）：推理格式是否规范
        - 过程质量奖励（可选）：推理链质量

        对于纯基于结果的RL（DeepSeek-R1的初始阶段），只用正确性
        """
        extracted = self.extract_answer(reason_response)
        correctness = 1.0 if extracted == correct_answer else 0.0
        return correctness


# ===== 演示测试 =====
print("=== GRPO 优势计算演示 ===")
grpo = GRPOStep()

# 场景：一个简单问题，模型生成了5个候选回答
rewards_scenario = [1.0, 1.0, 0.0, 1.0, 0.0]  # 3个对，2个错
advantages = grpo.group_relative_advantage(rewards_scenario)

print(f"Rewards: {rewards_scenario}")
print(f"Avg reward: {np.mean(rewards_scenario):.2f}")
print(f"Advantages: {[f'{a:.3f}' for a in advantages]}")
print("  解释: 正确的回答收到正向优势信号(+)")
print("        错误的回答收到负向优势信号(-)")

# 场景：reward标准化如何体现"相对优秀"
print("\n不同场景下的GRPO优势对比:")
print(f"  全对 [1,1,1]: advantages = {grpo.group_relative_advantage([1,1,1])} (无更新信号)")
print(f"  全错 [0,0,0]: advantages = {grpo.group_relative_advantage([0,0,0])} (无更新信号)")
print(f"  混合 [1,0]: advantages = {[f'{a:.2f}' for a in grpo.group_relative_advantage([1.0,0.0])]} (强学习信号)")
```

## 10. 模型评估

```python
"""
RL训练推理模型的评估
"""

import numpy as np
from typing import List


class RLReasoningEvaluator:
    """评估RL训练的推理模型"""

    @staticmethod
    def compute_pass_at_k(
        model_samples: List[str],
        verifier_fn,
        k_values: List[int],
    ) -> dict:
        """
        Pass@K：在K次采样中至少有一次正确的概率

        这是评估推理模型最关键的指标之一
        pass@k = 1 - (1-p)^k_empirical
        """
        result = {}
        n = len(model_samples)
        correct = [verifier_fn(s) for s in model_samples]
        p = np.mean(correct)

        for k in k_values:
            # 在实际评估中是: 从n个样本中随机k个，是否有任一正确
            result[k] = 1 - (1 - p) ** k

        result["single_pass_rate"] = p
        return result

    @staticmethod
    def reasoning_length_analysis(model_outputs: List[str]) -> dict:
        """
        分析推理链长度特征

        DeepSeek-R1 显示推理链会随RL训练变长
        """
        lengths = [len(o) for o in model_outputs]
        return {
            "min_length": min(lengths),
            "max_length": max(lengths),
            "mean_length": np.mean(lengths),
            "median_length": np.median(lengths),
            "std_length": np.std(lengths),
        }

    @staticmethod
    def format_adherence_rate(
        model_outputs: List[str],
        required_format_keywords: List[str],
    ) -> dict:
        """
        检查RL训练后格式遵循率

        格式奖励可能导致高格式遵循率
        但过高的格式奖励可能挤占正确性学习
        """
        rates = {}
        for keyword in required_format_keywords:
            count = sum(1 for o in model_outputs if keyword.lower() in o.lower())
            rates[keyword] = count / len(model_outputs)

        rates["overall_adherence"] = np.mean(list(rates.values()))
        return rates


# ===== 使用示例 =====
print("=== 推理RL模型的评估 ===")

# 模拟15个推理模型生成的回答
predicted_answers = ["14", "14", "12", "14", "10",
                     "14", "14", "14", "12", "14",
                     "14", "16", "14", "14", "12"]
# 11/15正确（单次正确率73%）

evaluator = RLReasoningEvaluator()
def simple_verifier(ans):
    return ans == "14"

pass_results = evaluator.compute_pass_at_k(
    predicted_answers, simple_verifier, [1, 4, 8, 16]
)
print(f"单次正确率: {pass_results['single_pass_rate']:.0%}")
for k, acc in pass_results.items():
    if k != "single_pass_rate":
        print(f"  pass@{k}: {acc:.1%}")
```

## 11. 常见问题与易错点

### 数据层面
| 问题 | 现象 | 原因 | 解决方案 |
|------|------|------|----------|
| 问题太难 | 奖励始终是0，模型无法学习 | 缺乏正向信号导致梯度消失 | 加入提示或先SFT热启动 |
| 问题太简单 | 奖励始终是1，没有区分度 | 组内标准化优势全为0 | 增大问题难度、增大N |

### 模型层面
| 问题 | 现象 | 原因 | 解决方案 |
|------|------|------|----------|
| 语言退化 | RL后输出变成"推理，推理，答案是X"的机械格式 | KL惩罚不够 | 增大KL系数或格式奖励权重 |
| 奖励黑客 | 模型输出"22（通过微妙的错误推理得到的数字但恰好=22）" | 验证器只看最终答案 | 过程奖励模型(PRM) |
| "啊哈时刻"意外行为 | 模型突然在某步开始输出奇怪的中英文混合 | RL中的突发行为 | 监控指标、不过度训练 |

### 调参层面
| 问题 | 现象 | 原因 | 解决方案 |
|------|------|------|----------|
| GRPO的N太小 | 学习信号弱，进步慢 | N=2-4时组内差异小 | N至少8，推荐16 |
| GRPO的N太大 | 虽效果好但每次更新太慢 | 生成N个长推理链的代价 | 平衡N和max_tokens |

## 12. 学习总结

### 核心思想回顾
RL推理训练使用自动可验证的奖励（或规则或测试用例）而非人类偏好来训练推理能力。GRPO（组内相对策略优化）使用"组内标准化"替代价值网络，使训练更简单高效。DeepSeek-R1展示了这种方法的巨大成功——模型能自发涌现推理行为。

### 关键公式
1. GRPO组内优势：$A_i = (r_i - \mu) / \sigma$
2. GRPO损失：$\mathcal{L} = -\min(\rho A, \text{clip}(\rho)A) + \beta \cdot \text{KL}$

### 与前序/相关算法的联系
- 建立在 SFT 冷启动和 CoT 推理格式之上
- GRPO 是 PPO 的简化变体，专为 LLM 推理训练设计
- 与推理时扩展共享"同一问题上多采样"的思想

### 后续学习方向
- 过程奖励模型 (PRM) 与 结果奖励模型 (ORM)
- Online AI Feedback代替人工验证
- Reasoning + Tool Use 的结合RL训练

## 13. 练习题与思考题

### 基础题

**题1**：GRPO为什么不需要价值网络 V(s)？这带来了什么好处？

**参考答案**：
GRPO使用"组内标准化奖励"替代价值函数来估计优势：$A_i = (r_i - mean(r)) / std(r)$。不需要价值网络的好处是：(1)节省了训练一个与大模型同规模的V网络的显存和计算；(2)减少了一个超参数调优的维度；(3)对于有唯一答案的任务（数学），组内比较已经提供了足够的学习信号。缺点是无法准确估计绝对价值，但对于扰动式奖励（对与错）已经足够。

**题2**：解释DeepSeek-R1中发现的"啊哈时刻"（aha moment）是什么？

**参考答案**：
在纯RL（无SFT冷启动）训练过程中，DeepSeek-R1模型在没有被明确教导"如何推理"的情况下，自发学会了在输出中插入"等等，我需要重新检查"这样的自我纠错行为，然后修正了答案。这种行为在预训练数据中存在但不显式，RL训练使模型"发现"了这一策略能带来更高奖励。这不是程序员的编码，而是RL探索产生的涌现行为。

### 进阶题

**题3**：如果奖励信号 r 总是等于最终结果的正确性（0或1），且没有过程奖励，RL训练如何能让模型学会更好的"推理过程"？这不就是"只看结果不看过程"吗？

**参考答案**：
虽然奖励信号只依赖于最终答案，但"路径"仍然被优化，原因是：(1) RL优化的是$\pi_\theta$(推理链+答案|问题)的整体概率，而不仅仅是答案概率；(2) 通过采样探索，更可能导向正确答案的推理模式会获得更高的期望回报；(3) 神经网络（LLM）作为函数逼近器，会逐渐学习到"什么推理模式在这些任务上更有效"。这是一种涌现学习——模型没有被告知"如何推理"，但通过试错找到了有效策略。但这也有极限——非常复杂的推理可能需要过程奖励。

### 开放思考题

**题4**：RL训练的推理模型有时会产生优化偏误（reward hacking），什么叫奖励黑客？给出一个数学推理训练中可能的奖励黑客例子，并提出缓解策略。

**参考答案**：
奖励黑客：模型学会了获得高奖励的策略，但该策略并非设计者意图。数学推理中的例子：
- 例子：概率统计类问题，模型发现输出最常见的答案（如42、0、1）在统计上"碰对"的概率比认真推理但可能算错更高。模型学会了"投机"而非"推理"。
- 缓解：使用代码执行验证（而不仅仅是文本比对答案），增加问题多样性降低"投机均值"的可能性，监控答案分布的均匀性。
