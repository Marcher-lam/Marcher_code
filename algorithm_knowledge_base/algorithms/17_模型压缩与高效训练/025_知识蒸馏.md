# 知识蒸馏 学习文档

> 将大模型的推理能力迁移到更小模型，实现高效推理。

> 来源线索：本节内容根据原书中关于"distillation"的第1章1.5节及第6章相关内容整理、扩展与教学化改写。

## 1. 算法基础认知

### 一句话定义
知识蒸馏是用大模型（教师）的输出指导小模型（学生）训练的技术。

### 直觉类比
一个经验丰富的大厨（教师模型）写出详细的带步骤的菜谱（训练数据），一个新手厨师（学生模型）照着菜谱练习能做出一模一样好吃的菜。菜谱即是"蒸馏出的知识"，它让新手的效率远高于自己从零摸索。

### 历史背景
知识蒸馏最早由 Hinton 等人于 2015 年提出，原始思路是用教师模型的软标签（概率分布）训练学生模型。在 LLM 领域，蒸馏通常指用大模型生成高质量训练数据供给小模型做 SFT。DeepSeek-R1 等推理模型的蒸馏取得了显著成果——小型推理模型的表现远超同规模的通用模型。

### 算法定位
- **类型**：监督学习/模型压缩/迁移学习
- **性质**：需要教师模型生成数据，对学生模型做 SFT 训练

### 前置知识
- 理解 SFT（监督微调）的原理
- 了解 LLM token 分布和 logits 的概念
- 了解推理模型的基本训练流程

## 2. 核心原理

### 核心思想
与其让小模型自己摸索推理能力（费时且效果不确定），不如让已经具备强推理能力的教师模型为小模型生成大量高质量训练数据。学生模型通过模仿这些数据来"继承"推理能力。这种方式比直接在小模型上做 RL 训练更稳定可控。

### 工作流程
1. 准备一个强大的教师推理模型（如 DeepSeek-R1、OpenAI o1）
2. 收集/选择需要推理能力的数据集（各类问题）
3. 用教师模型为每个问题生成包含详细推理链和答案的完整回复
4. 将教师模型的输出作为训练数据，对学生模型进行 SFT 训练
5. 评估学生模型的推理能力提升

### 关键技术选择
- **仅用教师输出**：最简单的方式，将教师模型的完整输出作为训练目标
- **软标签蒸馏**：使用教师模型的完整 logits 分布（推荐概率分布），学生模型同时学习正确的 token 和"合理性"信息
- **拒绝采样蒸馏**：教师模型生成多个候选回答，只保留正确的作为训练数据

### 直观解释
```
步骤1: 教师模型生成训练数据
问题: "15×2/5=?"
教师输出: 
thinking: 
  1. 先算 15×2 = 30
  2. 再除以 5: 30÷5 = 6
response:
  答案是 6

步骤2: 学生模型SFT学习
学生看到同样的(问题, 推理+答案)对，
通过SFT学会生成类似的推理过程和答案。
```

## 3. 数学公式与推导

### 符号约定
| 符号 | 含义 |
|------|------|
| $\theta_T$ | 教师模型参数 |
| $\theta_S$ | 学生模型参数 |
| $x$ | 输入问题 |
| $y$ | 生成的推理链+答案 |
| $p_T(y|x)$ | 教师模型的条件概率 |
| $p_S(y|x)$ | 学生模型的条件概率 |
| $\mathbf{z}_T$ | 教师模型的 logits 输出 |

### 标准 SFT 蒸馏（硬标签方式）

直接使用教师模型的输出文本作为监督信号：

$$\mathcal{L}_{\text{hard}}(\theta_S) = -\mathbb{E}_{x \sim \mathcal{D}} \left[\log p_{\theta_S}(y_T | x)\right]$$

其中 $y_T$ 是教师模型生成的完整推理+答案。

### 软标签蒸馏（KL 散度方式）

使用教师模型的输出概率分布作为"软目标"：

$$\mathcal{L}_{\text{soft}}(\theta_S) = \text{KL}(p_{\theta_T}(\cdot|x) \| p_{\theta_S}(\cdot|x))$$

分解到每个 token 位置：

$$\mathcal{L}_{\text{soft}}(\theta_S) = -\mathbb{E}_x \left[\sum_{t} p_{\theta_T}(y_t|x,y_{<t}) \cdot \log p_{\theta_S}(y_t|x,y_{<t})\right]$$

### 带温度的软标签

为了获取更多"暗知识"（如模型的不确定性），引入温度参数 $\tau$：

$$p_T^\tau(y_i|x) = \frac{\exp(z_{T,i} / \tau)}{\sum_j \exp(z_{T,j} / \tau)}$$

$$p_S^\tau(y_i|x) = \frac{\exp(z_{S,i} / \tau)}{\sum_j \exp(z_{S,j} / \tau)}$$

学生模型同时学习硬标签和软标签（加权组合）：

$$\mathcal{L}_{\text{total}}(\theta_S) = (1-\alpha) \cdot \mathcal{L}_{\text{hard}} + \alpha \cdot \tau^2 \cdot \mathcal{L}_{\text{soft}}^\tau$$

其中 $\alpha$ 控制软目标的权重，$\tau^2$ 是温度缩放补偿。

### 为什么软标签有帮助？

教师模型输出的概率分布包含了丰富信息：
- "这个 token 是唯一正确答案"是硬信息 → 硬标签
- "token A 的概率 60%, token B 的概率 25%"是暗知识 → 软标签
- 暗知识反映了教师模型的语言理解和不确定性，帮助学生学到更好的内部表征

## 4. 训练过程讲解

### 数据生成（教师模型推理）
1. **问题收集**：准备需要推理能力的问题集
2. **教师生成**：教师模型对每个问题产生完整的推理输出
3. **质量筛选**（可选）：通过答案验证过滤掉错误的输出
4. **多样性保持**：温度设置不要过低（>0.5），以在数据中保持推理多样性

### 学生模型训练（SFT）
- 直接使用教师生成的 (问题, 推理+答案) 对进行 SFT
- 如果有软标签（logits），需要使用 KL 散度损失
- 训练参数与标准 SFT 相同（学习率 2e-5，epoch 1-3）
- 可使用 LoRA 以节省显存

### 关键超参数
| 参数 | 作用 | 推荐范围 | 默认建议 |
|------|------|----------|----------|
| 生成 temperature | 控制教师输出的多样性 | 0.5 ~ 1.0 | 0.7 |
| 学习率 | SFT微调的学习率 | 1e-6 ~ 5e-5 | 2e-5 |
| epochs | 训练轮数 | 1 ~ 5 | 2-3 |
| $\tau$ (温度) | 软标签的平滑度 | 2 ~ 10 | 4 |
| $\alpha$ (软标签权重) | 硬标签 vs 软标签 | 0.3 ~ 0.7 | 0.5 |

### 数据规模建议
- 最少: 1000-3000条优秀数据可观察到显著提升
- 理想: 5000-20000条数据达到稳定效果
- 边际递减：20000条以上收益渐弱

## 5. 应用场景

### 典型应用
1. **推理模型压缩**：将DeepSeek-R1等大推理模型的推理能力迁移到7B、1.5B甚至0.5B参数的小模型。小模型推理更快，部署成本更低。
2. **领域专用推理**：先让大模型在领域数据上生成推理，蒸馏到小模型后部署。医疗诊断推理、法律推理等场景。
3. **边缘设备部署**：手机、IoT设备上只能跑小模型，但通过蒸馏继承较大的推理能力。
4. **快速迭代原型**：小模型训练快，可快速测试蒸馏效果，找到最佳教师/学生配对。

### 适用数据特征
- 拥有高质量的教师模型（推理能力显著强于学生）
- 有足够的问题数据供教师模型生成
- 目标是"可运行的小模型"而非"最佳的大模型"

### 不适用场景
- 教师模型和学生模型类型差异太大（如LLM→CNN——知识无法迁移）
- 学生模型需要的能力完全不在教师模型覆盖范围内
- 对模型透明度要求极高的场景（蒸馏过程可能有信息损失）

## 6. 优缺点分析

### 优点
| 优点 | 说明 | 成立条件 |
|------|------|----------|
| 高效压缩 | 相同推理能力下模型更小、更快 | 教师模型远优于学生初始能力 |
| 稳定可控 | 比直接在小模型上RL训练更稳定 | 教师模型输出质量可靠 |
| 保留语言能力 | SFT方式蒸馏较少导致语言退化 | 不做过多epoch |
| 成本灵活 | 教师推理SFT训练可分批进行 | — |

### 缺点
| 缺点 | 说明 | 缓解思路 |
|------|------|----------|
| 上限受限 | 学生不会超越教师能力 | 与RL结合做提升 |
| 偏差传播 | 教师模型的错误会传染 | 质量过滤、拒绝采样 |
| 丧失探索性 | 完全模仿教师失去了自创新路径的可能 | 混合蒸馏+RL |
| 知识损失 | 硬标签蒸馏丢失概率分布中的"暗知识" | 使用软标签蒸馏 |

### 与同类方法对比
| 方法 | 效果上限 | 稳定性 | 数据需求 | 计算成本 |
|------|----------|--------|----------|----------|
| 知识蒸馏 | 中-高（受限于教师） | 高 | 教师模型生成数据 | 中（需教师推理） |
| 直接RL训练小模型 | 高 | 中-低 | 自动奖励 | 高（RL昂贵） |
| 仅小模型SFT（人类标注） | 中 | 高 | 人类标注数据 | 低-中 |
| 小模型推理时扩展 | 中 | 最高 | 无需 | 推理时成本高 |

## 7. 调库实现

```python
"""
知识蒸馏的调库实现
教师模型生成推理数据 → 学生模型SFT蒸馏
"""

import torch
from transformers import AutoModelForCausalLM, AutoTokenizer
from datasets import Dataset
import json
import re


class DistillationDataGenerator:
    """用教师模型生成蒸馏训练数据"""

    def __init__(self, teacher_model_name: str):
        self.tokenizer = AutoTokenizer.from_pretrained(teacher_model_name)
        self.model = AutoModelForCausalLM.from_pretrained(
            teacher_model_name,
            torch_dtype=torch.bfloat16,
            device_map="auto",
        )
        self.model.eval()
        # 推理格式 prompt
        self.reasoning_prompt_template = (
            "<|im_start|>user\n{question}<|im_end|>\n"
            "<|im_start|>assistant\n"
        )

    @torch.inference_mode()
    def generate_reasoning(
        self,
        question: str,
        max_new_tokens: int = 2048,
        temperature: float = 0.7,
    ) -> str:
        """用教师模型生成带推理链的回答"""
        prompt = self.reasoning_prompt_template.format(question=question)
        inputs = self.tokenizer(prompt, return_tensors="pt").to(self.model.device)

        outputs = self.model.generate(
            **inputs,
            max_new_tokens=max_new_tokens,
            temperature=temperature,
            do_sample=True,
            top_p=0.95,
            pad_token_id=self.tokenizer.eos_token_id,
        )

        generated = outputs[0][inputs["input_ids"].shape[1]:]
        response = self.tokenizer.decode(generated, skip_special_tokens=True)
        return response

    def create_distillation_dataset(
        self,
        questions: list,
        answers: dict = None,  # id → 正确答案，用于过滤
        quality_filter: bool = True,
    ) -> Dataset:
        """
        生成蒸馏数据集

        如启用质量过滤：
        - 提取教师回答中的答案
        - 与正确答案比较
        - 只保留正确的样本
        """
        data = []
        for i, question in enumerate(questions):
            teacher_output = self.generate_reasoning(question)

            if quality_filter and answers:
                q_id = question.get("id", str(i))
                # 简化验证：在教师输出中寻找正确答案
                correct = answers.get(q_id, "")
                if correct and correct in teacher_output:
                    data.append({
                        "instruction": question["text"]
                        if isinstance(question, dict) else question,
                        "output": teacher_output,
                    })
            else:
                data.append({
                    "instruction": question["text"]
                    if isinstance(question, dict) else question,
                    "output": teacher_output,
                })

            print(f"  已生成 {len(data)}/{i+1} 条蒸馏数据")

        return Dataset.from_list(data)


class DistillationTrainer:
    """
    将教师生成的蒸馏数据训练到学生模型
    本质上是一个带蒸馏数据的 SFT 训练器
    """

    def __init__(self, student_model_name: str):
        self.tokenizer = AutoTokenizer.from_pretrained(student_model_name)
        self.tokenizer.pad_token = self.tokenizer.eos_token
        self.model = AutoModelForCausalLM.from_pretrained(
            student_model_name,
            torch_dtype=torch.bfloat16,
            device_map="auto",
        )

    def format_distillation_sample(self, instruction: str, output: str) -> str:
        """格式化蒸馏样本为训练格式"""
        return (
            f"<|im_start|>user\n{instruction}<|im_end|>\n"
            f"<|im_start|>assistant\n{output}<|im_end|>"
        )

    def tokenize_function(self, examples):
        """Tokenize 蒸馏数据"""
        texts = [
            self.format_distillation_sample(inst, out)
            for inst, out in zip(examples["instruction"], examples["output"])
        ]

        tokenized = self.tokenizer(
            texts,
            truncation=True,
            max_length=2048,
            padding=False,
        )

        # 创建labels（只对assistant部分计算损失）
        all_labels = []
        for i, input_ids in enumerate(tokenized["input_ids"]):
            # 找到 "<|im_start|>assistant" 的位置
            assistant_tokens = self.tokenizer.encode(
                "<|im_start|>assistant", add_special_tokens=False
            )
            labels = [-100] * len(input_ids)  # 默认全部ignore
            for j in range(len(input_ids) - len(assistant_tokens) + 1):
                if input_ids[j:j + len(assistant_tokens)] == assistant_tokens:
                    # 从assistant开始的部分计算loss
                    labels[j:] = input_ids[j:]
                    break
            all_labels.append(labels)

        tokenized["labels"] = all_labels
        return tokenized

sample_questions = [

    "一个数加5除以2等于10，这个数是？",

]
```

## 8. 手工代码实现

```python
"""
知识蒸馏的手工实现
展示软标签蒸馏的核心机制（温度缩放 + KL散度）
"""

import torch
import torch.nn as nn
import torch.nn.functional as F
import numpy as np


class SoftDistillationLoss:
    """
    软标签蒸馏（知识蒸馏的经典形式）

    让学生不仅学习"什么是对的"，也学习教师的"不确定性和替代可能性"
    """

    def __init__(self, temperature: float = 4.0, alpha: float = 0.5):
        """
        参数:
            temperature: 温度参数τ，越高概率分布越平滑
            alpha: 软标签损失的权重
        """
        self.temperature = temperature  # τ
        self.alpha = alpha              # 硬标签 vs 软标签权重

    def compute_loss(
        self,
        student_logits: torch.Tensor,    # 学生模型的输出 logits
        teacher_logits: torch.Tensor,    # 教师模型的输出 logits
        hard_labels: torch.Tensor,       # 真实 token 的 ID
    ) -> tuple:
        """
        计算蒸馏损失 = (1-α)×硬标签损失 + α×τ²×软标签损失

        返回 (总损失, 诊断信息)
        """
        # ---- 硬标签损失（标准交叉熵） ----
        hard_loss = F.cross_entropy(
            student_logits.view(-1, student_logits.size(-1)),
            hard_labels.view(-1),
            ignore_index=-100,
        )

        # ---- 软标签损失（温度缩放的KL散度） ----
        # 对教师和学生的logits用相同温度缩放
        student_soft = F.log_softmax(
            student_logits / self.temperature, dim=-1
        )
        teacher_soft = F.softmax(
            teacher_logits / self.temperature, dim=-1
        )

        # KL散度：KL(teacher || student)
        soft_loss = F.kl_div(
            student_soft,
            teacher_soft,
            reduction="batchmean",
        ) * (self.temperature ** 2)  # 温度补偿（梯度缩放）

        # ---- 组合损失 ----
        total_loss = (1 - self.alpha) * hard_loss + self.alpha * soft_loss

        return total_loss, {
            "hard_loss": hard_loss.item(),
            "soft_loss": soft_loss.item(),
            "total_loss": total_loss.item(),
        }


class SimpleDistillationDemo:
    """蒸馏过程的数值演示"""

    @staticmethod
    def demonstrate_temperature_effect():
        """展示温度参数如何影响概率分布"""
        logits = torch.tensor([[5.0, 2.0, 1.0, 0.5, 0.1]])

        temperatures = [1.0, 2.0, 4.0, 10.0]
        print("温度越高，分布越平滑（暗知识越丰富）:")
        print(f"{'Temp':<8} {'分布':<60} 最高 vs 次高")
        print("-" * 80)

        for tau in temperatures:
            probs = F.softmax(logits / tau, dim=-1)[0]
            dist_str = " ".join(f"{p:.3f}" for p in probs.tolist())
            ratio = probs[0] / probs[1]
            print(f"τ={tau:<5.1f} [{dist_str}]  {ratio:.1f}:1")

        print("""
        τ=1: 教师最偏好的选项被过度强化
        τ=4: 暗知识（次优选项仍有一定概率）被保留
        τ=10: 几乎均匀——太多噪声，有用的暗知识被稀释
        """)

    @staticmethod
    def distillation_simulation():
        """
        模拟：蒸馏 vs 仅硬标签训练的区别

        展示为什么暗知识有价值
        """
        # 模拟场景：一个token分类，vocab=5
        # 教师认为：
        #   token0: 60% (正确答案)
        #   token1: 30% (合理的替代)
        #   token2-4: 10% (不太可能)
        teacher_logits = torch.tensor([[2.0, 1.0, -1.0, -2.0, -3.0]])  # 5个token
        teacher_probs = F.softmax(teacher_logits, dim=-1)[0]
        correct_token = 0  # token 0 是正确答案

        # 学生A：只用硬标签训练（只知道答案是token0）
        student_hard_logits = torch.tensor([[1.8, -3.0, -3.0, -3.0, -3.0]])
        student_hard_probs = F.softmax(student_hard_logits, dim=-1)[0]

        # 学生B：蒸馏训练（学到了暗知识——token1也是合理的）
        student_soft_logits = torch.tensor([[1.6, 0.8, -1.5, -2.5, -3.0]])
        student_soft_probs = F.softmax(student_soft_logits, dim=-1)[0]

        print("\n蒸馏 vs 硬标签训练的区别：")
        print(f"教师分布: {teacher_probs}")
        print(f"硬标签学生分布: {student_hard_probs} (过拟合)")
        print(f"蒸馏学生分布: {student_soft_probs} (保留了暗知识)")
        print()
        print("硬标签学生在测试时如果遇到token1的情境会不知所措")
        print("蒸馏学生保留了\"有时token1也可能对\"的知识，泛化更好")


if __name__ == "__main__":
    print("=== 温度参数演示 ===")
    SimpleDistillationDemo.demonstrate_temperature_effect()
    print()
    print("=== 蒸馏 vs 硬标签比较 ===")
    SimpleDistillationDemo.distillation_simulation()
```

## 10. 模型评估

```python
"""
知识蒸馏效果的评估策略
"""

import numpy as np
from typing import List, Dict


class DistillationEvaluator:
    """评估蒸馏效果"""

    @staticmethod
    def compression_ratio(teacher_params: int, student_params: int) -> float:
        """计算压缩比"""
        return teacher_params / student_params

    @staticmethod
    def performance_retention_rate(
        teacher_accuracy: float,
        student_accuracy: float,
    ) -> float:
        """
        计算学生保留了多少教师的能力

        retention = student_acc / teacher_acc
        0.95+ = 优秀蒸馏
        0.85-0.95 = 良好蒸馏
        <0.85 = 有待改进
        """
        return student_accuracy / teacher_accuracy

    @staticmethod
    def efficiency_gain(
        teacher_accuracy: float,
        student_accuracy: float,
        teacher_time_ms: float,
        student_time_ms: float,
    ) -> Dict:
        """
        计算效率-效果增益比率

        效率比 = (速度提升) / (准确率损失)
        """
        speedup = teacher_time_ms / student_time_ms
        accuracy_drop = teacher_accuracy - student_accuracy

        # 如果准确率没有下降还加速了，这是理想蒸馏
        efficiency_score = speedup / max(accuracy_drop, 0.01)
        return {
            "speedup": speedup,
            "accuracy_drop": accuracy_drop,
            "efficiency_score": efficiency_score,
        }

    @staticmethod
    def verify_faithfulness(
        student_outputs: List[str],
        expected_reasoning_keywords: List[List[str]],
    ) -> Dict:
        """
        验证学生模型的推理是否"忠实"——是否真的在推理
        而不是直接从蒸馏数据中记忆答案

        检查推理链是否包含关键词（"首先""因此""计算"等推理标记）
        """
        reasoning_keywords = ["首先", "然后", "因此", "计算", "所以", "步骤"]
        scores = []

        for output in student_outputs:
            # 检查推理链结构
            score = 0
            for kw in reasoning_keywords:
                if kw in output:
                    score += 1
            scores.append(score / len(reasoning_keywords))

        return {
            "avg_reasoning_faithfulness": np.mean(scores),
            "min_faithfulness": min(scores),
            "samples_no_reasoning": sum(1 for s in scores if s == 0),
        }


# ===== 使用示例 =====
evaluator = DistillationEvaluator()

# 场景：70B教师蒸馏到1.5B学生
print("=== 蒸馏效果报告 ===")
print(f"压缩比: {evaluator.compression_ratio(70_000_000_000, 1_500_000_000):.1f}x")
print(f"能力保留率: {evaluator.performance_retention_rate(0.82, 0.58):.0%}")

efficiency = evaluator.efficiency_gain(
    teacher_accuracy=0.82, student_accuracy=0.58,
    teacher_time_ms=5000, student_time_ms=200,
)
print(f"推理速度提升: {efficiency['speedup']:.0f}×")
print(f"准确率下降: {efficiency['accuracy_drop']:.0%}")
```

## 11. 常见问题与易错点

### 数据层面
| 问题 | 现象 | 原因 | 解决方案 |
|------|------|------|----------|
| 蒸馏数据全是正确的 | 学生没学到如何从错误中恢复 | 缺少"推理失误然后纠正"的模式 | 保留少量教师犯错后自我纠正的数据 |
| 蒸馏数据格式单一 | 学生的推理模式僵硬 | 教师的temperature太低 | 教师生成时用temperature 0.7-0.8 |

### 模型层面
| 问题 | 现象 | 原因 | 解决方案 |
|------|------|------|----------|
| 过拟合蒸馏数据 | 验证集上效果差于蒸馏数据训练时的表现 | 蒸馏数据不够多样或epoch太多 | 更多样的蒸馏数据 + 早停 |
| 灾难性遗忘 | 蒸馏后模型在非推理任务上退化 | 蒸馏数据全是推理任务 | 混合通用任务的SFT数据 |

### 调参层面
| 问题 | 现象 | 原因 | 解决方案 |
|------|------|------|----------|
| 温度参数不当 | τ太小则退化为硬标签，τ太大则知识被稀释成噪声 | 没找到最佳温度范围 | τ在2-5之间网格搜索最佳值 |

## 12. 学习总结

### 核心思想回顾
知识蒸馏通过教师模型生成高质量的训练数据（推理链+答案）来教会学生模型推理。硬标签方式（教师输出文本→SFT）是最实践的方案，软标签方式（教师概率分布→KL蒸馏）保留了更多"暗知识"。蒸馏+RL混合方案通常获得最佳效果。

### 关键公式
1. 软标签损失：$\mathcal{L}_{\text{soft}} = \tau^2 \cdot \text{KL}(p_T^\tau \| p_S^\tau)$
2. 带温度的概率：$p^\tau(y_i) = \text{softmax}(z_i/\tau)$
3. 总蒸馏损失：$\mathcal{L} = (1-\alpha)\mathcal{L}_{\text{hard}} + \alpha\mathcal{L}_{\text{soft}}$

### 与前序/相关算法的联系
- 建立在 SFT 和推理模型训练之上
- 是推理模型能力利用的最高效方式之一
- 与推理时扩展互补——蒸馏用于减少推理成本，推理时扩展用于提升推理质量

### 后续学习方向
- 多教师蒸馏
- 渐进式蒸馏（逐层蒸馏）
- 蒸馏与RLHF结合

## 13. 练习题与思考题

### 基础题

**题1**：为什么蒸馏中的温度参数 $\tau > 1$ 能保留"暗知识"？$\tau=1$ 和 $\tau=4$ 有什么不同？

**参考答案**：
$\tau > 1$ 的效果是"平滑概率分布"。具体来说：
- $\tau=1$：softmax后分布很尖锐，教师认为最可能的token概率接近100%，其他几乎0%。学生只能学到"正确答案是什么"，失去了关于"次优答案有多少合理性"的信息。
- $\tau=4$：分布更平滑，次优token也保留可观概率。比如"关键"的概率60%，"重要"的概率25%，这一信息告诉学生"有时候次优的替代也可取"——这就是暗知识。
暗知识的价值在于帮助模型泛化到未见过的数据。

**题2**：在推理模型蒸馏中，为什么常用硬标签蒸馏（教师输出文本→SFT）而非软标签蒸馏？

**参考答案**：
(1) 工程简单性：获取教师输出文本比保存和传递完整 logits 简单很多（logits 矩阵可能是 (seq_len, vocab_size=150k) 的大矩阵）。
(2) 推理链的信息密度：推理链中真正的暗知识在"推理步骤"中已经显式化为文本——不是隐藏的概率偏好问题。
(3) 实际效果已经足够：文本SFT蒸馏在实验中已经能获得很好的效果。对于代码类等特殊任务，软标签可能更有价值。

### 进阶题

**题3**：教师模型的错误会传播到学生模型。设计一种策略来最小化错误的传播。

**参考答案**：
策略：**拒绝采样 + 质量过滤**
1. 对每个问题，教师生成K个候选（如K=5）
2. 使用可自动验证的方式（数学的回答的正确性）筛选出正确的
3. 只保留正确的样本用作蒸馏数据
4. 对于不能自动验证的开放问题，使用另一个评判模型（或LLM-as-judge）筛选

这种策略的提升效果显著，但额外增加了教师推理的K倍计算量和评判成本。

### 开放思考题

**题4**：如果将蒸馏和RL（GRPO）训练结合在一个学生模型上同时进行，会互相促进还是干扰？为什么？

**参考答案**：
可能的效果是**促进**，因为：
- 蒸馏提供"模仿高质量示范"，RL提供"探索更好的策略"
- 蒸馏的SFT可以作为RL的"冷启动"，降低RL探索成本
- RL探索产生的新数据可以被新的SFT阶段吸收
实际中的干扰风险：
- RL可能引导模型偏离教师蒸馏的"保守好策略"
- 两者目标函数的不一致可能导致震荡
最佳实践（DeepSeek成功模式）：**分阶段**而非同时训练——先蒸馏SFT，再RL，再SFT用RL数据蒸馏，再RL循环。
