## 1. 算法基础认知

### 一句话定义
GQA (Grouped Query Attention) 是多头注意力的优化版本，多组查询共享键值以减少显存带宽。

### 直觉类比
图书馆有16个查询窗口（查询头），但只有8个书库管理员（键值头）。每2个查询窗口共享同一个管理员——他们必须排队等待，但总的管理员数量减半，图书馆运行更高效。

### 历史背景
GQA由 Ainslie 等人于 2023 年提出。Llama 2 (2023) 采用了 GQA 使得推理更快。此后 GQA 迅速成为现代 LLM 的标准——Llama 3、Mistral、Qwen3、DeepSeek 等全部使用 GQA。

### 算法定位
- **类型**：注意力机制变体 / 推理优化 / 模型架构组件
- **性质**：模型注意力机制的设计选择，训练和推理都使用

### 前置知识
- 了解标准多头注意力 (MHA)
- 了解 KV Cache 的概念
- 了解 Q、K、V 在注意力中的作用

## 2. 核心原理

### 核心思想
标准 MHA 中每个注意力头都有独立的 Q、K、V 投影——如果有16个头，就有16组KV。GQA让多组查询（Q）头共享同一组键值（KV）——例如4个查询头共享1组KV，16个头只需要4组KV。这在推理时减少75%的KV cache内存，而建模性能损失很小。

### 工作流程
1. Q投影保留全部 num_heads 组（如16组）
2. K、V投影只产生 num_kv_groups 组（如4组）
3. 每组K、V通过repeat_interleave复制 group_size 次以匹配 Q 的数量
4. 其余注意力计算完全与MHA相同

### GQA=1 (MQA) 的极端情况
当 num_kv_groups = 1 时，GQA退化为 MQA (Multi-Query Attention)——所有查询头共享唯一一组KV。这是最节省内存的方式，但建模性能损失较大。GQA在MHA和MQA之间找到平衡点。

## 3. 数学公式与推导

### 符号约定
| 符号 | 含义 |
|------|------|
| $N_q$ | 查询头数量 (num_heads) |
| $N_{kv}$ | KV头数量 (num_kv_groups) |
| $G = N_q / N_{kv}$ | 每组查询头数量 (group_size) |
| $W_Q, W_K, W_V$ | Q、K、V 投影矩阵 |
| $d, d_h$ | 模型维度、每头维度 |

### 参数矩阵形状

| 矩阵 | MHA | GQA (N_q=16, N_kv=4) |
|------|-----|----------------------|
| $W_Q$ | $d \times (N_q \cdot d_h)$ | $d \times (16 \cdot d_h)$ |
| $W_K$ | $d \times (N_q \cdot d_h)$ | $d \times (4 \cdot d_h)$ |
| $W_V$ | $d \times (N_q \cdot d_h)$ | $d \times (4 \cdot d_h)$ |

GQA中 $W_K$ 和 $W_V$ 的参数减少了 75%。

### KV Cache 对比

| 方法 | KV Cache的元素数(每个token) |
|------|------|
| MHA | $2 \times N_q \times d_h$ |
| GQA | $2 \times N_{kv} \times d_h$ |
| MQA | $2 \times 1 \times d_h$ |

Qwen3 0.6B: N_q=16, N_kv=8, d_h=128
- GQA KV/token = 2 × 8 × 128 = 2048 元素
- MHA将是: 2 × 16 × 128 = 4096 元素
- GQA节省50%的KV cache内存

## 4. 训练过程讲解

GQA作为架构设计被固定，不需要在训练时做特殊调整。关键配置：

- **group_size 选择**: 通常2-8之间（Qwen3 0.6B用2，即16 Q头 / 8 KV头）
- **性能权衡**: group_size越大→内存越省但质量损失越大

Qwen3 0.6B 配置：
```python
"n_heads": 16,
"n_kv_groups": 8,  # 16/8 = 2个查询头共享一组KV
```

## 5. 应用场景

所有需要高效推理的现代LLM：对话助手、代码助手、推理模型。GQA的KV cache节省在长序列推理（如推理模型的长 CoT）中尤其关键。

## 6. 优缺点分析

| 优点 | 说明 |
|------|------|
| KV Cache 大幅减少 | 50-87.5%的内存节省 |
| 推理吞吐量提升 | 减少KV的显存带宽负担 |
| 建模性能损失小 | 实验中与MHA几乎无差距 |
| 更低延迟 | KV从显存读写更快的直接结果 |

| 缺点 | 说明 |
|------|------|
| 极端的MQA有质量损失 | 所有头共享一组KV限制表达力 |
| 训练到推理的内存不匹配 | 训练时仍有完整KV（未发生质变） |

## 8. 手工代码实现

```python
"""GQA手工实现"""
import torch
import torch.nn as nn
import torch.nn.functional as F

class GroupedQueryAttention(nn.Module):
    def __init__(self, d_in, num_heads, num_kv_groups, head_dim=None):
        super().__init__()
        self.num_heads = num_heads
        self.num_kv_groups = num_kv_groups
        self.group_size = num_heads // num_kv_groups
        
        if head_dim is None:
            assert d_in % num_heads == 0
            head_dim = d_in // num_heads
        self.head_dim = head_dim
        self.d_out = num_heads * head_dim

        # Q投影: 所有head独立
        self.W_query = nn.Linear(d_in, self.d_out, bias=False)
        # K, V投影: 只有num_kv_groups组（关键区别）
        self.W_key = nn.Linear(d_in, num_kv_groups * head_dim, bias=False)
        self.W_value = nn.Linear(d_in, num_kv_groups * head_dim, bias=False)
        self.out_proj = nn.Linear(self.d_out, d_in, bias=False)

    def forward(self, x, mask):
        b, n, _ = x.shape
        q = self.W_query(x).view(b, n, self.num_heads, self.head_dim).transpose(1, 2)
        k = self.W_key(x).view(b, n, self.num_kv_groups, self.head_dim).transpose(1, 2)
        v = self.W_value(x).view(b, n, self.num_kv_groups, self.head_dim).transpose(1, 2)

        # 扩展K、V: 每组KV复制group_size次
        # (b, num_kv_groups, n, d) → (b, num_heads, n, d)
        k = k.repeat_interleave(self.group_size, dim=1)
        v = v.repeat_interleave(self.group_size, dim=1)

        # 标准缩放点积注意力
        scores = q @ k.transpose(-2, -1) / (self.head_dim ** 0.5)
        attn = F.softmax(scores.masked_fill(mask[:,:,:n,:n], float('-inf')), dim=-1)
        context = (attn @ v).transpose(1, 2).reshape(b, n, self.d_out)
        return self.out_proj(context)
```

## 9-14. 总结、问题、练习、路径

### 学习总结
GQA在现代LLM中平衡了注意力的表达力和推理效率——多查询头共享键值来大幅减少KV Cache内存。

### 练习题
**题1**：MQA（单组KV）和GQA的性能差异原因是什么？

**参考答案**：MQA所有头共享唯一KV，限制了不同注意力头关注不同特征的能力——每个头的Q是独立的，但K、V完全相同，导致所有头"问不同的问题，但得到相同的回答"。GQA通过分组来恢复一些多样性，每组内的头共享KV，但不同组的KV不同。

### 学习路径
- **前置**：MHA、KV Cache
- **进阶**：MLA (Multi-head Latent Attention, DeepSeek-V2/V3使用的更高效注意力)
