# 自回归文本生成 学习文档

> 逐token预测下一个词，模型以"续写"的方式逐步生成完整文本。

> 来源线索：本节内容根据原书第2章2.6-2.7节关于autoregressive text generation的讲解整理、扩展与教学化改写。

## 1. 算法基础认知

### 一句话定义
自回归生成是LLM一次生成一个token、每次基于之前所有token预测下一个的文本生成方式。

### 直觉类比
就像用手机输入法的"联想词"功能——你输入一个字，输入法建议下一个可能的字，你选了后再建议下一个……这样逐词推进直到完成整个句子。

### 历史背景
自回归模型的概念在时间序列分析中已有数十年历史。在深度学习时代，2017年Transformer架构结合自回归生成成为主流。GPT系列("Generative Pre-trained Transformer")命名中的"Generative"指向的就是这种自回归生成方式。

### 算法定位
- **类型**：解码策略 / 生成模型 / 推理方法
- **性质**：LLM的默认文本生成方式，不修改模型参数

### 前置知识
- 了解LLM的token和tokenizer概念
- 基本概率论（条件概率、链式法则）
- 了解LLM的输出logits

## 2. 核心原理

### 核心思想
自回归生成基于"条件概率的链式法则"：整个序列的概率 = 每个token在前序条件下的概率的乘积。因此生成时只需在当前已生成的序列基础上预测下一个最可能的token，然后把这个token加入序列，循环进行。

### 工作流程
1. 用户输入prompt，转为token IDs
2. 将当前所有token IDs输入LLM，LLM输出每个位置的下一个token的概率分布
3. 从最后位置的分布中选择下一个token（贪婪选概率最高，或采样）
4. 将新token追加到序列末尾
5. 检查是否满足停止条件（达到max_tokens或生成EOS token）
6. 如果未停止，回到步骤2

### 关键概念解释
- **自回归(Autoregressive)**：每个输出依赖之前的所有输出
- **因果掩码(Causal Mask)**：LLM内部的注意力机制被遮罩以确保只能"看到过去不能看到未来"
- **EOS Token**：End-of-Sequence token，标记生成的结束
- **解码策略**：从概率分布中选择下一个token的方式（贪婪、温度采样、top-p、top-k等）

### 直观解释
```
迭代0: 输入: "The capital of"
迭代1: LLM → "The capital of France"  (+ "France")
迭代2: LLM → "The capital of France is"  (+ "is")
迭代3: LLM → "The capital of France is Paris"  (+ "Paris")
迭代4: LLM → "The capital of France is Paris."  (+ ".")
迭代5: LLM → EOS → 停止
```

## 3. 数学公式与推导

### 符号约定
| 符号 | 含义 |
|------|------|
| $\mathbf{x} = (x_1, ..., x_n)$ | 输入prompt的token序列 |
| $\mathbf{y} = (y_1, ..., y_m)$ | 生成的token序列 |
| $y_{<t} = (y_1,...,y_{t-1})$ | 前t-1个生成token |
| $V$ | 词汇表 |
| $p(y_t | x, y_{<t})$ | 在给定上下文中第t个token的概率 |

### 链式法则

整个序列的联合概率分解为条件概率的连乘：

$$p(y_1, ..., y_m | x) = \prod_{t=1}^{m} p(y_t | x, y_1, ..., y_{t-1})$$

### 贪婪解码

$$\hat{y}_t = \arg\max_{v \in V} p(y_t = v | x, y_{<t})$$

### 温度采样

$$\hat{y}_t \sim \text{Categorical}\left(\frac{\exp(z_i/T)}{\sum_j \exp(z_j/T)}\right)$$

其中 $z_i$ 是该token的logit值，$T$ 是温度参数。

- $T \to 0$：趋向贪婪解码
- $T = 1$：标准概率采样
- $T \to \infty$：趋向均匀随机

### Top-p (Nucleus) 采样

只从累积概率达到p的最小子集中采样：

$$\mathcal{V}^{(p)} = \left\{v_1, ..., v_k\right\} \text{ where } \sum_{i=1}^{k} p(y_t = v_i | ...) \geq p \text{ and } k \text{ is minimal}$$

## 4. 训练过程讲解

自回归生成是推理时方法，不需要训练，但需要配置解码参数。

### 推理配置
- **模型需设为 eval() 模式**：禁用dropout、batch norm的训练行为
- **@torch.inference_mode()**：禁用梯度计算以节省时间内存
- **KV Cache**：启用后可大幅减少冗余计算

### 停止条件设置
1. 达到最大生成token数 (max_new_tokens)
2. 生成EOS token
3. 可自定义（如检测到重复、检测到不安全内容）

### 关键超参数
| 参数 | 作用 | 推荐范围 | 默认建议 |
|------|------|----------|----------|
| max_new_tokens | 最大生成长度 | 50-4096 | 256-1024 |
| temperature | 随机性控制 | 0.0-1.5 | 0.6-0.7 |
| top_p | 核采样阈值 | 0.9-1.0 | 0.95 |
| top_k | 只考虑前k高概率token | 10-100 | 50 |
| repetition_penalty | 减少重复 | 1.0-1.2 | 1.0 |

## 5. 应用场景

现代LLM的所有文本生成都依赖自回归解码，包括对话、翻译、代码生成、推理模型输出等。这是唯一通用的LLM文本生成范式。

## 6. 优缺点分析

| 优点 | 说明 |
|------|------|
| 数学简单优美 | 链式法则直截了当 |
| 天然因果性 | 每个输出只依赖"过去"，符合语言直觉 |
| 灵活性高 | 可插不同的解码策略控制质量和多样性 |

| 缺点 | 说明 |
|------|------|
| 串行瓶颈 | 必须逐个生成，无法并行 |
| 误差累积 | 前一个token错了，后续都会被带偏 |
| 缺乏全局规划 | 模型看不到还没生成的"未来"token |

## 7. 调库实现

```python
"""
自回归文本生成的调库实现
"""

import torch
from transformers import AutoModelForCausalLM, AutoTokenizer

MODEL_NAME = "Qwen/Qwen2.5-0.5B-Instruct"

tokenizer = AutoTokenizer.from_pretrained(MODEL_NAME)
model = AutoModelForCausalLM.from_pretrained(
    MODEL_NAME, torch_dtype=torch.bfloat16, device_map="auto"
)
model.eval()

@torch.inference_mode()
def generate_text(
    prompt: str,
    max_new_tokens: int = 256,
    temperature: float = 0.7,
    top_p: float = 0.95,
) -> str:
    """使用各种解码策略的自回归文本生成"""
    inputs = tokenizer(prompt, return_tensors="pt").to(model.device)

    outputs = model.generate(
        **inputs,
        max_new_tokens=max_new_tokens,
        temperature=temperature,
        do_sample=(temperature > 0),
        top_p=top_p,
        pad_token_id=tokenizer.eos_token_id,
        eos_token_id=tokenizer.eos_token_id,
    )

    generated_ids = outputs[0][inputs["input_ids"].shape[1]:]
    return tokenizer.decode(generated_ids, skip_special_tokens=True)

# 测试
prompt = "Explain what is machine learning in one sentence:"
print(f"Prompt: {prompt}")
print(f"Generated: {generate_text(prompt)}")
```

## 8. 手工代码实现

```python
"""
自回归生成的手工实现
实现完整的贪婪解码 + 温度采样 + top-p采样的核心逻辑
"""

import torch
import torch.nn.functional as F
import numpy as np


class AutoregressiveGenerator:
    """手工实现自回归文本生成器"""

    def __init__(self, model, tokenizer):
        self.model = model
        self.tokenizer = tokenizer

    def _sample_next_token(self, logits, temperature, top_p, top_k):
        """
        从 logits 中采样下一个 token

        这是解码策略的核心——如何从概率分布转向离散选择。
        """
        # 温度缩放
        if temperature > 0:
            logits = logits / temperature
        else:
            # temperature=0 → 贪婪解码
            return torch.argmax(logits, dim=-1, keepdim=True)

        # 转为概率
        probs = F.softmax(logits, dim=-1)

        # Top-k 过滤
        if top_k > 0:
            top_k = min(top_k, probs.size(-1))
            topk_probs, _ = torch.topk(probs, top_k, dim=-1)
            min_topk = topk_probs[:, -1].unsqueeze(-1)
            probs = torch.where(probs < min_topk, 0.0, probs)

        # Top-p (nucleus) 过滤
        if top_p < 1.0:
            sorted_probs, sorted_indices = torch.sort(probs, descending=True, dim=-1)
            cumsum = torch.cumsum(sorted_probs, dim=-1)
            # 保留累积概率 <= top_p 的最小集合
            mask = cumsum - sorted_probs > top_p
            sorted_probs[mask] = 0.0
            # 重新归一化
            sorted_probs = sorted_probs / sorted_probs.sum(dim=-1, keepdim=True)
            # 从排序后的分布中采样
            next_token_idx = torch.multinomial(sorted_probs, 1)
            next_token = sorted_indices.gather(-1, next_token_idx)
            return next_token

        # 标准概率采样
        next_token = torch.multinomial(probs, 1)
        return next_token

    @torch.inference_mode()
    def generate(
        self,
        prompt: str,
        max_new_tokens: int = 100,
        temperature: float = 0.7,
        top_p: float = 0.95,
        top_k: int = 0,
        eos_token_id: int = None,
    ) -> str:
        """完整的自回归生成"""
        token_ids = self.tokenizer.encode(prompt)
        # 转为二维tensor (batch=1, seq_len)
        token_ids = torch.tensor([token_ids])

        for _ in range(max_new_tokens):
            # 前向传播：输入当前序列，获取各位置的logits
            logits = self.model(token_ids)
            # 只取最后一个位置的logits（预测下一个token用）
            last_logits = logits[:, -1, :]

            # 采样/选择下一个token
            next_token = self._sample_next_token(
                last_logits, temperature, top_p, top_k
            )

            # 检查EOS停止
            if eos_token_id is not None and next_token.item() == eos_token_id:
                break

            # 追加新token
            token_ids = torch.cat([token_ids, next_token], dim=1)

        # 解码输出
        return self.tokenizer.decode(token_ids[0].tolist())


# ===== 演示解码策略 =====
# 模拟logits演示不同温度
logits_example = torch.tensor([[3.0, 2.0, 1.0, 0.5, 0.1]])

print("温度对概率分布的影响:")
for T in [0.1, 0.5, 1.0, 2.0]:
    probs = F.softmax(logits_example / T, dim=-1)[0]
    print(f"  T={T:.1f}: {[f'{p:.3f}' for p in probs.tolist()]}")
print("T越低→分布越尖(接近贪婪); T越高→分布越平(更随机)")
```

## 9. 可视化与结果理解

import matplotlib.pyplot as plt
import numpy as np
import torch
import torch.nn.functional as F

logits = torch.tensor([[5.0, 3.0, 2.0, 1.5, 1.0, 0.5, 0.2, 0.1, 0.05, 0.02]])
temperatures = [0.1, 0.5, 1.0, 2.0]
vocab_tokens = ['A', 'B', 'C', 'D', 'E', 'F', 'G', 'H', 'I', 'J']

fig, axes = plt.subplots(2, 2, figsize=(12, 10))
colors = plt.cm.viridis(np.linspace(0.1, 0.9, 10))

for ax, T in zip(axes.flat, temperatures):
    probs = F.softmax(logits / T, dim=-1)[0].numpy()
    bars = ax.bar(vocab_tokens, probs, color=colors, edgecolor='black')
    ax.set_title(f"T = {T}", fontsize=14, fontweight='bold')
    ax.set_ylabel("概率")
    ax.set_ylim(0, 1.0)
    # 标注最高值
    max_idx = np.argmax(probs)
    ax.annotate(f"{probs[max_idx]:.1%}", xy=(max_idx, probs[max_idx]),
                xytext=(0, 8), textcoords='offset points', ha='center', fontsize=10)

fig.suptitle("温度采样: 温度T对token概率分布的影响\nT低=确定性高, T高=多样性高", fontsize=15, fontweight='bold')

plt.show()

## 10. 模型评估

自回归生成的质量通过困惑度(Perplexity)、生成文本的人类评测以及与特定任务相关的指标来评估。

```python
@torch.inference_mode()
def compute_perplexity(model, tokenizer, text):
    """困惑度评估——模型对文本的"意外程度"越低越好"""
    inputs = tokenizer(text, return_tensors="pt")
    input_ids = inputs["input_ids"]
    outputs = model(input_ids, labels=input_ids)
    loss = outputs.loss
    ppl = torch.exp(loss)
    return ppl.item()
```

## 11. 常见问题与易错点

| 问题 | 现象 | 原因 | 解决方案 |
|------|------|------|----------|
| 重复循环 | 生成 "hello hello hello..." | 贪婪解码陷入循环 | 用温度采样 + repetition_penalty |
| 生成过早停止 | 输出被截断 | max_new_tokens太小 | 增大max_new_tokens |
| EOS不触发生成 | 模型一直生成不停 | 模型没学到何时停止 | 显式传入eos_token_id |
| 输出格式不一致 | 每次输出格式不同 | 未固定解码策略 | 用固定temperature=0(贪婪)或小的随机性 |

## 12. 学习总结

自回归生成是LLM产生文本的核心机制：基于条件概率链式法则逐token生成。不同的解码策略（贪婪/温度/top-p/top-k）影响输出的质量和多样性。理解这个过程是所有LLM高级应用（推理、对话、代码生成）的基础。

## 13. 练习题与思考题

**题1**：为什么要用 temperature 采样而不是贪婪解码？贪婪总是选"最高概率"有什么问题？

**参考答案**：贪婪解码每次选概率最高的token，导致：(1)对同一输入总是生成完全相同的输出（零多样性）；(2)可能错过全局更优的序列——贪心算法有"局部最优≠全局最优"的问题；(3)倾向于重复和退化。温度采样引入受控的随机性，在确定性和多样性之间找到平衡。

**题2**：实现一个简单的beam search解码并比较与贪婪采样的区别。

**参考答案**：Beam search维护K个最优的部分序列，每步扩展所有K个序列的所有可能下一个token，保留新的K个最优。比贪婪更全局化（能考虑多条备选路径），但仍可能缺乏多样性（K个序列趋同）。

## 14. 学习路径建议

- **前置**：tokenizer/BPE基础
- **平行**：各种解码策略对比（贪婪/beam search/温度/top-p）
- **进阶**：推理时计算扩展（在自回归基础上多路径采样）
