# 分词器基础

## 什么是分词器？

**分词器（Tokenizer）**是LLM文本处理和生成管道中的关键组件。它不是LLM本身的直接部分，但对于准备输入数据和将输出转换回人类可读文本至关重要。

## 分词器的作用

分词器在LLM工作流中承担以下任务：

1. **编码（Encode）**：将人类可读的文本转换为token ID（数字）
2. **解码（Decode）**：将token ID转换回人类可读的文本

## Token是什么？

**Token**是语言模型处理的文本最小单元。一个token可以是：
- 完整的单词
- 单词的一部分
- 标点符号

具体切分方式取决于分词器的算法。

### 举例说明

句子："An LLM can be useful."

常见的分词器可能将其切分为：
```
"An", " L", "LM", " can", " be", " useful", "."
```

然后这些token会被转换为模型可以摄入的数字ID。

## 使用Qwen3分词器

### 下载分词器文件

首先，下载对应Qwen3基础LLM的分词器文件：

```python
from reasoning_from_scratch.qwen3 import download_qwen3_small

download_qwen3_small(kind="base", tokenizer_only=True, out_dir="qwen3")
```

这会显示类似的进度条：
```
tokenizer-base.json: 100% (6MiB/6MiB)
```

命令下载大约6MB的`tokenizer-base.json`文件并保存在`qwen3`子目录中。

### 加载分词器

从分词器文件加载分词器设置到`Qwen3Tokenizer`：

```python
from pathlib import Path
from reasoning_from_scratch.qwen3 import Qwen3Tokenizer

tokenizer_file_path = Path("qwen3") / "tokenizer-base.json"
tokenizer = Qwen3Tokenizer(tokenizer_file_path=tokenizer_file_path)
```

## 分词器实战

### 文本编码

将文本转换为token ID：

```python
prompt = "Explain large language models."
input_token_ids_list = tokenizer.encode(prompt)
```

### 文本解码

将token ID转换回文本：

```python
text = tokenizer.decode(input_token_ids_list)
print(text)
```

输出：
```
'Explain large language models.'
```

## 查看token ID对应关系

让我们看看`encode`方法生成的token ID及其对应的文本：

```python
for i in input_token_ids_list:
    print(f"[{i}] --> {tokenizer.decode([i])}")
```

输出：
```
[840] --> Ex
[20772] --> plain
[3460] --> large
[4128] --> language
[4119] --> models
[13] --> .
```

**观察：**
- 原始文本被切分为6个token ID
- 每个token代表一个单词或子词，取决于分词器如何切分输入
- 例如，"Explain"被拆分成两个单独的token："Ex"和"plain"

## 为什么"Explain"被拆分？

分词器算法使用基于**字节对编码（Byte Pair Encoding，BPE）**的子词方法。

BPE的优点：
- 可以使用完整单词和子词单元的混合来表示常见和罕见单词
- 空格也经常包含在token中（例如" large"），这有助于LLM检测单词边界

### Qwen3分词器词汇表大小

Qwen3分词器有大约151,000个token的词汇表，这在目前算是相对较大的。

**对比参考：**
- 早期GPT-2：约50,000个token
- Llama 3：约128,000个token

### 词汇表大小的影响

较大的词汇表：
- **优点**：允许更多单词被表示为单个token，而不是被拆分为子词组件
  - 减少输入token数量
  - 更短的输入序列
  - 减少处理时间和资源使用

- **缺点**：增加语言模型的大小和每个生成token的计算成本

**权衡：**
如果将一个单词拆分（如将"Explain"拆成"Ex"和"plain"），会导致更多输入token。更多token导致更长的输入序列，这会增加处理时间和资源使用。例如，token数量加倍会大致使运行模型的计算成本加倍。

## 练习：处理未知单词

**任务：**
实验使用分词器，看看它如何处理未知单词。

**提示：**
1. 创造一些不存在的单词
2. 如果你会说多种语言，尝试用非英语语言编码单词

**示例代码：**
```python
prompt = "Hello, Ardwarklethyrx. Haus und Garten."
# Ardwarklethyrx是一个编造的词
# Haus und Garten是德语（房子和花园）

input_token_ids_list = tokenizer.encode(prompt)
for i in input_token_ids_list:
    print(f"[{i}] --> {tokenizer.decode([i])}")
```

**预期结果：**
未知词会被拆分为更小的子词甚至单个字符，这使得分词器和LLM能够处理任何输入。

**观察：**
- 德语单词没有被分解为字符或子词，这表明分词器在训练期间见过德语文本
- 这也表明LLM可能也在德语文本上训练过，应该能够很好地处理某些非英语语言
