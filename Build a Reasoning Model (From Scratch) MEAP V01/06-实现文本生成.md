# 实现文本生成函数

## 概述

前几节我们了解了LLM基本顺序文本生成过程中的单次迭代。现在，基于这个概念，我们将实现一个文本生成函数，使用预训练的LLM根据用户提示生成连贯文本。

## generate_text_basic函数

`generate_text_basic`函数实现了使用`argmax`函数的顺序文本生成过程。

### 函数实现

```python
@torch.inference_mode()
def generate_text_basic(
    model,
    token_ids,
    max_new_tokens,
    eos_token_id=None
):
    input_length = token_ids.shape[1]
    model.eval()  # 切换到评估模式以启用确定性行为（最佳实践）

    for _ in range(max_new_tokens):
        out = model(token_ids)[:, -1]  # 获取最后一个token的分数

        next_token = torch.argmax(out, dim=-1, keepdim=True)

        # 如果批次中的所有序列都生成了EOS token则停止
        if (eos_token_id is not None
            and torch.all(next_token == eos_token_id)):
            break

        # 将新预测的token追加到序列中
        token_ids = torch.cat([token_ids, next_token], dim=1)

    # 只返回生成的token（排除原始输入）
    return token_ids[:, input_length:]
```

**装饰器说明：**
- `@torch.inference_mode()`：禁用梯度跟踪以提高速度和内存效率

## 使用示例

让我们使用这个函数生成一个100-token的响应：

```python
prompt = "Explain large language models in a single sentence."

# 将输入token ID转移到与模型所在的相同设备（CPU、GPU）
input_token_ids_tensor = torch.tensor(
    tokenizer.encode(prompt),
    device=device
).unsqueeze(0)

max_new_tokens = 100  # 让模型生成最多100个新token

output_token_ids_tensor = generate_text_basic(
    model=model,
    token_ids=input_token_ids_tensor,
    max_new_tokens=max_new_tokens,
)

# 将输出token ID从PyTorch张量转换为Python列表
output_text = tokenizer.decode(
    output_token_ids_tensor.squeeze(0).tolist()
)
print(output_text)
```

**注意：**
以下代码会较慢，可能需要1-3分钟完成，具体取决于你的计算机（我们将在后续部分加速）。

It is composed of a vast array of symbols, including letters, numbers, and words, which are used to convey meaning and express thoughts and ideas. The evolution of language has

**观察：**
- 模型很好地遵循了指令，生成了一个清晰的单句作为对提示的响应
- 但它继续在特殊token`<|endoftext|>`之后生成额外的、无关的文本
  - 这个token在训练期间用于标记文档结束并分隔不同样本

## 前导空格问题

你可能注意到" Large"（第一个输出词）中的前导空格。这是因为模型基于输入提示继续文本，但我们在返回行中用`token_ids[:, input_length:]`切掉了原始提示。

**解决方案：**
如果这个前导空格困扰你，可以通过以下方式移除：
- `token_ids[:, input_length:].lstrip()`
- 或 `output_text.lstrip()`

## 使用EOS Token停止生成

在推理中使用模型（即基于输入生成输出）时，我们通常希望它一旦产生特殊token`<|endoftext|>`就停止。

这个token由ID 151643表示，我们可以确认：

```python
print(tokenizer.encode("<|endoftext|>"))
```

为方便起见，这个token ID也通过`tokenizer.eos_token_id`属性保存。我们可以将此ID传递给`generate_text_basic`函数以指示何时应该停止生成：

```python
output_token_ids_tensor = generate_text_basic(
    model=model,
    token_ids=input_token_ids_tensor,
    max_new_tokens=max_new_tokens,
    eos_token_id=tokenizer.eos_token_id  # 传递结束序列token ID
)

output_text = tokenizer.decode(
    output_token_ids_tensor.squeeze(0).tolist()
)
print(output_text)
```

### 生成结果（带EOS停止）

```
Large language models are artificial intelligence systems that can understand, generate, and process human language, enabling them to perform a wide range of tasks, from answering questions to writing articles, and even creating creative content.
```

如果我们比较与之前响应的输出，可以看到文本生成在遇到结束序列token时停止了。

## 性能测量

生成响应相对较慢，可能需要几秒到几分钟，具体取决于硬件。

### 实用统计函数

让我们实现一个简单的实用函数来测量文本生成过程的运行时间：

```python
def generate_stats(output_token_ids, tokenizer, start_time, end_time):
    total_time = end_time - start_time
    print(f"时间: {total_time:.2f}秒")
    print(f"速度: {int(output_token_ids.numel() / total_time)} tokens/秒")

    if torch.cuda.is_available():
        max_mem_bytes = torch.cuda.max_memory_allocated()
        max_mem_gb = max_mem_bytes / (1024 ** 3)
        print(f"最大内存分配: {max_mem_gb:.2f} GB")

    output_text = tokenizer.decode(output_token_ids.squeeze(0).tolist())
    print(f"\n{output_text}")
```

**说明：**
- 计算：总运行时间、生成速度（tokens/秒）、GPU内存使用
- GPU内存使用目前只计算支持CUDA的GPU，PyTorch缺少CPU和Apple Silicon GPU的类似实用函数

### 测量性能


## 术语说明

当阅读LLM文献或软件文档时，你会不可避免地遇到术语**推理（inference）**，经常被用来代替文本生成。

**在此语境下：**
- 推理来自神经网络术语
- 指使用训练好的模型进行预测，如从提示生成下一个token
- 这不同于统计学中的推理（通常指从数据中得出关于总体的结论）

因此，当我们调用`generate_text_basic`函数时，我们可能在进行神经网络意义上的推理。
