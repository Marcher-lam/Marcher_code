推荐系统是一个**逐层过滤的漏斗**：

```

         │
         ▼ 召回（多路）
    ┌─────────────┐
    │  候选集      │  ← 几千~几万
    │  (千级)      │
    └─────────────┘
         │

    ┌─────────────┐
    │  粗排结果    │  ← 几百~几千
    │  (百级)      │
    └─────────────┘
         │
         ▼ 精排
    ┌─────────────┐
    │  精排结果    │  ← 几十~几百
    │  (百级)      │
    └─────────────┘
         │
         ▼ 重排
    ┌─────────────┐
    │  最终结果    │  ← 展示数量
    │  (几十)      │
    └─────────────┘
```

## 3. 召回层（Recall）

### 3.1 召回的作用

**召回（Recall）是从海量物品中快速筛选出用户可能感兴趣的候选集。**

```
召回的核心目标：
1. 规模：从百万/亿级物品筛选到千级
2. 速度：毫秒级完成
3. 覆盖：尽可能召回相关物品
```

### 3.2 为什么需要召回

直接对百万物品排序？
- 排序模型复杂，计算量大
- 在线服务延迟要求高（<100ms）
- 不现实！

解决方案：
- 先用简单快速的模型召回候选集
- 再用复杂模型对候选集精排

### 3.3 多路召回

实际系统通常采用**多路召回**策略：

```
┌─────────────────────────────────────────────────────────────┐
│                        多路召回                              │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   用户请求                                                  │
│      │                                                      │
│      ├────→ [协同过滤召回] ────┐                            │
│      │                       │                              │
│      ├────→ [向量召回] ────────┤                            │
│      │                       │                              │
│      ├────→ [内容召回] ────────┼──→ 合并去重 ──→ 候选集     │
│      │                       │     (千级)                  │
│      ├────→ [热门召回] ────────┤                            │
│      │                       │                              │
│      ├────→ [规则召回] ────────┤                            │
│      │                       │                              │
│      └────→ [图召回] ──────────┘                            │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 3.4 常见召回方法

| 召回方法 | 原理 | 适用场景 | 速度 |
|---------|------|---------|-----|
| **协同过滤** | 找相似用户/物品 | 有行为数据 | 快 |
| **向量召回** | Embedding相似度 | 通用 | 快(ANN) |
| **内容召回** | 属性/标签匹配 | 新物品冷启动 | 快 |
| **热门召回** | 全局/分类热门 | 新用户冷启动 | 极快 |
| **规则召回** | 业务规则 | 特定场景 | 极快 |
| **图召回** | 图结构关系 | 关系复杂场景 | 中等 |

### 3.5 召回评估指标

```python
# 召回率：正样本被召回的比例
Recall = 召回的正样本数 / 总正样本数

# 命中率：用户喜欢的物品被召回的比例
Hit Rate = 命中用户数 / 总用户数

# 覆盖率：被召回物品占总物品的比例
Coverage = 召回物品数 / 总物品数
```

## 4. 排序层（Ranking）

### 4.1 排序的作用

**排序（Ranking）是对召回的候选集进行精细打分，确定最终展示顺序。**

```
排序的核心目标：
1. 精准：预测用户对每个物品的感兴趣程度
2. 区分：给不同物品明显不同的分数
3. 效果：提升CTR、CVR等业务指标
```

### 4.2 粗排 vs 精排

| 维度 | 粗排 | 精排 |
|-----|------|-----|
| **输入规模** | 千级 | 百级 |
| **模型复杂度** | 简单 | 复杂 |
| **特征数量** | 少(几十) | 多(几百上千) |
| **延迟要求** | <10ms | <50ms |
| **目标** | 快速筛选 | 精准排序 |

### 4.4 排序模型分类

| 类型 | 代表模型 | 特点 |
|-----|---------|-----|
| **线性模型** | LR | 简单、可解释性强 |
| **树模型** | GBDT+LR | 自动特征组合 |
| **因子分解** | FM、FFM | 二阶特征交叉 |
| **深度模型** | DeepFM、W&D | 高阶特征交叉 |
| **序列模型** | DIN、DIEN | 用户兴趣建模 |
| **多任务模型** | MMOE、PLE | 多目标联合优化 |

### 4.5 排序评估指标

```python
# 离线指标
AUC = ROC曲线下面积  # 排序能力
LogLoss = 交叉熵损失  # 预测准确性
NDCG = 归一化折损累积增益  # 排序质量

# 在线指标
CTR = 点击数 / 曝光数
CVR = 转化数 / 点击数
```

## 5. 重排层（Re-ranking）

### 5.1 重排的作用

**重排（Re-ranking）是在精排结果基础上，进行业务规则调整和多样性优化。**

```
重排的核心目标：
1. 多样性：避免推荐结果过于单一
2. 新颖性：增加惊喜感
3. 公平性：给更多物品曝光机会
4. 业务规则：满足特定业务需求
```

### 5.3 多样性策略详解

**1. 打散策略**

```python
# 类目打散：同类目物品不能连续出现
def category_diversity(items, max_same=2):
    """同类型最多连续出现max_same个"""
    result = []
    last_category = None
    same_count = 0

    for item in items:
        if item.category == last_category:
            same_count += 1
            if same_count >= max_same:
                continue  # 跳过
        else:
            same_count = 0

        result.append(item)
        last_category = item.category

    return result
```

**2. MMR（最大边际相关性）**

```python
# MMR：平衡相关性和多样性
def mmr(items, lambda_param=0.5):
    """
    MMR = λ * relevance - (1-λ) * max_similarity_to_selected
    """
    selected = []
    remaining = items.copy()

    while remaining and len(selected) < k:
        best_score = -inf
        best_item = None

        for item in remaining:
            # 相关性分数
            relevance = item.score
            # 与已选物品的最大相似度
            max_sim = max([similarity(item, s) for s in selected], default=0)
            # MMR分数
            mmr_score = lambda_param * relevance - (1 - lambda_param) * max_sim

            if mmr_score > best_score:
                best_score = mmr_score
                best_item = item

        selected.append(best_item)
        remaining.remove(best_item)

    return selected
```

## 9. 离线 vs 在线

### 9.1 对比

| 维度 | 离线系统 | 在线系统 |
|-----|---------|---------|
| **时机** | 定期批量处理 | 实时响应 |
| **数据** | 历史全量数据 | 当前请求数据 |
| **延迟** | 分钟~小时级 | 毫秒级 |
| **目标** | 模型训练、效果分析 | 实时推荐服务 |

### 10.1 核心流程回顾


1. **漏斗结构**：从海量到少量，逐层筛选

3. **精排重排**：精准打分 + 业务调整
4. **反馈闭环**：持续优化迭代
