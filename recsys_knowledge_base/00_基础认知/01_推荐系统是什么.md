# 推荐系统是什么

> 本文是推荐系统知识库的第一篇，带你建立对推荐系统最基础的认识。

---

## 1. 推荐系统的定义

### 1.1 一句话定义

**推荐系统（Recommender System）是一种信息过滤系统，它根据用户的历史行为、兴趣偏好等信息，主动向用户推送可能感兴趣的内容。**

### 1.2 更直白的解释

想象你走进一家超大型超市：
- 没有推荐：你需要自己在几万件商品中寻找想要的
- 有推荐：导购员根据你的喜好，主动告诉你"您可能喜欢这个"

推荐系统就是那个"智能导购员"。

### 1.3 核心本质

```
推荐系统 = 在信息过载时代，帮助用户发现感兴趣内容的系统
```

它解决的核心矛盾是：
- **信息供给**：海量内容（百万/千万/亿级）
- **用户注意力**：有限（每天几十分钟到几小时）

---

## 2. 为什么需要推荐系统

### 2.1 三个核心原因

| 原因 | 说明 |
|-----|------|
| **信息过载** | 内容太多，用户找不到想要的 |
| **用户需求模糊** | 用户不知道自己想要什么 |
| **长尾效应** | 大量优质内容被埋没，需要被挖掘 |

### 2.2 具体场景举例

**抖音/短视频：**
- 每天上传视频数百万
- 用户只能看几十到几百个
- 需要从海量视频中找到用户喜欢的

**电商（淘宝/京东）：**
- 商品数亿件
- 用户搜索"手机"，结果几千个
- 需要帮用户找到最可能购买的

**音乐（网易云音乐/Spotify）：**
- 歌曲数千万
- 用户不知道听什么
- 需要根据口味推荐

### 2.3 推荐系统 vs 搜索引擎

| 对比维度 | 搜索引擎 | 推荐系统 |
|---------|---------|---------|
| 触发方式 | 用户主动输入查询 | 系统主动推送 |
| 用户意图 | 明确 | 不明确或模糊 |
| 典型场景 | "我想买iPhone 15" | "给你推荐几首歌" |
| 核心目标 | 匹配查询 | 发现兴趣 |

## 3. 推荐系统的核心目标

### 3.1 业务目标

推荐系统最终要服务于业务，常见目标包括：

| 目标 | 说明 | 典型场景 |
|-----|------|---------|
| **点击率（CTR）** | 用户点击推荐内容的比例 | 新闻、短视频 |
| **转化率（CVR）** | 用户完成目标行为的比例 | 电商购买 |
| **停留时长** | 用户在平台停留的时间 | 短视频、长视频 |
| **留存率** | 用户再次回访的比例 | 所有产品 |
| **GMV** | 商品交易总额 | 电商 |
| **用户满意度** | 长期用户体验 | 所有产品 |

### 3.2 技术目标

从技术角度，推荐系统追求：

1. **准确性（Accuracy）**
   - 推荐的内容用户确实喜欢
   - 衡量指标：AUC、NDCG、Recall@K

2. **覆盖率（Coverage）**
   - 能推荐的内容占全部内容的比例
   - 避免"马太效应"（头部内容垄断）

3. **多样性（Diversity）**
   - 推荐结果不要太单一
   - 比如不要连续推荐10个手机视频

4. **新颖性（Novelty）**
   - 推荐用户不知道但可能喜欢的
   - 而不是只推荐用户已经知道的

5. **惊喜性（Serendipity）**
   - 推荐超出用户预期的内容
   - 比如推荐一个全新类型但用户很喜欢的

6. **实时性（Real-time）**
   - 快速响应用户行为变化
   - 用户刚点了体育，立刻推荐更多体育

### 3.3 目标的权衡

这些目标往往存在冲突：

```
准确性 ←→ 多样性
（推荐最准确的 vs 推荐多样化的）

新颖性 ←→ 准确性
（推荐新东西 vs 推荐确定喜欢的）

覆盖率 ←→ 准确性
（推荐更多物品 vs 只推荐热门物品）
```

实际工作中需要根据业务场景进行权衡。

## 4. 推荐系统的输入与输出

### 4.1 输入（数据源）

推荐系统需要以下数据作为输入：

```
┌─────────────────────────────────────────────────────────┐
│                    推荐系统输入                          │
├─────────────────────────────────────────────────────────┤
│  用户数据                                                │
│  ├── 用户属性：年龄、性别、地域、设备                    │
│  ├── 行为数据：点击、收藏、购买、评分                    │
│  └── 社交数据：关注、好友、互动                          │
├─────────────────────────────────────────────────────────┤
│  物品数据                                                │
│  ├── 基础属性：类目、品牌、价格、标题                    │
│  ├── 内容数据：图片、视频、文本描述                      │
│  └── 统计数据：热度、销量、评分                          │
├─────────────────────────────────────────────────────────┤
│  上下文数据                                              │
│  ├── 时间：早/中/晚、工作日/周末、节假日                  │
│  ├── 地点：国家、城市、具体位置                          │
│  └── 场景：首页、详情页、搜索结果页                      │
└─────────────────────────────────────────────────────────┘
```

### 4.2 输出（推荐结果）

推荐系统的输出通常是一个**有序列表**：

```python
# 推荐结果示例
recommendations = [
    {"item_id": "A001", "score": 0.95, "reason": "猜你喜欢"},
    {"item_id": "A002", "score": 0.92, "reason": "相似推荐"},
    {"item_id": "A003", "score": 0.88, "reason": "热门推荐"},
    # ... 更多推荐项
]
```

输出包含：
- **物品ID列表**：推荐什么
- **排序分数**：推荐强度
- **推荐理由**：为什么推荐（可选）

## 5. 推荐系统的核心流程

### 5.1 简化流程

```
用户行为数据 ──→ 分析用户偏好 ──→ 匹配候选物品 ──→ 排序 ──→ 展示给用户
```

### 5.2 完整流程（工业级）

```
┌────────────────────────────────────────────────────────────────────┐
│                         推荐系统完整流程                            │
├────────────────────────────────────────────────────────────────────┤
│                                                                    │
│  ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐     │
│  │ 数据采集 │───→│ 特征工程 │───→│ 召回阶段 │───→│ 排序阶段 │     │
│  └──────────┘    └──────────┘    └──────────┘    └──────────┘     │
│       │                                               │            │
│       │               ┌──────────┐                    │            │
│       │               │ 重排阶段 │←───────────────────┘            │
│       │               └──────────┘                                 │
│       │                    │                                       │
│       │                    ▼                                       │
│       │               ┌──────────┐                                 │
│       └──────────────→│ 曝光展示 │                                 │
│                       └──────────┘                                 │
│                            │                                       │
│                            ▼                                       │
│                       ┌──────────┐                                 │
│                       │ 用户反馈 │ ──→ 反馈到数据采集（闭环）       │
│                       └──────────┘                                 │
│                                                                    │
└────────────────────────────────────────────────────────────────────┘
```

### 5.3 各阶段说明

| 阶段 | 作用 | 输入 | 输出 |
|-----|------|-----|------|
| **数据采集** | 收集用户行为数据 | 用户交互日志 | 行为数据表 |
| **特征工程** | 构建模型可用特征 | 原始数据 | 特征向量 |
| **召回** | 从海量物品中筛选候选集 | 用户特征、物品库 | 候选集（千级） |
| **排序** | 对候选集精细打分排序 | 候选集、精细特征 | 排序列表（百级） |
| **重排** | 业务规则、多样性调整 | 排序列表 | 最终推荐结果 |
| **曝光展示** | 将结果展示给用户 | 推荐结果 | 前端展示 |

## 7. 推荐系统的核心问题

### 7.1 经典问题

| 问题 | 描述 | 常见解决思路 |
|-----|------|-------------|
| **冷启动** | 新用户/新物品没有历史数据 | 基于内容、热门推荐、探索策略 |
| **稀疏性** | 用户-物品交互矩阵非常稀疏 | 矩阵分解、深度学习 |
| **可扩展性** | 物品/用户规模大 | 分层架构、ANN检索 |
| **实时性** | 用户兴趣变化需要快速响应 | 流式计算、在线学习 |

### 7.2 评估问题

| 问题 | 描述 |
|-----|------|
| 离线 vs 在线 | 离线指标好不代表在线效果好 |
| 延迟反馈 | 用户可能过一段时间才转化 |
| 选择偏差 | 只能观测到用户看到并点击的 |
| 位置偏差 | 用户更倾向于点击靠前的位置 |

## 10. 本章总结

### 10.1 核心要点

1. **推荐系统本质**：信息过滤系统，解决信息过载问题
2. **核心目标**：准确性、覆盖率、多样性、新颖性等的权衡
3. **基本流程**：数据采集 → 召回 → 排序 → 重排 → 展示
4. **关键挑战**：冷启动、稀疏性、可扩展性、实时性
