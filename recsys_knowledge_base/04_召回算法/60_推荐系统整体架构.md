### 1.2 三层架构

| 层级 | 响应时间 | 数据时效性 | 典型任务 |
|-----|---------|-----------|---------|
| **在线系统** | < 100ms | 实时 | 响应用户请求，推荐服务 |
| **近线系统** | 秒级 | 准实时 | 实时特征更新，流式处理 |
| **离线系统** | 小时/天级 | 历史数据 | 模型训练，批量计算 |

## 3. 近线系统

### 3.1 实时数据流

```
用户行为
    │
    ▼
┌─────────────┐
│   埋点上报   │
└─────────────┘
    │
    ▼
┌─────────────┐
│  消息队列   │  Kafka
│  (Kafka)    │
└─────────────┘
    │
    ├──→ 实时特征计算
    │         │
    │         ▼
    │    ┌─────────┐
    │    │ Redis   │  更新实时特征
    │    └─────────┘
    │
    └──→ 实时样本生成
              │
              ▼
         ┌─────────┐
         │在线学习 │  增量更新模型
         └─────────┘
```

### 3.2 实时特征更新

```python
# 实时特征更新示例

# 用户实时行为特征
user_realtime_features = {
    "user_id": "u123",
    "last_10_clicks": ["item1", "item2", ...],  # 最近点击的10个物品
    "last_category": "tech",                    # 最近点击的类目
    "session_clicks": 15,                       # 当前会话点击数
    "last_active_time": 1703232000,             # 最后活跃时间
}

# 物品实时统计特征
item_realtime_features = {
    "item_id": "item456",
    "click_count_1h": 1234,     # 近1小时点击数
    "click_count_24h": 5678,    # 近24小时点击数
    "ctr_1h": 0.05,             # 近1小时CTR
}
```

### 3.3 流式计算

```
Flink流式处理任务：

1. 实时CTR计算
   - 窗口内点击数 / 窗口内曝光数
   - 滑动窗口（1分钟、5分钟、1小时）

2. 实时热度计算
   - 基于时间衰减的点击/播放计数
   - 更新热门榜单

3. 实时用户画像
   - 更新用户的短期兴趣标签
   - 追踪用户会话行为
```

### 4.2 延迟分解

```
推荐系统延迟要求：< 100ms（通常目标）

各阶段延迟分解：
┌────────────────────────────────────────────────────────┐
│  阶段          │  延迟目标    │  说明                  │
├────────────────────────────────────────────────────────┤
│  特征获取      │  5-15ms     │  Redis/HBase查询      │
│  召回（多路）  │  20-30ms    │  并行执行             │
│  粗排          │  5-10ms     │  简单模型             │
│  精排          │  30-50ms    │  复杂模型+特征获取    │
│  重排          │  5-10ms     │  规则处理             │
│  其他          │  5-10ms     │  网络、序列化等       │
└────────────────────────────────────────────────────────┘

总计：约 70-125ms
```

### 4.3 核心服务

```
推荐系统核心服务：

1. 特征服务
   - 存储和查询用户/物品特征
   - 支持高并发、低延迟
   - 技术：Redis、HBase

2. 召回服务
   - 执行多路召回策略
   - 向量检索（Faiss）
   - 协同过滤计算

3. 排序服务
   - 模型推理
   - 技术：TF Serving、ONNX Runtime
   - 支持GPU/CPU推理

4. 重排服务
   - 多样性控制
   - 业务规则处理
   - 曝光过滤
```

```
│  问题3：模型效果衰减                                       │
│  ├── 原因：数据漂移、用户兴趣变化                         │
│  └── 处理：重新训练、增加新特征、在线学习                 │
│                                                            │
│  问题4：服务不可用                                         │
│  ├── 原因：依赖服务故障、资源耗尽                         │
│  └── 处理：熔断降级、重启、切换机房                       │
│                                                            │
└────────────────────────────────────────────────────────────┘
```

## 9. 本章总结

### 9.1 核心要点

1. **三层架构**：离线（训练）+ 近线（实时特征）+ 在线（服务）
2. **核心链路**：召回 → 粗排 → 精排 → 重排
3. **数据闭环**：用户行为 → 数据采集 → 模型优化 → 推荐服务

### 9.2 关键技术

```
离线：
- 数据仓库：Hive、Spark
- 模型训练：TensorFlow、PyTorch

近线：
- 消息队列：Kafka
- 流处理：Flink
- 实时存储：Redis

在线：
- 特征服务：Redis、HBase
- 向量检索：Faiss、Milvus
- 模型服务：TF Serving
```
